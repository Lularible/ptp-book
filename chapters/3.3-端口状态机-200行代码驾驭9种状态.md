# 3.3 端口状态机：200行代码驾驭9种状态

## 状态机的艺术

PTP端口有9种状态，状态转换规则复杂。

但LinuxPTP只用**337行**的fsm.c就实现了完整的状态机（`ptp_fsm()`200行）。

这是如何做到的？

---

## 状态机概述

### IEEE 1588定义的状态

第二章我们详细讲解了PTP端口的9种状态：

```text
1. INITIALIZING   - 初始化
2. FAULTY         - 故障
3. DISABLED       - 禁用
4. LISTENING      - 监听
5. PRE_MASTER     - 预备主
6. MASTER         - 主时钟
7. PASSIVE        - 被动
8. UNCALIBRATED   - 未校准
9. SLAVE          - 从时钟
```

### LinuxPTP的状态定义

```c
/* fsm.h, 第24-35行 */

enum port_state {
    PS_INITIALIZING = 1,
    PS_FAULTY,
    PS_DISABLED,
    PS_LISTENING,
    PS_PRE_MASTER,
    PS_MASTER,
    PS_PASSIVE,
    PS_UNCALIBRATED,
    PS_SLAVE,
    PS_GRAND_MASTER,  /* 非标准扩展 */
};
```

**PS_GRAND_MASTER的由来**：

```text
IEEE 1588只定义了PS_MASTER状态。

但LinuxPTP添加了PS_GRAND_MASTER状态（fsm.h:34，源码行尾注释直接写着
non-standard extension）。10 个 PS_* 里，只有它是 linuxptp 私货。

区别：
- PS_MASTER：端口在某条路径上当主时钟（BMCA 的 M3 判定，bmc.c:173）
- PS_GRAND_MASTER：本时钟就是整个时钟域的根（BMCA 的 M1/M2 判定，
  bmc.c:156、bmc.c:163）

它是个纯粹的“内部状态”，不对外暴露。凡是状态要写进报文的地方，
linuxptp 都把它折回 PS_MASTER：
- 管理属性 PORT_DATA_SET 的响应：
    if (target->state == PS_GRAND_MASTER) {       /* port.c:1019-1023 */
        pds->portState = PS_MASTER;
    } else {
        pds->portState = target->state;
    }
- NetSync Monitor 响应：
    head->port_state =                            /* port.c:543 */
        p->state == PS_GRAND_MASTER ? PS_MASTER : p->state;
```

### 状态机事件

```c
/* fsm.h, 第38-56行 */

enum fsm_event {
    EV_NONE,                              /* 无事件 */
    EV_POWERUP,                           /* 上电 */
    EV_INITIALIZE,                        /* 初始化 */
    EV_DESIGNATED_ENABLED,                /* 被启用 */
    EV_DESIGNATED_DISABLED,               /* 被禁用 */
    EV_FAULT_CLEARED,                     /* 故障清除 */
    EV_FAULT_DETECTED,                    /* 故障检测 */
    EV_STATE_DECISION_EVENT,              /* 状态决策事件 */
    EV_QUALIFICATION_TIMEOUT_EXPIRES,     /* 资格超时 */
    EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES,  /* Announce超时 */
    EV_SYNCHRONIZATION_FAULT,             /* 同步故障 */
    EV_MASTER_CLOCK_SELECTED,             /* 主时钟选中 */
    EV_INIT_COMPLETE,                     /* 初始化完成 */
    EV_RS_MASTER,                         /* 推荐状态：主时钟 */
    EV_RS_GRAND_MASTER,                   /* 推荐状态：网络主时钟 */
    EV_RS_SLAVE,                          /* 推荐状态：从时钟 */
    EV_RS_PASSIVE,                        /* 推荐状态：被动 */
};
```

**事件分类**：

```text
第一类：基础事件
- EV_POWERUP：设备上电
- EV_INITIALIZE：重新初始化
- EV_INIT_COMPLETE：初始化完成

第二类：控制事件
- EV_DESIGNATED_ENABLED：管理员启用端口
- EV_DESIGNATED_DISABLED：管理员禁用端口

第三类：故障事件
- EV_FAULT_DETECTED：检测到故障
- EV_FAULT_CLEARED：故障已清除
- EV_SYNCHRONIZATION_FAULT：同步故障

第四类：定时器事件
- EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES：Announce超时
- EV_QUALIFICATION_TIMEOUT_EXPIRES：资格超时

第五类：BMCA事件
- EV_STATE_DECISION_EVENT：状态决策
- EV_MASTER_CLOCK_SELECTED：主时钟选中
- EV_RS_*：BMCA推荐状态
```

### 图中事件名 → linuxptp 事件对照

2.5 章画状态图时用的是标准端口状态转移图的原文事件名（不带前缀），本章及之后讲的是实现，一律用带 `EV_` 前缀的 `fsm.h` 名字。两套写法按下表一一对应：

| `EV_POWERUP` | :40 | `POWERUP` |
| `EV_INITIALIZE` | :41 | `INITIALIZE` |
| `EV_DESIGNATED_ENABLED` | :42 | `DESIGNATED_ENABLED` |
| `EV_DESIGNATED_DISABLED` | :43 | `DESIGNATED_DISABLED` |
| `EV_FAULT_CLEARED` | :44 | `FAULT_CLEARED` |
| `EV_FAULT_DETECTED` | :45 | `FAULT_DETECTED` |
| `EV_STATE_DECISION_EVENT` | :46 | `STATE_DECISION_EVENT` |
| `EV_QUALIFICATION_TIMEOUT_EXPIRES` | :47 | `QUALIFICATION_TIMEOUT_EXPIRES` |
| `EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES` | :48 | `ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES` |
| `EV_SYNCHRONIZATION_FAULT` | :49 | `SYNCHRONIZATION_FAULT` |
| `EV_MASTER_CLOCK_SELECTED` | :50 | `MASTER_CLOCK_SELECTED` |
| `EV_INIT_COMPLETE` | :51 | `INITIALIZATION_COMPLETE` ← **全套里唯一改了名的** |

## 主状态机实现

### ptp_fsm函数

```c
/* fsm.c:21-220 —— 以下为节选，只保留骨架；10 个 case 分支
   在下面的“状态转换详解”里逐个逐字给出，完整 44 条规则见“完整状态转换表” */

enum port_state ptp_fsm(enum port_state state, enum fsm_event event, int mdiff)
{
	enum port_state next = state;              /* fsm.c:23 */

	if (EV_INITIALIZE == event || EV_POWERUP == event)   /* fsm.c:25-26 */
		return PS_INITIALIZING;

	switch (state) {                         /* fsm.c:28 */
	case PS_INITIALIZING:                    /* fsm.c:29-40，详见下文 */
		break;
	case PS_FAULTY:                          /* fsm.c:42-53 */
		break;
	case PS_DISABLED:                        /* fsm.c:55-58 */
		break;
	case PS_LISTENING:                       /* fsm.c:60-86，详见下文 */
		break;
	case PS_PRE_MASTER:                      /* fsm.c:88-108，详见下文 */
		break;
	case PS_MASTER:                          /* fsm.c:110 */
	case PS_GRAND_MASTER:                    /* fsm.c:111（与 MASTER 落穿共用一块） */
		break;
	case PS_PASSIVE:                         /* fsm.c:130-153 */
		break;
	case PS_UNCALIBRATED:                    /* fsm.c:155-184 */
		break;
	case PS_SLAVE:                           /* fsm.c:186-216，详见下文 */
		break;
	}

	return next;                                 /* fsm.c:219 */
}
```

**设计亮点**：

```text
亮点一：函数式设计

状态机是一个纯函数：
- 输入：当前状态 + 事件 + mdiff
- 输出：下一状态
- 无副作用

好处：
- 可测试性强
- 易于理解
- 便于调试

亮点二：默认保持当前状态

enum port_state next = state;

如果事件不被处理，状态保持不变。
这避免了复杂的错误处理。

亮点三：快速路径处理

if (EV_INITIALIZE == event || EV_POWERUP == event)
    return PS_INITIALIZING;

无论当前什么状态，初始化事件都回到INITIALIZING。
避免在每个case中重复处理。
```

### 状态转换详解

#### INITIALIZING状态

```c
/* fsm.c, 第29-40行 */

case PS_INITIALIZING:
    switch (event) {
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_INIT_COMPLETE:
        next = PS_LISTENING;
        break;
    default:
        break;
    }
    break;
```

**状态转换图**：

```text
INITIALIZING
    │
    ├─ EV_FAULT_DETECTED ──→ PS_FAULTY
    │
    └─ EV_INIT_COMPLETE ───→ PS_LISTENING

说明：
- 初始化过程中检测到故障 → 进入故障状态
- 初始化完成 → 进入监听状态，开始接收Announce
```

#### LISTENING状态

```c
/* fsm.c, 第60-86行 */

case PS_LISTENING:
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES:
        next = PS_MASTER;
        break;
    case EV_RS_MASTER:
        next = PS_PRE_MASTER;
        break;
    case EV_RS_GRAND_MASTER:
        next = PS_GRAND_MASTER;
        break;
    case EV_RS_SLAVE:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**状态转换图**：

```text
LISTENING
    │
    ├─ EV_DESIGNATED_DISABLED ───────────────→ PS_DISABLED
    │
    ├─ EV_FAULT_DETECTED ────────────────────→ PS_FAULTY
    │
    ├─ EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES ──→ PS_MASTER
    │   （长时间没收到Announce，自己当主时钟）
    │
    ├─ EV_RS_MASTER ─────────────────────────→ PS_PRE_MASTER
    │   （BMCA建议当主时钟）
    │
    ├─ EV_RS_GRAND_MASTER ───────────────────→ PS_GRAND_MASTER
    │   （BMCA建议当网络主时钟）
    │
    ├─ EV_RS_SLAVE ──────────────────────────→ PS_UNCALIBRATED
    │   （BMCA建议当从时钟）
    │
    └─ EV_RS_PASSIVE ────────────────────────→ PS_PASSIVE
        （BMCA建议保持被动）
```

#### PRE_MASTER状态

```c
/* fsm.c, 第88-108行 */

case PS_PRE_MASTER:
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_QUALIFICATION_TIMEOUT_EXPIRES:
        next = PS_MASTER;
        break;
    case EV_RS_SLAVE:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**PRE_MASTER的作用**：

```text
为什么需要PRE_MASTER状态？

防止网络震荡：
- 端口决定当主时钟
- 先进入PRE_MASTER等待一段时间
- 确认没有更好的主时钟
- 超时后才进入MASTER状态

等待时间：
- 由qualificationTimeout决定
- 通常是announceInterval的几倍
- 确保Announce信息充分传播
```

#### MASTER和GRAND_MASTER状态

```c
/* fsm.c, 第110-128行 */

case PS_MASTER:
case PS_GRAND_MASTER:  /* 两个状态处理相同 */
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_RS_SLAVE:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**代码合并技巧**：

```text
case PS_MASTER:
case PS_GRAND_MASTER:
    /* 两个状态共享同一套处理逻辑 */

这是C语言的switch特性：
- 多个case可以共享同一个代码块
- 减少代码重复
- 提高可维护性
```

#### SLAVE状态

```c
/* fsm.c, 第186-216行 */

case PS_SLAVE:
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES:
        next = PS_MASTER;
        break;
    case EV_SYNCHRONIZATION_FAULT:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_MASTER:
        next = PS_PRE_MASTER;
        break;
    case EV_RS_GRAND_MASTER:
        next = PS_GRAND_MASTER;
        break;
    case EV_RS_SLAVE:
        if (mdiff)  /* 主时钟变化了 */
            next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**mdiff参数的意义**：

```c
/* fsm.c:206-209（ptp_fsm 的 PS_SLAVE 分支内） */
case EV_RS_SLAVE:
	if (mdiff)
		next = PS_UNCALIBRATED;
	break;
```

```text
mdiff = "master difference"（主时钟差异）

含义：
- mdiff = 0：主时钟没变
- mdiff ≠ 0：主时钟变了

行为：
- 如果收到EV_RS_SLAVE且主时钟没变（mdiff=0）
  → 保持SLAVE状态，不需要重新校准

- 如果收到EV_RS_SLAVE且主时钟变了（mdiff≠0）
  → 进入UNCALIBRATED，重新同步

这是优化：
- 主时钟切换是常见情况
- 避免不必要的状态切换
```

## 仅从时钟状态机

### ptp_slave_fsm函数

```c
/* fsm.c:222-337 —— 以下为节选，完整函数含 6 个状态分支 */

enum port_state ptp_slave_fsm(enum port_state state, enum fsm_event event,
			      int mdiff)
{
	enum port_state next = state;

	if (EV_INITIALIZE == event || EV_POWERUP == event)   /* fsm.c:227-228 */
		return PS_INITIALIZING;

	switch (state) {
	case PS_INITIALIZING:   /* fsm.c:231-242 */
	case PS_FAULTY:         /* fsm.c:244-255 */
	case PS_DISABLED:       /* fsm.c:257-260 */
	case PS_LISTENING:      /* fsm.c:262-282 */
	case PS_UNCALIBRATED:   /* fsm.c:284-304 */
	case PS_SLAVE:          /* fsm.c:306-330 */
		/* …各分支见下… */
		break;
	default:                /* fsm.c:332-333 */
		break;          /* PRE_MASTER / MASTER / GRAND_MASTER / PASSIVE
		                   四个主时钟侧状态在 ptp_slave_fsm 里没有分支，
		                   落到这里，next 保持 state 不变 */
	}

	return next;                /* fsm.c:336 */
}
```

**与主状态机的区别**：

```text
ptp_fsm（完整状态机，fsm.c:21-220）：
- 可以成为主时钟
- 可以成为从时钟
- 10 个 PS_* 状态全都有分支，可以进入所有状态

ptp_slave_fsm（仅从状态机，fsm.c:222-337）：
- 永远不能成为主时钟：PS_PRE_MASTER / PS_MASTER / PS_GRAND_MASTER /
  PS_PASSIVE 四个状态在它这里没有任何 case，落到 default: break;（fsm.c:332-333）
- EV_RS_MASTER / EV_RS_GRAND_MASTER / EV_RS_PASSIVE / EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES
  这四个事件不是被“忽略”，而是**显式列为 case 标签并归一到 PS_LISTENING**
  （LISTENING 里 fsm.c:270-275；UNCALIBRATED 里 fsm.c:292-297；
   SLAVE 里 fsm.c:314-319）
- 可达状态是 **6 个**，不是 3 个：
  PS_INITIALIZING（fsm.c:231）、PS_FAULTY（:244）、PS_DISABLED（:257）、
  PS_LISTENING（:262）、PS_UNCALIBRATED（:284）、PS_SLAVE（:306）

适用场景：
- defaultDS.slaveOnly = TRUE 的设备（配置项现名 clientOnly，
  slaveOnly 是已废弃的旧名，config.c:264、787-788）
- 不想参与BMCA的终端设备
```


### 状态机其实有四套，不是两套

除了上面这两套，v4.4 还有另外两套，装在 `designated_fsm.c`（107 行）里：`designated_master_fsm()`（`designated_fsm.c:23`）与 `designated_slave_fsm()`（`designated_fsm.c:64`）。选哪一套是在 `port_open()` 里一次性决定的，装进 `p->state_machine` 这个函数指针（`port_private.h:102-103`）：

```c
/* port.c:3583-3594（逐字，节选） */

if (p->bmca == BMCA_NOOP && !port_is_uds(p)) {
	if (p->master_only) {
		p->state_machine = designated_master_fsm;
	} else if (clock_slave_only(clock)) {
		p->state_machine = designated_slave_fsm;
	} else {
		pr_err("Please enable at least one of serverOnly or clientOnly when BMCA == noop.\n");
		goto err_transport;
	}
} else {
	p->state_machine = clock_slave_only(clock) ? ptp_slave_fsm : ptp_fsm;
}
```

判据是 `clock_slave_only()`，它读的是 `defaultDS` 的标志位，就一行（`clock.c:1919-1922`）：

```c
/* clock.c:1919-1922 （逐字摘录，中文注释为本书所加） */

int clock_slave_only(struct clock *c)
{
	return c->dds.flags & DDS_SLAVE_ONLY;
}
```

```c
	}
```

## 状态机的使用

### 在端口中调用状态机

真实的调用链有**三层**，不是一层：`port_dispatch()` 只做一次函数指针转发，选哪套状态机是 `port_open()` 时就定好的（见上一节），转移动作则按延迟机制分成 E2E / P2P 两个版本。

```c
/* 第一层：port_dispatch() —— port.c:2922-2925 逐字，就这么薄 */

void port_dispatch(struct port *p, enum fsm_event event, int mdiff)
{
	p->dispatch(p, event, mdiff);
}

/* p->dispatch 在 port_open() 里按 clock_type 赋好（port.c:3553-3569）：
   OC/BC → bc_dispatch，P2P → p2p_dispatch，E2E → e2e_dispatch */

/* 第二层：bc_dispatch() —— 以下为改写版（节选），真实源码见 port.c:2927-2957 */

static void bc_dispatch(struct port *p, enum fsm_event event, int mdiff)
{
	if (clock_slave_only(p->clock)) {          /* port.c:2929-2933 */
		if (event == EV_RS_GRAND_MASTER) {
			port_slave_priority_warning(p);    /* 只警告，不改流向 */
		}
	}

	if (!port_state_update(p, event, mdiff)) { /* port.c:2935-2937 */
		return;                            /* 状态没变，连定时器都不用重排 */
	}

	switch (p->delayMechanism) {               /* port.c:2939-2947 */
	case DM_COMMON_P2P:
	case DM_P2P:
		port_p2p_transition(p, p->state);
		break;
	default:
		port_e2e_transition(p, p->state);
		break;
	}

	/* …jbod 下 PHC 切换失败会补发 EV_FAULT_DETECTED，port.c:2949-2956… */
}

/* 第三层：port_state_update() —— 以下为改写版（节选），真实源码见 port.c:3761-3803 */

int port_state_update(struct port *p, enum fsm_event event, int mdiff)
{
	enum port_state next = p->state_machine(p->state, event, mdiff);  /* :3763 */
	/* ↑ 就是这一句调用 fsm.c 里的纯函数；用哪个由 p->state_machine
	   这个函数指针决定（port.c:3593），所以这里不需要 if/else 判断
	   slave_only */

	if (PS_FAULTY == next) {                    /* port.c:3765-3772 */
		struct fault_interval i;
		fault_interval(p, last_fault_type(p), &i);
		if (port_link_status_get(p) && clear_fault_asap(&i)) {
			pr_notice("%s: clearing fault immediately", p->log_name);
			next = p->state_machine(next, EV_FAULT_CLEARED, 0);
		}
	}

	if (PS_INITIALIZING == next) {              /* port.c:3774-3789 */
		/* 特例：初始化是立刻做的，所以可以顺手把结果喂回状态机，
		   一步就直接落到 LISTENING（或 FAULTY） */
		if (port_is_enabled(p)) {
			port_disable(p);
		}
		if (port_initialize(p)) {           /* port.c:2006 */
			event = EV_FAULT_DETECTED;
		} else {
			event = EV_INIT_COMPLETE;
		}
		next = p->state_machine(next, event, 0);
	}

	if (mdiff) {
		p->unicast_state_dirty = true;      /* port.c:3791-3793 */
	}
	if (next != p->state) {                     /* port.c:3794-3800 */
		port_show_transition(p, next, event);   /* port.c:1342，打印状态迁移日志 */
		p->state = next;
		port_notify_event(p, NOTIFY_PORT_STATE); /* port.c:3498，通知订阅者 */
		p->unicast_state_dirty = true;
		return 1;
	}

	return 0;                                   /* port.c:3802 */
}
```

### 状态转移动作（没有 enter / exit 之分）

这里要更正一个模型上的误解：linuxptp **没有**分离的 enter / exit 两个钩子。真实做法是“**先清空所有定时器，再按新状态把该起的起起来**”，一个函数干完，参数是 `next`（新状态）。下面这段是逐字抄的 E2E 版本：

```c
/* port.c, 第2828-2873行（逐字，仅加了中文注释） */

static void port_e2e_transition(struct port *p, enum port_state next)
{
	port_clr_tmo(p->fda.fd[FD_ANNOUNCE_TIMER]);        /* 先把六个定时器全清掉 */
	port_clr_tmo(p->fda.fd[FD_SYNC_RX_TIMER]);
	port_clr_tmo(p->fda.fd[FD_DELAY_TIMER]);
	port_clr_tmo(p->fda.fd[FD_QUALIFICATION_TIMER]);
	port_clr_tmo(p->fda.fd[FD_MANNO_TIMER]);
	port_clr_tmo(p->fda.fd[FD_SYNC_TX_TIMER]);
	/* Leave FD_UNICAST_REQ_TIMER running. */

	switch (next) {
	case PS_INITIALIZING:
		break;                                   /* 什么也不做 */
	case PS_FAULTY:
	case PS_DISABLED:
		port_disable(p);                           /* :2843 */
		sad_set_last_seqid(clock_config(p->clock), p->spp, -1);
		break;
	case PS_LISTENING:
		port_set_announce_tmo(p);                  /* :2847 */
		break;
	case PS_PRE_MASTER:
		port_set_qualification_tmo(p);             /* :2850 */
		break;
	case PS_MASTER:
	case PS_GRAND_MASTER:
		if (!p->inhibit_announce) {
			set_tmo_log(p->fda.fd[FD_MANNO_TIMER], 1, -10); /*~1ms*/
		}                                          /* :2854-2856 */
		port_set_sync_tx_tmo(p);                   /* :2857 */
		sad_set_last_seqid(clock_config(p->clock), p->spp, -1);
		break;
	case PS_PASSIVE:
		port_set_announce_tmo(p);                  /* :2861 */
		break;
	case PS_UNCALIBRATED:
		flush_last_sync(p);                        /* :2864 */
		flush_delay_req(p);                        /* :2865 */
		sad_set_last_seqid(clock_config(p->clock), p->spp, -1);
		/* fall through */
	case PS_SLAVE:
		port_set_announce_tmo(p);                  /* :2869 */
		port_set_delay_tmo(p);                     /* :2870 */
		break;
	};
}
```

**各状态的真实动作对照**：

```text
port_e2e_transition()（port.c:2838-2872）：

PS_INITIALIZING（:2839-2840）
- 转移函数里什么都不做
- 真正的初始化不在这里，而是 port_state_update() 检测到 next == PS_INITIALIZING
  时先调 port_initialize()（port.c:2006，把 config 里的 portDS 各项读进结构体、
  建 timerfd），再立刻喂回 EV_INIT_COMPLETE / EV_FAULT_DETECTED（port.c:3774-3789）

PS_FAULTY / PS_DISABLED（:2841-2845）
- port_disable(p)（port.c:1978）：清 TC、flush 三个队列、p->best = NULL、
  free_foreign_masters(p)、关传输、关所有 timer fd
- sad_set_last_seqid(..., -1)：把安全关联的序号基线复位

PS_LISTENING（:2846-2848）
- 只起 Announce 接收超时定时器：port_set_announce_tmo(p)
- 注意：清空外部主时钟（foreign master）列表发生在 port_disable() 里
  （port.c:1988），不是进 LISTENING 的时候

PS_PRE_MASTER（:2849-2851）
- 起资格超时定时器：port_set_qualification_tmo(p)

PS_MASTER / PS_GRAND_MASTER（:2852-2859）
- 两个状态共用同一套代码（switch 的 case 落穿）
- 若未 inhibit_announce，把 Announce 发送定时器设成约 1ms（set_tmo_log(fd, 1, -10)）
- 起 Sync 发送定时器：port_set_sync_tx_tmo(p)
- “准备响应 Delay_Req”不需要额外动作——收包分发本来就一直开着

PS_PASSIVE（:2860-2862）
- 同样只起 Announce 接收超时定时器（所以 PASSIVE 也能因超时升级为 MASTER，
  见 fsm.c:138-140）

PS_UNCALIBRATED（:2863-2867）
- flush_last_sync(p) + flush_delay_req(p)：清掉待配对的 Sync 与待响应的 Delay_Req
- 复位安全序号，然后 fall through 到 PS_SLAVE

PS_SLAVE（:2868-2871）
- 起 Announce 接收超时定时器 + 起 Delay_Req 发送定时器
```

P2P 版本 `port_p2p_transition()`（`port.c:2875-2920`）结构完全一样，只有三处差别：**DELAY 定时器跨转移不清**（`port.c:2879` 注释 “Leave FD_DELAY_TIMER running.”）；进 LISTENING 时**额外**起 Delay 定时器（`port.c:2893-2896`，因为 P2P 要一直和对端测 peer delay）；进 UNCALIBRATED 时 flush 的是 peer delay 而不是 delay_req（`port.c:2911-2914`），且 PS_SLAVE 分支**不再**调 `port_set_delay_tmo()`（`port.c:2916-2918`）。

## 设计模式分析

### 状态模式

LinuxPTP的状态机实现了经典的状态模式：

```text
状态模式的要素：
1. 状态枚举（enum port_state）
2. 事件枚举（enum fsm_event）
3. 状态转换表（switch-case嵌套）
4. 状态转移动作（先清空全部定时器，再按新状态重排；E2E 与 P2P 各一份）

优点：
- 状态转换逻辑集中在一处
- 易于添加新状态
- 易于添加新事件
- 状态转换清晰可见
```

### 表驱动 vs 嵌套switch

LinuxPTP选择**嵌套switch**而不是**状态转换表**：

```text
状态转换表方式（伪代码）：
struct {
    enum port_state from;
    enum fsm_event event;
    enum port_state to;
} state_table[] = {
    {PS_INITIALIZING, EV_INIT_COMPLETE, PS_LISTENING},
    {PS_LISTENING, EV_RS_SLAVE, PS_UNCALIBRATED},
    // ...
};

嵌套switch方式：
switch (state) {
    case PS_INITIALIZING:
        switch (event) {
            case EV_INIT_COMPLETE:
                next = PS_LISTENING;
        }
}

为什么选择嵌套switch？

优点：
- 代码紧凑
- 编译器优化好
- 无需额外数据结构
- 易于调试（可以在case中加日志）

缺点：
- 添加状态需要修改多处代码
- 不如表驱动直观

LinuxPTP的考虑：
- 状态数量固定（标准 9 个 + linuxptp 私有的 PS_GRAND_MASTER = 10 个）
- 事件数量固定（17个）
- 状态转换规则稳定
- 选择嵌套switch更高效
```

## 小结：状态机的设计智慧

**函数式设计**：
- 纯函数，无副作用
- 易于测试和调试

**默认保持状态**：
- 未处理的事件不改变状态
- 避免意外状态转换

**快速路径处理**：
- 特殊事件提前返回
- 减少嵌套深度

**状态合并**：
- 相似状态共享代码
- 减少代码重复

**状态机是可替换的函数指针**：
- 完整状态机（`ptp_fsm`，fsm.c:21-220）
- 仅从状态机（`ptp_slave_fsm`，fsm.c:222-337）
- 另有 `designated_master_fsm` / `designated_slave_fsm`（designated_fsm.c:23、64），供 `bmca == BMCA_NOOP` 的 G.8275.1 场景使用
- 四者同签名，装在 `p->state_machine` 里，由 `port_open()` 一次选定（port.c:3583-3594）

> **【悬念留给3.4】**

>
> 它需要比较两个数据集，决定谁更适合当主时钟。

> LinuxPTP的BMCA实现只有175行，包括：
> - 数据集比较函数
> - 状态决策函数
>
> 它是如何在这么少的代码中实现完整的BMCA？
>
> 下一节，我们详细解读。
