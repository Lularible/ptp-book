# 3.5 伺服控制器：让时钟追上主人的艺术

## 同步的核心问题

当PTP端口进入SLAVE状态后，面临的核心问题是：

**如何调整本地时钟，使其与主时钟保持同步？**

这就是伺服控制器（Servo）的任务。

---

## 伺服控制器概述

### 伺服的作用

```text
伺服控制器的输入：
- offset：本地时钟与主时钟的偏差（纳秒）
- local_ts：本地时间戳
- weight：样本权重

伺服控制器的输出：
- ppb：频率调整值（parts per billion，十亿分之一）

伺服控制器的目标：
- 最小化offset
- 使本地时钟频率与主时钟一致
```

### LinuxPTP支持的伺服类型

```c
/* servo.h, 第33-39行 */

enum servo_type {
    CLOCK_SERVO_PI,          /* PI控制器（最常用） */
    CLOCK_SERVO_LINREG,      /* 线性回归滤波器 */
    CLOCK_SERVO_NTPSHM,      /* NTP共享内存 */
    CLOCK_SERVO_NULLF,       /* 空滤波器 */
    CLOCK_SERVO_REFCLOCK_SOCK, /* 参考时钟套接字 */
};
```

**各伺服类型的特点**：

```text
PI控制器：
- 比例-积分控制器
- 经典的控制理论方法
- 参数可调，适应性强
- 适合大多数场景

线性回归滤波器：
- 基于统计学方法（加权最小二乘拟合）
- 自适应窗口大小（4/8/16/32/64 个点）
- 适合高精度场景

NTP共享内存：
- 与NTP共享时间信息
- 用于混合部署
- 不直接调整时钟（恒返回0.0、状态恒为UNLOCKED，ntpshm.c:117-118）

空滤波器：
- 恒返回 0.0 ppb，从不调整频率（nullf.c:46、:57）
- 只按阈值判定状态：LOCKED / JUMP / UNLOCKED
- 用于"只测量不调钟"的场景

参考时钟套接字：
- 把样本经Unix socket送出去，由外部程序（如chrony）做滤波
- 协议结构抄自chrony-3.2的refclock_sock.c（refclock_sock.c:35）
- 用于GPS等外部源
```

## PI控制器详解

### PI控制器原理

```text
PI控制器 = 比例（P）+ 积分（I）

控制方程：
output = Kp × offset + Ki × ∫offset dt（源码里这个积分累积量就是 drift）

其中：
- Kp：比例增益
- Ki：积分增益
- offset：当前偏差
- drift：累积的频率漂移

比例项（P）：
- 响应当前偏差
- 偏差越大，调整越大
- 快速响应

积分项（I）：
- 响应历史累积偏差
- 消除稳态误差
- 长期稳定
```

### PI控制器采样函数

```c
/* pi.c, 第64-155行 */

static double pi_sample(struct servo *servo,
                        int64_t offset,
                        uint64_t local_ts,
                        double weight,
                        enum servo_state *state)
{
    struct pi_servo *s = container_of(servo, struct pi_servo, servo);
    double ki_term, ppb = s->last_freq;
    double freq_est_interval, localdiff;

    switch (s->count) {
    case 0:
        /* 第一次采样：只记录数据 */
        s->offset[0] = offset;
        s->local[0] = local_ts;
        *state = SERVO_UNLOCKED;
        s->count = 1;
        break;

    case 1:
        /* 第二次采样：估计频率偏差 */
        s->offset[1] = offset;
        s->local[1] = local_ts;

        /* 确保时间顺序正确 */
        if (s->local[0] >= s->local[1]) {
            *state = SERVO_UNLOCKED;
            s->count = 0;
            break;
        }

        /* 检查时间间隔是否足够 */
        localdiff = (s->local[1] - s->local[0]) / 1e9;
        localdiff += localdiff * FREQ_EST_MARGIN;
        freq_est_interval = 0.016 / s->ki;
        if (freq_est_interval > 1000.0) {
            freq_est_interval = 1000.0;
        }
        if (localdiff < freq_est_interval) {
            *state = SERVO_UNLOCKED;
            break;
        }

        /* 估计频率偏差 */
        s->drift += (1e9 - s->drift) * (s->offset[1] - s->offset[0]) /
                                    (s->local[1] - s->local[0]);

        /* 限制频率范围 */
        if (s->drift < -servo->max_frequency)
            s->drift = -servo->max_frequency;
        else if (s->drift > servo->max_frequency)
            s->drift = servo->max_frequency;

        /* 判断是否需要阶跃 */
        if ((servo->first_update &&
             servo->first_step_threshold &&
             servo->first_step_threshold < llabs(offset)) ||
            (servo->step_threshold &&
             servo->step_threshold < llabs(offset)))
            *state = SERVO_JUMP;
        else
            *state = SERVO_LOCKED;

        ppb = s->drift;
        s->count = 2;
        break;

    case 2:
        /* 正常工作：PI控制 */
        
        /* 检查是否需要重置 */
        if (servo->step_threshold &&
            servo->step_threshold < llabs(offset)) {
            *state = SERVO_UNLOCKED;
            s->count = 0;
            break;
        }

        /* PI控制方程 */
        ki_term = s->ki * offset * weight;
        ppb = s->kp * offset * weight + s->drift + ki_term;
        
        /* 限制输出范围 */
        if (ppb < -servo->max_frequency) {
            ppb = -servo->max_frequency;
        } else if (ppb > servo->max_frequency) {
            ppb = servo->max_frequency;
        } else {
            s->drift += ki_term;  /* 更新积分项 */
        }
        
        *state = SERVO_LOCKED;
        break;
    }

    s->last_freq = ppb;
    return ppb;
}
```

**三阶段采样详解**：

```text
阶段0（count=0）：初始化
- 记录第一个样本
- 状态：UNLOCKED
- 输出：上次频率（无新调整）

阶段1（count=1）：频率估计
- 记录第二个样本
- 计算两个样本之间的频率偏差
- 公式：drift += (1e9 - drift) × (offset[1] - offset[0]) / (local[1] - local[0])
- 这是对本地振荡器频率偏差的估计
- 状态：LOCKED或JUMP
- 输出：估计的drift

阶段2（count=2）：正常PI控制
- 每次采样都执行PI控制
- 公式：ppb = (kp + ki) × offset × weight + drift
- 状态：LOCKED
- 输出：PI控制器输出
```

### PI参数调整

```c
/* pi.c, 第157-171行 */

static void pi_sync_interval(struct servo *servo, double interval)
{
    struct pi_servo *s = container_of(servo, struct pi_servo, servo);

    /* 根据Sync间隔自动调整Kp */
    s->kp = s->configured_pi_kp_scale * 
            pow(interval, s->configured_pi_kp_exponent);
    if (s->kp > s->configured_pi_kp_norm_max / interval)
        s->kp = s->configured_pi_kp_norm_max / interval;

    /* 根据Sync间隔自动调整Ki */
    s->ki = s->configured_pi_ki_scale * 
            pow(interval, s->configured_pi_ki_exponent);
    if (s->ki > s->configured_pi_ki_norm_max / interval)
        s->ki = s->configured_pi_ki_norm_max / interval;

    pr_debug("PI servo: sync interval %.3f kp %.3f ki %.6f",
             interval, s->kp, s->ki);
}
```

**自适应参数的意义**：

```text
为什么要根据Sync间隔调整参数？

Sync间隔长：
- 两个样本之间间隔长
- 频率估计更准确
- 但响应慢
- 需要更大的Kp和Ki

Sync间隔短：
- 两个样本之间间隔短
- 频率估计可能不准
- 但响应快
- 需要更小的Kp和Ki

公式（pi.c:161-167）：
kp = kp_scale × interval^kp_exponent，再按 kp_norm_max / interval 封顶
ki = ki_scale × interval^ki_exponent，再按 ki_norm_max / interval 封顶

config.c 里的默认值（注意：两个 scale 的默认值是 0！）：
- pi_proportional_scale   = 0.0      config.c:338
- pi_proportional_exponent = -0.3    config.c:336
- pi_proportional_norm_max = 0.7     config.c:337（上限 1.0）
- pi_integral_scale       = 0.0      config.c:334
- pi_integral_exponent    = 0.4      config.c:332
- pi_integral_norm_max    = 0.3      config.c:333（上限 2.0）

这意味着：
- 默认情况下Kp和Ki就随Sync间隔自适应：间隔越长，Kp越小（×interval⁻⁰·³）、Ki越大（×interval⁰·⁴）
- 只有当用户显式设置`pi_proportional_const`和`pi_integral_const`进入固定模式时，指数才被强制为0，Kp/Ki不随间隔变化
```

## 线性回归滤波器详解

### 原理

```text
线性回归滤波器的思想：
- 收集多个(offset, time)样本点
- 用线性回归拟合一条直线
- 直线的斜率 = 频率偏差
- 直线的截距 = 初始偏差

优点：
- 利用多个样本，减少噪声影响（最小二乘本身的平滑作用）
- 自适应窗口大小：4/8/16/32/64 五种长度里挑一个
- 频率估计与相位拉回解耦：斜率给频率，截距给"还要拉多少"

数学公式：
给定n个点(x_i, y_i)，回归直线：
y = slope × x + intercept

等权重时的闭式解：
slope = (n∑xy - ∑x∑y) / (n∑x² - (∑x)²)
intercept = (∑y - slope×∑x) / n

源码是**带权重 w_i 的版本**（linreg.c:186-188），把 ∑ 换成 ∑(·×w)、n 换成 ∑w：
res->slope = (xy_sum - x_sum * y_sum / w_sum) /
             (x2_sum - x_sum * x_sum / w_sum);
res->intercept = (y_sum - res->slope * x_sum) / w_sum;
权重全相等时，两式与上面那组闭式解等价。
```

### 线性回归采样

真实函数是 `linreg_sample()`（`linreg.c:216-287`），调用序列固定四步：`update_reference → add_sample → regress → update_size`（`linreg.c:234-238`）。下面按源码**改写**：函数名、调用顺序、判据与返回值语义都与源码一致，只省略了 `pr_debug()` 这一行调试输出（`linreg.c:248-249`），并把源码的英文注释换成中文旁注。

```c
/* linreg.c:216-287，按源码改写（省略pr_debug） */

static double linreg_sample(struct servo *servo,
                            int64_t offset,
                            uint64_t local_ts,
                            double weight,
                            enum servo_state *state)
{
    struct linreg_servo *s = container_of(servo, struct linreg_servo, servo);
    struct result *res;
    int corr_interval;

    /* 源码开头有一段注释（linreg.c:226-232）交代了一个近似假设：
       把"当前时刻"与"频率真正被写进时钟的时刻"都当作 local_ts
       （即收到 Sync 的本地时间戳）；只要两者的差远小于更新间隔，
       环路就足够稳。 */

    /* 步骤1：把reference推进到local_ts（这一步最容易被漏掉，
       reference.x / reference.y / x_remainder / last_update 四个字段全靠它维护）。
       y 累加的是原始本地时间间隔；
       x 累加的是"去掉当前 clock_freq 修正量之后"的间隔，
       即 x_interval = y_interval / (1.0 + clock_freq / 1e9)（linreg.c:116），
       小数部分存进 x_remainder 下次接着用（linreg.c:117-118）。 */
    update_reference(s, local_ts);       /* 定义 linreg.c:107-124 */

    /* 步骤2：写入环形缓冲区。注意坐标不是(local_ts, offset)，
       而是(reference.x, reference.y - offset) */
    add_sample(s, offset, weight);       /* 定义 linreg.c:126-136 */

    /* 步骤3：在内部对全部窗口长度各做一次加权回归，
       结果写进 s->results[size - MIN_SIZE] */
    regress(s);                          /* 定义 linreg.c:138-190 */

    /* 步骤4：挑窗口长度，结果写 s->size（返回void） */
    update_size(s);                      /* 定义 linreg.c:192-214 */

    if (s->size < MIN_SIZE) {            /* linreg.c:240，不是"MIN_POINTS" */
        /* 点数不够：regress()里 n > s->num_points 就break，窗口选不出来 */
        *state = SERVO_UNLOCKED;
        return -s->clock_freq;
    }

    res = &s->results[s->size - MIN_SIZE];

    /* 判断要不要跳变：比的是拟合截距，不是offset本身 */
    if ((servo->first_update &&
         servo->first_step_threshold &&
         servo->first_step_threshold < fabs(res->intercept)) ||
        (servo->step_threshold &&
         servo->step_threshold < fabs(res->intercept))) {
        move_reference(s, 0, -offset);   /* 时钟即将被跳offset，reference跟着跳 */
        s->last_update -= offset;
        *state = SERVO_JUMP;
    } else {
        *state = SERVO_LOCKED;
    }

    /* 步骤5：斜率是无量纲频率比（≈1.0），换算成ppb */
    s->clock_freq = 1e9 * (res->slope - 1.0);            /* linreg.c:265 */

    /* 步骤6：再叠一项"把残余相位截距拉回去"的修正，窗口越长拉得越慢 */
    corr_interval = s->size <= 4 ? 1 : s->size / 2;      /* linreg.c:275 */
    s->clock_freq += res->intercept / s->update_interval / corr_interval;

    /* 步骤7：钳到 ±max_frequency */
    if (s->clock_freq > servo->max_frequency)
        s->clock_freq = servo->max_frequency;
    else if (s->clock_freq < -servo->max_frequency)
        s->clock_freq = -servo->max_frequency;

    s->frequency_ratio = res->slope / (1.0 + s->clock_freq / 1e9);

    return -s->clock_freq;                               /* linreg.c:286 */
}
```

### 自适应窗口选择

```c
/* 选择最佳窗口大小 */

static void update_size(struct linreg_servo *s)
{
    struct result *res;
    double best_err;
    int size, best_size;

    /* Find largest size with smallest prediction error */

    best_size = 0;
    best_err = 0.0;

    for (size = MIN_SIZE; size <= MAX_SIZE; size++) {
        res = &s->results[size - MIN_SIZE];
        if ((!best_size && res->slope) ||
            (best_err * ERR_EQUALS > res->err &&
             res->err_updates >= ERR_INITIAL_UPDATES)) {
            best_size = size;
            best_err = res->err;
        }
    }

    s->size = best_size;
}
```

**自适应原理**：

```text
源码注释自己说明了准则：Find largest size with smallest prediction error。不是"取误差最小的窗口"，而是"在够好的窗口里取最长的那个"。

判据拆成两支（linreg.c:205-207）：
- (!best_size && res->slope)
    第一个"有回归结果"的窗口先无条件入选（点数不够时res->slope保持0）
- (best_err * ERR_EQUALS > res->err && res->err_updates >= ERR_INITIAL_UPDATES)
    当前窗口的预测误差 err 不超过已选最好者的 1.05 倍
    （ERR_EQUALS = 1.05，linreg.c:39），
    且它的误差统计已经初始化完毕
    （ERR_INITIAL_UPDATES = 10 次更新，linreg.c:37）

误差 err 是"截距预测值 vs 实测值"的滑动平均（linreg.c:157-168）：
- 前 10 次累加求均值
- 之后按 ERR_SMOOTH = 0.02（linreg.c:35）做指数平滑

好处：
- 点数少时自然回落到短窗口（regress里 n > num_points 就break，
  对应 results[] 项的 slope 一直是 0，选不上）
- 点数够且预测不差时优先用长窗口（4→8→16→32→64），更平稳
- 没有配置文件参与：MIN_SIZE / MAX_SIZE 是编译期#define
```

### pi_reset 与 linreg_reset：复位强度差两个量级

基类的第 4 个虚函数是 `reset`（`servo_private.h:44`），转发层 `servo_reset()` 只是一行 `servo->reset(servo)`（`servo.c:157-160`）。两个伺服的实现差异极大：

```c
/* pi.c:173-178 —— 最小复位：只把采样阶段打回0 */

static void pi_reset(struct servo *servo)
{
    struct pi_servo *s = container_of(servo, struct pi_servo, servo);

    s->count = 0;
}
```

```c
/* linreg.c:296-310 —— 把回归积累的历史全清掉 */

static void linreg_reset(struct servo *servo)
{
    struct linreg_servo *s = container_of(servo, struct linreg_servo, servo);
    unsigned int i;

    s->num_points = 0;
    s->last_update = 0;
    s->size = 0;
    s->frequency_ratio = 1.0;

    for (i = MIN_SIZE; i <= MAX_SIZE; i++) {
        s->results[i - MIN_SIZE].slope = 0.0;
        s->results[i - MIN_SIZE].err_updates = 0;
    }
}
```

```text
字段            pi_reset                    linreg_reset
计数/点数       s->count = 0                num_points = 0, size = 0
频率估计        drift 保留（不清零）        各窗口 slope = 0.0, err_updates = 0
时间基准        local[]/offset[] 不动       last_update = 0（reference靠它续算）
频率比          无：PI不提供rate_ratio      frequency_ratio = 1.0
已施加的频偏    last_freq 保留              clock_freq 保留（不动）
```

## 伺服状态详解

### 四种状态

```c
/* servo.h, 第44-67行 */

enum servo_state {
    SERVO_UNLOCKED,       /* 未锁定 */
    SERVO_JUMP,           /* 需要跳变 */
    SERVO_LOCKED,         /* 已锁定 */
    SERVO_LOCKED_STABLE,  /* 稳定锁定 */
};
```

**状态含义**：

```text
SERVO_UNLOCKED：
- 伺服还没有足够的数据
- 或者偏差过大需要重置
- 不能可靠地调整时钟

SERVO_JUMP：
- 偏差超过阈值
- 需要时钟跳变
- 用于快速修正大偏差

SERVO_LOCKED：
- 伺服正在跟踪
- 偏差在正常范围
- 进行正常的频率调整

SERVO_LOCKED_STABLE：
- 连续多次偏差小于阈值
- 伺服已稳定
- 可以考虑降低Sync频率
```

### 状态转换

`servo_sample()` 的完整源码见前面「采样函数」一节，这里只补最后一支——它带着 `servo.c` 里一段很关键的注释：

```c
/* servo.c:126-147，节选最后一支（前三支见上） */

    switch (*state) {
    /* SERVO_UNLOCKED / SERVO_JUMP / SERVO_LOCKED 三支：servo.c:127-139 */
    case SERVO_LOCKED_STABLE:
        /*
         * This case will never occur since the only place
         * SERVO_LOCKED_STABLE is set is in this switch/case block
         * (case SERVO_LOCKED).
         */
        break;
    }
```

```c
/* servo.c:100-114，完整源码 */

static int check_offset_threshold(struct servo *s, int64_t offset)
{
    long long int abs_offset = llabs(offset);

    if (s->offset_threshold) {
        if (abs_offset < s->offset_threshold) {
            if (s->curr_offset_values)
                s->curr_offset_values--;
        } else {
            s->curr_offset_values = s->num_offset_values;
        }
        return s->curr_offset_values ? 0 : 1;
    }
    return 0;
}
```

**稳定检测逻辑**：

```text
配置参数：
- servo_offset_threshold：偏差阈值
- servo_num_offset_values：检查次数

工作原理：
1. 每次采样，检查|offset|是否小于阈值
2. 如果小于，计数器减1
3. 如果大于，计数器重置
4. 当计数器减到0，进入LOCKED_STABLE

示例：
配置：offset_threshold = 100ns, num_offset_values = 5

样本1：|offset| = 80ns < 100ns → count = 4
样本2：|offset| = 90ns < 100ns → count = 3
样本3：|offset| = 150ns > 100ns → count = 5（重置）
样本4：|offset| = 70ns < 100ns → count = 4
样本5：|offset| = 60ns < 100ns → count = 3
样本6：|offset| = 80ns < 100ns → count = 2
样本7：|offset| = 90ns < 100ns → count = 1
样本8：|offset| = 85ns < 100ns → count = 0 → LOCKED_STABLE

这确保：
- 连续N次偏差都小于阈值才认为稳定
- 任何一次超差都会重置计数
```

## 阶跃阈值配置

### 阶跃的作用

```text
当偏差很大时：
- 逐渐调整太慢
- 需要时钟跳变

阶跃阈值决定何时跳变：
- step_threshold：正常运行时的阈值
- first_step_threshold：首次同步的阈值

为什么区分首次和正常？

首次同步：
- 设备刚启动，偏差可能很大（毫秒甚至秒级）
- 允许更大的首次跳变
- 快速进入同步状态

正常运行：
- 偏差应该在纳秒级
- 只允许小的跳变
- 避免服务中断
```

### 配置示例

```ini
# 配置文件ptp4l 用 -f <file> 指定（ptp4l.c:57），
# 仓库自带的样例在 configs/*.cfg（如 configs/default.cfg、configs/gPTP.cfg）。

[global]
# 正常运行期的阶跃阈值（秒）。默认 0.0 = 禁用（config.c:362）
step_threshold 0.0

# 首次同步的阶跃阈值（秒）。默认 0.00002 = 20微秒（config.c:288）
first_step_threshold 0.00002

# 频率调整上限（ppb）。默认 900000000 ≈ "不额外设限"（config.c:316），
# 实际生效值取 min(硬件能力, 本项)：servo.c:81-85。
# 下面这行是"用户主动收紧到 500ppm"的示例，不是默认值
max_frequency 500000
```

**实际效果**：

```text
场景：设备刚启动，偏差 = 1秒

配置：first_step_threshold = 0.00002（20微秒，默认值）
      step_threshold = 0.0（禁用，默认值）

处理：
1. servo->first_update 初值为1（servo.c:87），
   阶段1 的判断式走"first_update && first_step_threshold < |offset|"这一支
   （pi.c:113-118）
2. |offset| = 1秒 > 20微秒 ⇒ SERVO_JUMP
3. clock_synchronize() 先 clockadj_set_freq(-adj)、再 clockadj_step(-offset)
   （clock.c:2055-2061）；跳变后 step_window_counter 若配置了 step_window
   会被置起（clock.c:2069、:1982-1988），随后几拍 sync 直接跳过不做同步
4. first_update 置 0（servo.c:132），偏差被一次性抹平
5. 之后 step_threshold = 0，再大的偏差也只调频、不跳变

后续运行中，如果改配 step_threshold = 0.00001（10微秒）：
1. 阶段2（count=2）里 |offset| = 20微秒 > 10微秒 ⇒ 先回 SERVO_UNLOCKED
   并把 count 清 0（pi.c:133-138），这一拍**不会**跳
2. pi.c:126-132 的注释解释了为什么：阶跃留到"阶段1"再做，
   好让 drift 像刚启动时那样重新估计一遍
3. 下一拍进阶段0（只记录），再下一拍进阶段1，
   此时 step_threshold 那一支成立（pi.c:116-118）⇒ SERVO_JUMP，跳一次
4. 跳完重新走估计 → 回到阶段2 正常调频
```

**两种配置模式**：

```text
    pi_proportional_const 0.7
    pi_integral_const     0.3

      但各自仍受 norm_max / interval 封顶（pi.c:162-163、:166-167）

    Kp = 0.7 × interval^0.5，封顶 0.7 / interval
    Ki = 0.3 × interval^0.4      ← 不是 ^0.5！
                                   ki 的指数来自 config.c:332 的默认值
```

## 小结：伺服控制器的设计智慧

**面向对象设计**：
- 基类定义接口
- 派生类实现具体算法
- 统一的调用方式

**三阶段采样**：
- 初始化 → 频率估计 → 正常控制
- 逐步进入稳定状态

**自适应参数**：
- 根据Sync间隔自动调整
- 适应不同网络条件

**多种算法选择**：
- PI控制器：经典可靠
- 线性回归：鲁棒性强
- 空滤波器：调试用
