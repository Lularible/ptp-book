# 4.4 从时钟程序实现：时间的“追随者”

> ⚠️ **重要提示**：
> - 完整、最新的源码请查看 `ptp_lite/` 目录（本章对齐 **1.1.0**，`ptp_common.h:21-22`）
> - 如发现差异，以源码为准

## 从时钟的职责

从时钟需要精确地追随主时钟：

```text
从时钟任务：

1. 接收Announce消息
   - 发现主时钟
   - 提取主时钟信息

2. 接收Sync+Follow_Up消息
   - 记录Sync接收时间t2
   - 从Follow_Up获取t1
   - 得到一次Sync的未补偿差值 (t2 - t1)，还不是最终偏差

3. 发送Delay_Req消息
   - 定期发送
   - 记录发送时间t3

4. 接收Delay_Resp消息
   - 获取t4
   - 计算路径延迟：delay = [(t2-t1) + (t4-t3)] / 2
   - 计算真实偏差：offset = (t2-t1) - delay

5. 调整系统时钟
   - 使用伺服算法
   - 渐进调整或跳变
```

## 伺服算法实现

### ptp_servo.h

```c
/* ptp_servo.h:1-75（逐字） */
/**
 * @file ptp_servo.h
 * @brief PI servo controller
 */

#ifndef PTP_SERVO_H
#define PTP_SERVO_H

#include <stdint.h>

/* PI gains: the software-timestamp pair of linuxptp, SWTS_KP_SCALE = 0.1 and
 * SWTS_KI_SCALE = 0.001 (pi.c:30-31). The 0.7 / 0.3 that used to be here are
 * its *hardware* timestamp gains (pi.c:28-29) - seven and three hundred times
 * too hot for timestamps carrying tens of microseconds of jitter.
 *
 * linuxptp also rescales both gains with the sync interval and caps them by
 * norm_max (pi_sync_interval(), pi.c:157-171). ptp_lite always runs a 1 s sync
 * interval and pow(1, x) == 1, so that normalisation would be a no-op and is
 * deliberately not implemented. */
#define SERVO_KP 0.1
#define SERVO_KI 0.001

/* Step threshold (nanoseconds) - 10 ms */
#define SERVO_STEP_THRESHOLD 10000000LL

/* Contract on the caller, not a bound the servo enforces: pi_servo_sample()
 * works in double and 2^53 ns (~104 days) is where an int64_t stops converting
 * to double exactly, so a larger |offset| is not "a very large offset" but an
 * invalid measurement (a stale or hostile timestamp pair) that whoever calls
 * us must reject instead of handing it here - see ptp_slave.c. Two clocks
 * further apart than this have to be brought together with `date -s` first. */
#define SERVO_MAX_OFFSET_NS (9007199254740992LL)   /* 2^53 nanoseconds */

/* Clamp on the loop output, in ppb: +-500 ppm, the fallback limit linuxptp
 * uses when the kernel reports no adjustable range (clockadj.c:139-140).
 * Uncapped, one sample at the step threshold asks Kp * 1e7 = 1e6 ppb = 1000 ppm,
 * twice the clamp: the kernel answers EINVAL while the integral keeps charging. */
#define SERVO_MAX_FREQ_PPB 500000.0

/* Clamp on the integral accumulator, in nanoseconds of summed offset, derived
 * so that the integral term alone never exceeds the full frequency range:
 * ki * SERVO_MAX_INTEGRAL_NS == SERVO_MAX_FREQ_PPB. */
#define SERVO_MAX_INTEGRAL_NS (SERVO_MAX_FREQ_PPB / SERVO_KI)

/* Consecutive in-range samples needed to count as locked, and as stably locked
 * (the old code tested count > 1 and count > 10). */
#define SERVO_LOCKED_SAMPLES 2
#define SERVO_STABLE_SAMPLES 11

/* Servo states */
typedef enum {
    SERVO_UNLOCKED,
    SERVO_JUMP,
    SERVO_LOCKED,
    SERVO_LOCKED_STABLE
} servo_state_t;

/* PI servo structure. There is no last_freq member on purpose: linuxptp keeps
 * one (pi.c:71, pi.c:192-193) because its two-step frequency estimator starts
 * from the previous estimate. ptp_lite writes the trim with
 * clock_adjtime(ADJ_FREQUENCY), an absolute setting that stays until written
 * again, so a sample with nothing to say simply writes nothing. */
typedef struct {
    double kp;
    double ki;
    double integral;
    servo_state_t state;
    int count;   /* saturates at SERVO_STABLE_SAMPLES, so it cannot overflow */
} pi_servo_t;

/* Function declarations */
void pi_servo_init(pi_servo_t *s);
double pi_servo_sample(pi_servo_t *s, int64_t offset, servo_state_t *state);

#endif /* PTP_SERVO_H */
```

### ptp_servo.c（`ptp_servo.c:1-88`，逐字）

```c
/* ptp_servo.c:1-88（逐字） */
/**
 * @file ptp_servo.c
 * @brief PI servo controller implementation
 */

#include <stdint.h>
#include "ptp_servo.h"

void pi_servo_init(pi_servo_t *s)
{
    s->kp = SERVO_KP;
    s->ki = SERVO_KI;
    s->integral = 0.0;
    s->state = SERVO_UNLOCKED;
    s->count = 0;
}

double pi_servo_sample(pi_servo_t *s, int64_t offset, servo_state_t *state)
{
    double freq_adj;
    uint64_t mag;

    /* |offset| in unsigned arithmetic. llabs(INT64_MIN) is undefined
     * behaviour, and INT64_MIN is exactly what a bogus 48-bit seconds field
     * used to produce; -(offset + 1) cannot overflow for any int64_t. */
    mag = (offset < 0) ? (uint64_t)(-(offset + 1)) + 1U : (uint64_t)offset;

    if (mag > (uint64_t)SERVO_STEP_THRESHOLD) {
        /* Large offset: ask the caller for one phase step, then go back to
         * UNLOCKED with count = 0 and integral = 0 so that the loop has to prove
         * itself again before it may steer the frequency. linuxptp does the same
         * on a jump: *state = SERVO_UNLOCKED, count = 0 (pi.c:133-138).
         *
         * The jump reaches the caller through *state exactly once; the stored
         * state does not keep it. The old code left the stored state at
         * SERVO_JUMP, so the next small sample found neither "count > 1" nor
         * "count > 10" true and stepped the clock a second time. */
        s->state = SERVO_UNLOCKED;
        s->integral = 0.0;
        s->count = 0;
        *state = SERVO_JUMP;
        return 0.0;   /* a step invalidates any frequency estimate */
    }

    /* Phase is close enough to steer. Saturate the counter at the promotion
     * point instead of letting it grow without bound. */
    if (s->count < SERVO_STABLE_SAMPLES) {
        s->count++;
    }
    if (s->count >= SERVO_STABLE_SAMPLES) {
        s->state = SERVO_LOCKED_STABLE;
    } else if (s->count >= SERVO_LOCKED_SAMPLES) {
        s->state = SERVO_LOCKED;
    } else {
        /* First in-range sample: nothing to steer with yet. */
        s->state = SERVO_UNLOCKED;
    }

    /* The PI term only runs in the locked states; UNLOCKED returns 0 and the
     * caller then leaves the clock trim alone. Sign convention: offset is
     * (local time - master time), so a positive offset means "we are ahead"
     * and asks for a negative frequency correction. */
    if (s->state == SERVO_UNLOCKED) {
        freq_adj = 0.0;
    } else {
        freq_adj = -s->kp * (double)offset - s->ki * s->integral;

        if (freq_adj > SERVO_MAX_FREQ_PPB) {
            freq_adj = SERVO_MAX_FREQ_PPB;
        } else if (freq_adj < -SERVO_MAX_FREQ_PPB) {
            freq_adj = -SERVO_MAX_FREQ_PPB;
        } else {
            /* Anti-windup: integrate only while the output is not saturated.
             * Otherwise a persistent offset would charge the integral term up
             * to a value the kernel refuses with EINVAL while the loop kept
             * asking for more (linuxptp pi.c:142-148). */
            s->integral += (double)offset;
            if (s->integral > SERVO_MAX_INTEGRAL_NS) {
                s->integral = SERVO_MAX_INTEGRAL_NS;
            } else if (s->integral < -SERVO_MAX_INTEGRAL_NS) {
                s->integral = -SERVO_MAX_INTEGRAL_NS;
            }
        }
    }

    *state = s->state;
    return freq_adj;
}
```

### 实现要点

1. **状态转换**：
   - 当 |offset| > 10ms 时，进入 JUMP 状态（相位跳变），内部随即回 UNLOCKED
   - 当 |offset| ≤ 10ms 且 count ≥ 2（`SERVO_LOCKED_SAMPLES`）时，进入 LOCKED 状态（频率调整）
   - 当 count ≥ 11（`SERVO_STABLE_SAMPLES`）时，进入 LOCKED_STABLE 状态

2. **PI控制器**：
   - 只在 LOCKED 和 LOCKED_STABLE 状态工作
   - 积分项累积历史偏差，实现精确控制

3. **为什么选择 10ms 阈值**：
   - 取得太小：软件时间戳的正常抖动就会触发相位跳变
   - 取得太大：明显跑偏的钟迟迟不肯步进，只能靠频率慢慢追
   - 10ms 是一个平衡选择

## 时钟调整实现

从时钟需要根据伺服状态调整系统时钟。1.1.0 把这一段拆成了三个部分：一个可移植的 `clock_adjtime`、抽出来的 `set_freq()`、以及瘦身后的 `adjust_clock()`。

### 一个可移植的 `clock_adjtime`（`ptp_slave.c:33-48`，逐字）

### `set_freq` 与 `adjust_clock`（`ptp_slave.c:247-324`，逐字）

```c
/* ptp_slave.c:247-324（逐字） */
/** @brief Apply an absolute frequency trim. @return 0 on success. */
static int set_freq(double freq_ppb)
{
    struct timex tx;

    memset(&tx, 0, sizeof(tx));
    tx.modes = ADJ_FREQUENCY;
    /* The servo clamps freq_ppb to +-SERVO_MAX_FREQ_PPB, so the scaled value
     * (5e5 * 65.536 ~= 3.3e7) always fits in a 32-bit long. The clamp is there
     * against kernel EINVAL and integrator divergence, not against that overflow:
     * with Kp = 0.1 an unclamped output reaches 1e6 ppb, ~6.5e7 scaled, no UB. */
    tx.freq = (long)(freq_ppb * PPB_TO_TIMEX_FREQ);

    if (ptp_clock_adjtime(CLOCK_REALTIME, &tx) < 0) {
        perror("clock_adjtime FREQ failed");
        return -1;
    }
    printf("FREQ ADJ: %.2f ppb\n", freq_ppb);
    return 0;
}

/** @brief Act on one servo sample: step the phase or steer the frequency. */
static void adjust_clock(int64_t offset_ns, double freq_ppb, servo_state_t state)
{
    struct timespec ts;
    int64_t abs_ns;

    switch (state) {
    case SERVO_JUMP:
        /* linuxptp clears the trim before stepping (clock.c:2056 then :2059):
         * the rate we were steering at says nothing once the clock is moved by
         * force. freq_ppb is 0.0 on a jump. */
        if (set_freq(freq_ppb) < 0) {
            return;
        }

        clock_gettime(CLOCK_REALTIME, &ts);
        /* offset_ns is bounded by SERVO_MAX_OFFSET_NS, so nothing below can
         * overflow; negating an unchecked value is UB at INT64_MIN. */
        abs_ns = (offset_ns < 0) ? -offset_ns : offset_ns;
        if (offset_ns < 0) {
            /* Behind the master: move the clock forward. */
            ts.tv_sec  += (time_t)(abs_ns / NS_PER_SEC);
            ts.tv_nsec += (long)(abs_ns % NS_PER_SEC);
            if (ts.tv_nsec >= NS_PER_SEC) {
                ts.tv_sec++;
                ts.tv_nsec -= NS_PER_SEC;
            }
        } else {
            /* Ahead of the master: move the clock backward. */
            ts.tv_sec  -= (time_t)(abs_ns / NS_PER_SEC);
            ts.tv_nsec -= (long)(abs_ns % NS_PER_SEC);
            if (ts.tv_nsec < 0) {
                ts.tv_sec--;
                ts.tv_nsec += NS_PER_SEC;
            }
        }

        if (clock_settime(CLOCK_REALTIME, &ts) < 0) {
            perror("clock_settime failed");
            printf("Failed to adjust clock by %" PRId64 " ns\n", offset_ns);
        } else {
            printf("CLOCK JUMP: %" PRId64 " ns (new time: %ld.%09ld)\n",
                   offset_ns, (long)ts.tv_sec, ts.tv_nsec);
        }
        break;

    case SERVO_LOCKED:
    case SERVO_LOCKED_STABLE:
        (void)set_freq(freq_ppb);
        break;

    case SERVO_UNLOCKED:
    default:
        /* Nothing to act on; the trim already in force is kept. */
        break;
    }
}
```

## 双Socket实现

从时钟需要监听两个PTP端口：

```c
/* ptp_slave.c:527-610 —— 以下为改写版（节选），真实源码见该区间 */
int main(int argc, char *argv[])
{
    int event_fd, general_fd, max_fd;

    /* 创建两个socket：一个监听319，一个监听320 */
    event_fd = create_socket(argv[1], PTP_EVENT_PORT);      /* 319  :551 */
    general_fd = create_socket(argv[1], PTP_GENERAL_PORT);  /* 320  :557 */
    max_fd = (event_fd > general_fd) ? event_fd : general_fd;   /* :573 */

    /* 使用select监听两个socket */
    while (g_running) {                                     /* :580 */
        fd_set readfds;

        FD_ZERO(&readfds);
        FD_SET(event_fd, &readfds);
        FD_SET(general_fd, &readfds);

        select(max_fd + 1, &readfds, NULL, NULL, &timeout);  /* :600 */

        /* 处理event端口（319）的消息：Sync 和 Delay_Resp */
        if (FD_ISSET(event_fd, &readfds)) {
            handle_datagram(event_fd, recv_buf, 1);          /* :604 */
        }

        /* 处理general端口（320）的消息：Follow_Up 和 Announce */
        if (FD_ISSET(general_fd, &readfds)) {
            handle_datagram(general_fd, recv_buf, 0);        /* :607 */
        }
    }
}
```

**为什么需要双Socket**：

根据IEEE 1588标准：
- **Event端口（319）**：Sync, Delay_Req（需要时间戳）
- **General端口（320）**：Follow_Up, Announce, Delay_Resp（不需要时间戳）

注意：ptp-lite 的实现把 Delay_Resp 也放在 319 端口接收；标准里 Delay_Resp 属于 320 端口的 general 消息。

使用双Socket确保能收到所有PTP消息。

/** @brief Follow_Up received: t1, but only for the newest Sync. */
static void handle_follow_up(const ptp_follow_up_msg_t *msg)
{
    uint16_t seq = be16toh(msg->header.sequence_id);

    /* Sequence pairing: a Follow_Up is only usable with the Sync carrying the
     * same sequenceId; a late, duplicated or forged one would otherwise replace
     * t1 with a timestamp unrelated to the t2 we measured. */
    if (seq != last_sync_seq || t2_valid == 0) {
        drop_msg("Follow_Up does not match the newest Sync");
        return;
    }
    if (ptp_to_timespec(&msg->precise_origin_timestamp, &t1) != 0) {
        drop_msg("Follow_Up preciseOriginTimestamp out of range");
        return;
    }
    t1_valid = 1;
    printf("Follow_Up seq=%u: t1=%ld.%09ld t2=%ld.%09ld\n", seq,
           (long)t1.tv_sec, t1.tv_nsec, (long)t2.tv_sec, t2.tv_nsec);
}

```c
/* ptp_slave.c:389-455（逐字） */
/** @brief Delay_Resp received: t4, then the E2E math and the servo update. */
static void handle_delay_resp(const ptp_delay_resp_msg_t *msg)
{
    struct timespec t4;
    servo_state_t state;
    int64_t dt_sync, dt_req, delay, offset;
    double freq;

    /* IEEE 1588-2019 9.5.7: a Delay_Resp is associated with our Delay_Req only
     * if requestingPortIdentity and the echoed sequenceId both match - 9.5.7
     * calls the latter requestingSequenceId. linuxptp: port.c:2348, :2354-2358. */
    if (be16toh(msg->header.sequence_id) != outstanding_delay_req_seq) {
        drop_msg("Delay_Resp sequenceId is not the one we sent");
        return;
    }
    /* From here on the round is finished whatever happens: every exit below
     * invalidates t1/t2/t3, so a stale timestamp can never be paired with a
     * fresh one from the next round. */
    if (memcmp(&msg->requesting_port_identity, &slave_port_id,
               sizeof(ptp_port_identity_t)) != 0) {
        drop_msg("Delay_Resp is not addressed to this port");
        clear_round();
        return;
    }
    if (t1_valid == 0 || t2_valid == 0 || t3_valid == 0) {
        drop_msg("Delay_Resp without a complete Sync/Delay_Req round");
        clear_round();
        return;
    }
    if (ptp_to_timespec(&msg->receive_timestamp, &t4) != 0) {
        drop_msg("Delay_Resp receiveTimestamp out of range");
        clear_round();
        return;
    }

    /* Both tv_sec operands are widened to int64_t before the difference is taken:
     * on an ILP32 target the subtraction would otherwise run in a 32-bit time_t,
     * where (time_t)sec has already wrapped negative. The decoded seconds are
     * bounded by PTP_MAX_VALID_SECONDS, so |dsec| < 2^32 and every product below
     * stays inside int64_t (2^32 * 1e9 ~= 4.29e18 < INT64_MAX ~= 9.22e18). */
    dt_sync = ((int64_t)t2.tv_sec - (int64_t)t1.tv_sec) * NS_PER_SEC +
              (int64_t)(t2.tv_nsec - t1.tv_nsec);
    dt_req  = ((int64_t)t4.tv_sec - (int64_t)t3.tv_sec) * NS_PER_SEC +
              (int64_t)(t4.tv_nsec - t3.tv_nsec);
    delay   = (dt_sync + dt_req) / 2;
    offset  = dt_sync - delay;

    if (delay < 0 || offset > SERVO_MAX_OFFSET_NS ||
        offset < -SERVO_MAX_OFFSET_NS) {
        /* A negative path delay, or an offset beyond SERVO_MAX_OFFSET_NS, is
         * not a very large offset: it is a measurement that straddled a clock
         * adjustment, a stale or hostile timestamp pair. Reject it rather than
         * set the system time to an arbitrary value. */
        drop_msg("measured delay/offset out of range");
        clear_round();
        return;
    }

    printf("Delay_Resp: t3=%ld.%09ld t4=%ld.%09ld delay=%" PRId64
           " ns offset=%" PRId64 " ns\n",
           (long)t3.tv_sec, t3.tv_nsec, (long)t4.tv_sec, t4.tv_nsec,
           delay, offset);

    freq = pi_servo_sample(&servo, offset, &state);
    adjust_clock(offset, freq, state);
    clear_round();     /* consumed - never reused, least of all after a jump */
}
```

## 下集预告

本章实现了完整的PTP从时钟：

**关键特性**：
- ✅ 双 Socket 监听 319/320，三类通用报文由主钟的 320 发出、Sync 置 twoStepFlag、单播的 Delay_Resp 置 `unicastFlag`
- ✅ E2E 延迟测量，且每一轮测量**要么被完整消费、要么被作废**，不会跨着一次改钟复用时间戳
