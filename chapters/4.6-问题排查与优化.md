# 4.6 问题排查与优化

## 常见问题

### 问题1：收不到消息

```bash
# 检查：防火墙
sudo iptables -A INPUT -p udp --dport 319 -j ACCEPT
sudo iptables -A INPUT -p udp --dport 320 -j ACCEPT

# 检查：组播路由
ip maddr show eth0
# 应该看到组播地址
```

两个端口都要放行：319 是 event（Sync、Delay_Req），320 是 general（Follow_Up、Announce、Delay_Resp）。只开 319 的话，从钟会一直停在 `Received Sync seq=N` 而永远等不到 `Follow_Up`，症状是每隔一秒一条 `DROP: Delay_Resp without a complete Sync/Delay_Req round (total N)`（`ptp_slave.c:413-416`）。

### 问题2：时间不准

```bash
# 检查：系统时钟
timedatectl status
# 关闭NTP：timedatectl set-ntp false
```

`systemd-timesyncd`／`chronyd`／`ntpd` 和 ptp_lite 都在改同一个 `CLOCK_REALTIME`：前者走各自的 slew／step 路径，后者用 `clock_settime`＋`ADJ_FREQUENCY`（`ptp_slave.c:305`、`:260`）。两个互不知情的环路互相拉扯，表现是 offset 长期在一个非零值附近徘徊、`FREQ ADJ` 的符号反复翻转。查一下有没有进程在抢：

```bash
ps -eo pid,cmd | grep -E 'chronyd|systemd-timesyncd|ntpd' | grep -v grep
```

### 问题3：偏差大

```text
# 原因：软件时间戳精度低
# 解决：使用硬件时间戳（需要网卡支持）
```
