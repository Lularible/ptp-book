# Part 3: Inside the Source: LinuxPTP, the De Facto Implementation

## 3.1 Entering the Open-Source PTP World: A Panorama of the LinuxPTP Project

### What LinuxPTP is

LinuxPTP is the de facto open-source implementation of IEEE 1588 for Linux. It is what most carrier-grade and industrial PTP deployments on Linux actually run.

- Homepage: https://linuxptp.org/ (source mirror on SourceForge)
- License: GNU GPL v2
- Version covered in this book: v4.x
- Implementation language: C

It ships three main tools:

| Tool | Job |
|:---|:---|
| `ptp4l` | the PTP daemon: clocks, ports, BMCA, servo |
| `phc2sys` | synchronizes the system clock (CLOCK_REALTIME) to a PHC |
| `pmc` | the PTP management client |

Plus `phc_ctl` for ad-hoc PHC reads and writes.

### The source layout (a quick tour)

```
ptp4l.c            main(), argument parsing, event loop
clock.c            the clock instance, BMCA orchestration, servo calls
port.c             ports, the receiver/timer paths, hop-by-hop processing
fsm.c              the port state machine (ptp_fsm / ptp_slave_fsm)
bmc.c              the dataset comparison and state decision (BMCA)
servo.c, pi.c      the servo framework and the PI controller
config.c           configuration file and defaults
msg.c              message (de)serialization
tlv.c              TLV (de)serialization
transport*.c,udp.c,raw.c,uds.c   transports: UDP/IPv4, UDP/IPv6, raw Ethernet, UDS
sk.c               socket helpers: timestamping, device ioctls
phc.c, clockadj.c  PHC access and clock adjustment helpers
phc2sys.c          the phc2sys tool
pmc.c, pmc_common.c the pmc tool
```

Line counts (v4.4) total roughly 38,500 lines of C + headers, the core state machine, BMCA, and servo logic is tiny; the surface area (transports, ioctls, corner cases) dominates.

### ptp4l's startup, in one glance

1. Parse options (`-i <iface>`, `-f <config>`, `-s`/`-S`/`-H` timestamping, `-l` log level, ...).
2. Read the configuration file (e.g., `/etc/linuxptp/ptp4l.conf`).
3. Decide the clock type: one interface → ordinary clock; more than one → boundary clock.
4. Create the clock, one port per interface.
5. Run the main loop: poll sockets and timers, dispatch events, feed the servo.

The transport/`getopt` options in `ptp4l.c` include `-A` (auto delay mechanism), `-E`/`-P` (E2E/P2P), `-2` (raw Ethernet), `-4`/`-6` (IPv4/IPv6), `-H`/`-S` (hardware/software timestamping).

### The clock types

```c
enum clock_type {
    CLOCK_TYPE_ORDINARY   = 0x8000,
    CLOCK_TYPE_BOUNDARY   = 0x4000,
    CLOCK_TYPE_P2P        = 0x2000,
    CLOCK_TYPE_E2E        = 0x1000,
    CLOCK_TYPE_MANAGEMENT = 0x0800,
};
```

### The servo states

```c
enum servo_state {
    SERVO_UNLOCKED,
    SERVO_JUMP,
    SERVO_LOCKED,
    SERVO_LOCKED_STABLE,
};
```

The servo starts UNLOCKED; when the offset is huge it may JUMP (step); once the offset is small the state becomes LOCKED, and with sustained stability, LOCKED_STABLE.

### Config essentials

A config file (or `-f`) sets the same fields the protocol discusses:

```ini
[global]
domainNumber 0
twoStepFlag 1
slaveOnly 0
clock_type OC          # OC / BC / P2P / E2E
time_stamping hardware

[eth0]
logAnnounceInterval 1
logSyncInterval 0
logMinDelayReqInterval 0
announceReceiptTimeout 3
```

PI servo tuning is configurable too:

```ini
pi_proportional_const 0.0
pi_integral_const 0.0
pi_proportional_scale 0.7
pi_integral_scale 0.3
```

### Building

```bash
make            # userspace tools
make prefix=/opt/ptp install
```

or for a custom kernel tree, `make KBUILD_OUTPUT=/path/to/kernel/build`.

### Running

```bash
# ordinary clock, one interface, log to stdout
sudo ptp4l -i eth0 -m

# boundary clock
sudo ptp4l -i eth0 -i eth1 -m

# master
sudo ptp4l -i eth0 -m -s

# software timestamping (no PHC required)
sudo ptp4l -i eth0 -m -S
```

Check timestamping support first with `ethtool -T eth0`.
