# 3.10 Management Protocol and pmc: PTP's Remote Control

## Why a management protocol?

A running PTP network needs management:

```text
Common management needs:

1. Status monitoring
- What is the current clock offset?
- Who is the master clock?
- How is synchronization doing?

2. Parameter configuration
- Change the priority
- Adjust the send interval
- Set the domain number

3. Fault diagnosis
- Why is it not synchronized?
- Message statistics
- Error counts

4. Operations
- Switch the master clock
- Restart a port
- Update the configuration

How do you do all that?

IEEE 1588 defines a management protocol:
- Management messages
- GET: read parameters
- SET: set parameters
- COMMAND: execute commands
```

## Management protocol basics

### Management message structure

```c
/* msg.h:171-179 */

struct management_msg {
    struct ptp_header   hdr;                /* common header */
    struct PortIdentity targetPortIdentity; /* target port (10 bytes) */
    UInteger8           startingBoundaryHops;
    UInteger8           boundaryHops;
    uint8_t             flags;              /* high 4 bits reserved | low 4 bits actionField */
    uint8_t             reserved;
    uint8_t             suffix[0];          /* TLVs follow */
} PACKED;
```

**Key fields**:

```text
targetPortIdentity:
- Sets the target of the management message
- Can be a specific port
- Can be a broadcast (all 0xFF)

sequenceId:
- Pairs a request with its response
- Increments the sequence number
- Used to match the response

boundaryHops:
- Management messages can cross boundary clocks
- Decremented by one at each boundary clock
- No longer forwarded at 0 (still processed locally), which prevents infinite propagation

actionField:
- GET: request a read
- SET: request a set
- RESPONSE: response
- COMMAND: command
- ACKNOWLEDGE: acknowledgement
```

### Management action types

```c
/* tlv.h:58-64 */

enum management_action {
    GET,         /* read request */
    SET,         /* set request */
    RESPONSE,    /* response */
    COMMAND,     /* command */
    ACKNOWLEDGE, /* acknowledgement */
};
```

**Action flows**:

```text
GET operation:

client → server: GET DEFAULT_DATA_SET
server → client: RESPONSE DEFAULT_DATA_SET (data)

SET operation:

client → server: SET PRIORITY1 (value=128)
server → client: RESPONSE PRIORITY1 (value=128)
```

### What boundary_hops does

```text
How far management messages reach:

boundary_hops = 1:
- Crosses 1 boundary clock
- Reaches the adjacent segment

boundary_hops = 2:
- Can pass through 2 boundary clocks
- Reaches a more distant segment

boundary_hops = 255:
- Almost unlimited propagation
- Can reach the entire PTP domain

Boundary clock handling:
1. Receive the management message
2. If boundary_hops is not 0, decrement it, then forward
   (the hop that brings it to 0 still forwards)
3. The next hop sees boundary_hops = 0: it processes the message but does not forward

Loop prevention:
- Limits the propagation range
- Avoids broadcast storms
```

## The pmc tool

### pmc in brief

```text
pmc = PTP Management Client

What it does:
- A client tool for managing PTP devices
- Talks to ptp4l over the management protocol
- Reads and sets parameters
- Diagnoses problems

Features:
- Command-line interface
- Interactive or batch mode
- idtab has 60 entries: 37 have handlers (60 minus 23, including the no-data NULL_MANAGEMENT), 23 marked not_supported
- Supports LinuxPTP extensions

Typical use:
pmc -u -b 0 "GET CURRENT_DATA_SET"
```

### pmc command-line options

The options `pmc -h` (`pmc.c:684-706`) prints are below; the notes are the book's:

```text
usage: pmc [options] [commands]

Network Transport:
-2          IEEE 802.3 (raw Ethernet)
-4          UDP IPv4 (default)
-6          UDP IPv6
-u          UDS local (Unix-domain socket)

Other Options:
-b [num]    boundary hops, default 1
-d [num]    domain number, default 0
-f [file]   read configuration from a file
-h          print this help and exit
-i [dev]    interface device, default eth0 or /var/run/pmc.$pid (UDS)
-s [path]   UDS server address, default /var/run/ptp4l
-t [hex]    transport specific field, default 0x0
-v          print the software version and exit
-z          send zero-length TLVs
```

**Choosing a transport**:

```bash
# UDP/IPv4 (most common)
pmc -4 -i eth0 "GET CURRENT_DATA_SET"

# UDP/IPv6
pmc -6 -i eth0 "GET CURRENT_DATA_SET"

# Raw Ethernet
pmc -2 -i eth0 "GET CURRENT_DATA_SET"

# UDS (local management)
pmc -u -s /var/run/ptp4l "GET CURRENT_DATA_SET"
```

**Setting boundary_hops**:

```bash
# Manage only the local port
pmc -u -b 0 "GET TIME_STATUS_NP"

# Manage neighboring devices
pmc -u -b 1 "GET CURRENT_DATA_SET"

# Manage the whole domain
pmc -u -b 255 "GET DEFAULT_DATA_SET"
```

### Command parsing

```c
/* pmc_common.c:419-452 */

static int parse_action(char *s)
{
    int len = strlen(s);
    if (0 == strncasecmp(s, "GET", len))
        return GET;
    else if (0 == strncasecmp(s, "SET", len))
        return SET;
    else if (0 == strncasecmp(s, "CMD", len))
        return COMMAND;
    else if (0 == strncasecmp(s, "COMMAND", len))
        return COMMAND;
    return BAD_ACTION;
}

static int parse_id(char *s)
{
    int i, index = BAD_ID, len = strlen(s);
    
    /* check for an exact match */
    for (i = 0; i < ARRAY_SIZE(idtab); i++) {
        if (strcasecmp(s, idtab[i].name) == 0) {
            return i;
        }
    }
    
    /* check for a prefix match */
    for (i = 0; i < ARRAY_SIZE(idtab); i++) {
        if (0 == strncasecmp(s, idtab[i].name, len)) {
            if (index == BAD_ID)
                index = i;
            else
                return AMBIGUOUS_ID;    /* ambiguous */
        }
    }
    return index;
}
```

**Parsing logic**:

```text
pmc command format: [ACTION] ID [parameters]

Examples:
GET CURRENT_DATA_SET
SET PRIORITY1 128
TARGET *

Parsing steps:
1. Extract the ACTION (optional, defaults to GET)
2. Extract the ID (may be abbreviated)
3. Validate the ID
4. Extract parameters (if any)
5. Build the management message
6. Send it and wait for the response
```

### Handling GET

```c
/* pmc_common.c:163-169 */

static void do_get_action(struct pmc *pmc, int action, int index, char *str)
{
    if (action == GET)
        pmc_send_get_action(pmc, idtab[index].code);
    else
        fprintf(stderr, "%s only allows GET\n", idtab[index].name);
}
```

**GET flow**:

```text
1. User enters: GET CURRENT_DATA_SET
2. Parse: action=GET, id=CURRENT_DATA_SET
3. Call: pmc_send_get_action(pmc, MID_CURRENT_DATA_SET)
4. Build the management message:
   - actionField = GET
   - managementId = MID_CURRENT_DATA_SET
   - no data field
5. Send the message
6. Wait for the response
7. Display the result
```

### Handling SET

```c
/* pmc_common.c:171-404 (simplified) */

static void do_set_action(struct pmc *pmc, int action, int index, char *str)
{
    switch (action) {
    case GET:
        pmc_send_get_action(pmc, code);
        return;
    case SET:
        break;
    default:
        fprintf(stderr, "%s only allows GET or SET\n", idtab[index].name);
        return;
    }

    switch (code) {
    case MID_PRIORITY1:
    case MID_PRIORITY2:
        cnt = sscanf(str, " %*s %*s %hhu", &mtd.val);
        if (cnt != 1) {
            fprintf(stderr, "%s SET needs 1 value\n", idtab[index].name);
            break;
        }
        pmc_send_set_action(pmc, code, &mtd, sizeof(mtd));
        break;
    }
}
```

### Printing responses

```c
/* pmc.c:159-682 (simplified) */

static void pmc_show(struct ptp_message *msg, FILE *fp)
{
    struct management_tlv *mgt;
    struct tlv_extra *extra;
    struct TLV *tlv;

    /* get the TLV */
    extra = TAILQ_FIRST(&msg->tlv_list);
    tlv = (struct TLV *) msg->management.suffix;
    mgt = (struct management_tlv *) msg->management.suffix;

    /* display according to the ID */
    switch (mgt->id) {
    case MID_CURRENT_DATA_SET:
        cds = (struct currentDS *) mgt->data;
        fprintf(fp, "CURRENT_DATA_SET "
            IFMT "stepsRemoved     %hd"
            IFMT "offsetFromMaster %.1f"
            IFMT "meanPathDelay    %.1f",
            cds->stepsRemoved, 
            cds->offsetFromMaster / 65536.0,
            cds->meanPathDelay / 65536.0);
        break;

    case MID_TIME_STATUS_NP:
        tsn = (struct time_status_np *) mgt->data;
        fprintf(fp, "TIME_STATUS_NP "
            IFMT "master_offset              %" PRId64
            IFMT "ingress_time               %" PRId64
            IFMT "gmPresent                  %s"
            IFMT "gmIdentity                 %s",
            tsn->master_offset,
            tsn->ingress_time,
            tsn->gmPresent ? "true" : "false",
            cid2str(&tsn->gmIdentity));
        break;
    }
}
```

## Practical scenarios

### Scenario 1: Diagnosing a sync problem

```bash
# Check the current sync state
pmc -u "GET CURRENT_DATA_SET"

# Output:
# stepsRemoved     5
# offsetFromMaster -32768.0
# meanPathDelay    16384.0

# Analysis:
# stepsRemoved=5: 5 hops from the master clock
# offsetFromMaster=-32768 ns ≈ -32 µs of offset
# meanPathDelay=16384 ns ≈ 16 µs of path delay

# Look at the master clock information
pmc -u "GET PARENT_DATA_SET"

# Check detailed status
pmc -u "GET TIME_STATUS_NP"

# Output:
# master_offset              -32768
# gmPresent                  true
# gmIdentity                 aabbcc.fffe.ddeeff
```

### Scenario 2: Switching the master clock

```bash
# Priority of the current master clock
pmc -u "GET DEFAULT_DATA_SET"

# Output:
# priority1               128
# priority2               128

# Lower the current master's priority
pmc -u "SET PRIORITY1 200"

# A new master takes over (if another clock has a higher priority)

# Or raise the priority to become the master
pmc -u "SET PRIORITY1 100"
```

### Scenario 3: Monitoring port statistics

```bash
# Check port statistics
pmc -u "GET PORT_STATS_NP"

# Output:
# rx_Sync                   12345
```

## How pmc talks to ptp4l

### The UDS channel

```bash
# ptp4l creates the UDS interface at startup
ptp4l -i eth0 -m -S

# UDS paths it creates:
# /var/run/ptp4l       (read-write)
# /var/run/ptp4lro     (read-only)

# pmc connects over UDS
pmc -u -s /var/run/ptp4l "GET CURRENT_DATA_SET"
```

**Why UDS**:

```text
UDS (Unix Domain Socket) features:

1. Local communication
- No network involved
- Low latency
- High throughput

2. Secure
- File-system permission control
- Non-root users can use the read-only interface

3. Simple
- No IP configuration
- No port configuration

Where it fits:
- Local management
- Monitoring scripts
- Automated operations
```

### The network channel

```bash
# Manage a remote device over UDP
pmc -4 -i eth0 -b 1 "GET PORT_DATA_SET"

# Notes:
# - boundary_hops sets the management range
# - the network must be reachable
# - a firewall may block it
```

## Advanced usage

### Scripted monitoring

```bash
#!/bin/bash
# monitor.sh - PTP monitoring script

while true; do
    echo "=== $(date) ==="
    
    # Get the current status
    pmc -u "GET TIME_STATUS_NP" | grep -E "master_offset|gmIdentity"
    
    # Check whether the offset is too large
    offset=$(pmc -u "GET TIME_STATUS_NP" | grep master_offset | awk '{print $2}')
    
    if [ "$offset" -gt 1000000 ]; then
        echo "ALERT: Large offset detected: $offset ns"
    fi
    
    sleep 10
done
```

### Bulk configuration

```bash
#!/bin/bash
# config.sh - bulk configuration script

# Set the priorities
pmc -u "SET PRIORITY1 128"
pmc -u "SET PRIORITY2 128"
```
