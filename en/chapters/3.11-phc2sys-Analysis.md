# 3.11 phc2sys Analysis: The Bridge Between the PHC and the System Clock

## Why you need phc2sys

PTP synchronization has a key problem:

```text
PTP synchronizes the PHC (PTP Hardware Clock):
- ptp4l operates on the PHC
- timestamps come from the PHC
- the PHC is what gets adjusted

But applications use the system clock (CLOCK_REALTIME):
- gettimeofday() reads the system clock
- the system clock ≠ PHC
- the time an application sees may be wrong

The problem:
How do applications get accurate time?

The answer:
phc2sys!
```

### ptp4l vs phc2sys

```text
What ptp4l does:
- synchronizes the PHC to the network master clock
- handles the PTP protocol
- adjusts PHC frequency and phase

What phc2sys does:
- synchronizes the system clock to the PHC
- or synchronizes the PHC to the system clock
- or synchronizes one PHC to another

Typical deployment:
network master clock → ptp4l → PHC → phc2sys → system clock → applications
```

## How phc2sys works

### Clock hierarchy

```text
Clock hierarchy:

1. Network master clock (Grandmaster)
   - GPS time source
   - atomic clock
   - the highest precision

2. PHC (PTP Hardware Clock)
   - NIC hardware clock
   - nanosecond precision
   - ptp4l synchronizes it to the network master clock

3. System clock (CLOCK_REALTIME)
   - Linux kernel clock
   - the clock applications access
   - phc2sys synchronizes it to the PHC

Synchronization chain:
Grandmaster → PHC → System Clock
```

### Synchronization method

```c
/* phc2sys.c:576-647 (excerpt) */

static void update_clock(struct domain *domain, struct clock *clock,
                         int64_t offset, uint64_t ts, int64_t delay)
{
    enum servo_state state = SERVO_UNLOCKED;
    double ppb = 0.0;

    /* create the servo */
    if (!clock->servo) {
        clock->servo = servo_add(domain, clock);
        if (!clock->servo)
            return;
    }

    /* handle leap seconds */
    if (clock_handle_leap(domain, clock, offset, ts))
        return;

    /* apply the offset adjustment */
    offset += get_sync_offset(domain, clock);

    /* if not in free-running mode, adjust the clock */
    if (!domain->free_running) {
        /* sanity check */
        if (clock->sanity_check && clockcheck_sample(clock->sanity_check, ts))
            servo_reset(clock->servo);

        /* servo sample */
        ppb = servo_sample(clock->servo, offset, ts, 1.0, &state);
        clock->servo_state = state;

        /* adjust the clock according to servo state */
        switch (state) {
        case SERVO_UNLOCKED:
            break;
        case SERVO_JUMP:
            clockadj_step(clock->clkid, -offset);
            /* there's no break here: the real code has a Fall through comment
               (phc2sys.c:611); after the step it still has to set the frequency */
        case SERVO_LOCKED:
        case SERVO_LOCKED_STABLE:
            clockadj_set_freq(clock->clkid, -ppb);
            break;
        }
    }
}
```

**The synchronization loop**:

```text
phc2sys main loop:

1. Read the source clock time (PHC or system clock)
2. Read the target clock time
3. Compute the difference: offset = target time - source time
4. Call the servo to compute the adjustment
5. Adjust the target clock according to servo state:
   - SERVO_JUMP: step the clock (large offset); after the step it falls through and adjusts frequency too
   - SERVO_LOCKED: frequency adjustment (small offset)
   - SERVO_LOCKED_STABLE: stable synchronization

Adjustment methods:
- Clock step: change the time immediately (may affect applications)
- Frequency adjustment: gradual adjustment (smooth, no jumps)
```

## The phc2sys command line

### Basic usage

```bash
# Synchronize the system clock to the PHC
phc2sys -s /dev/ptp0 -c CLOCK_REALTIME -w

# Option notes:
# -s /dev/ptp0: source clock (PHC)
# -c CLOCK_REALTIME: target clock (system clock)
# -w: wait for ptp4l to synchronize
```

### Common options

```text
# Source and target
-s [dev|name]  source clock device (interface name or PHC device)
-c [dev|name]  target clock device (e.g. CLOCK_REALTIME)
-d [dev]       PPS source device

# Synchronization mode
-a             automatic configuration (listen to ptp4l and pick the source clock)
-r             synchronize the system (realtime) clock; repeat -r to also serve as a time source
-w             wait for ptp4l to synchronize

# Servo parameters
-E [pi|linreg] choose the servo algorithm (default pi)
-P [kp]        proportional constant of the PI controller (default 0.7)
-I [ki]        integral constant of the PI controller (default 0.3)
-S [step]      steady-state step threshold (0.0 by default = disabled; a start-up step still occurs above the first-step threshold, 20 µs by default, unless -F 0 disables it)
-F [step]      step threshold at startup only (default 0.00002)

# Other
-O [offset]    target-source time offset (seconds, UTC/TAI)
-R [rate]      target clock update rate (Hz, default 1.0)
-u [num]       how many samples per statistics summary (default 0 = no summary, print each one)
-n [num]       domain number, up to 16 times together with -z (default 0)
-z [path]      ptp4l UDS address, up to 16 times in automatic mode
-l [num]       log level (default 6)
-m             print to stdout
```

### Typical scenarios

```bash
# Scenario 1: PTP slave clock
# ptp4l synchronizes the PHC to the network master clock
# phc2sys synchronizes the system clock to the PHC
ptp4l -i eth0 -s -m &
phc2sys -s eth0 -c CLOCK_REALTIME -w -m

# Scenario 2: the PHC is fed by local GPS (ts2phc or similar); ptp4l doesn't run on this host
# with no ptp4l there's no -w to wait for, so you must supply -O yourself
phc2sys -s /dev/ptp0 -c CLOCK_REALTIME -O 37 -m

# Scenario 3: multiple NICs, synchronizing one PHC to another PHC
# the eth0 PHC is managed by ptp4l, so -w is required:
# without -w (and without -O) phc2sys exits immediately and reports
# "time offset must be specified using -w or -O" (phc2sys.c:1410-1413)
phc2sys -s eth0 -c eth1 -w -m
```

### Automatic configuration

```c
/* phc2sys.c:382-466 (excerpt/simplified) */

static int reconfigure_domain(struct domain *domain)
{
    struct clock *c, *src = NULL;
    int src_cnt = 0, dst_cnt = 0;

    /* walk all clocks */
    LIST_FOREACH(c, &domain->clocks, list) {
        if (c->clkid == CLOCK_REALTIME) {
            /* the system clock can always be a destination */
            LIST_INSERT_HEAD(&domain->dst_clocks, c, dst_list);
            domain->src_clock = c->dest_only ? NULL : c;
            return 0;
        }

        /* choose the source clock from the port state */
        switch (c->state) {
        case PS_SLAVE:
            src = c;
            src_cnt++;
            break;
        case PS_MASTER:
        case PS_PASSIVE:
            /* as destination clock */
            LIST_INSERT_HEAD(&domain->dst_clocks, c, dst_list);
            dst_cnt++;
            break;
        }
    }

    /* select the source clock */
    if (src_cnt == 1) {
        domain->src_clock = src;
        pr_info("selecting %s as domain source clock", src->device);
    }

    return 0;
}
```

**Automatic source selection**:

```text
phc2sys can pick the source clock automatically:

1. Listen for ptp4l port state notifications
2. When a port becomes SLAVE
3. Automatically select that PHC as the source clock
4. Synchronize the other clocks to that PHC

Configuration:
phc2sys -a (automatic mode)

Workflow:
- Port A: SLAVE state → PHC A as source
- Port B: MASTER state → PHC B as destination
- phc2sys synchronizes automatically: PHC A → PHC B
```

## Time offset handling

### UTC vs TAI

```text
PTP uses TAI time:
- International Atomic Time
- unaffected by leap seconds
- increments continuously

The system clock usually uses UTC:
- Coordinated Universal Time
- affected by leap seconds
- has jumps

Offset:
UTC = TAI - leap_seconds

Currently (2024): TAI - UTC = 37 seconds

phc2sys has to handle this offset:
- read the PHC (TAI)
- read the system clock (UTC)
- offset = PHC_time - (sys_time + 37)
```

### Sync offset configuration

```c
/* phc2sys.c:528-535 */

static int64_t get_sync_offset(struct domain *domain, struct clock *dst)
{
    int direction = domain->forced_sync_offset;

    if (!direction)
        direction = dst->is_utc - domain->src_clock->is_utc;
    
    return (int64_t)dst->sync_offset * NS_PER_SEC * direction;
}
```

**Configuration example** (the commands themselves appeared above; here we only cover where the 37 seconds come from):

```bash
# Form one: the one under "Basic usage", letting -w ask ptp4l
#   while -w waits for ptp4l to synchronize, it also keeps updating the offset
#   between sink and source from the currentUtcOffset it gets from ptp4l
#   (phc2sys.8:192-199, code entry point pmc_agent_query_utc_offset at
#   phc2sys.c:1534-1540)

# Form two: the one under "Typical scenarios · Scenario 2", hardcoding it yourself
#   once -O is given, settings.forced_sync_offset is set to -1 (phc2sys.c:1295-1299),
#   so the direction in get_sync_offset() takes the forced branch and no longer
#   looks at the difference in is_utc
```

## Statistics and monitoring

### Example output

```bash
$ phc2sys -s eth0 -c CLOCK_REALTIME -w -u 1 -m

phc2sys[1234.567]: selecting CLOCK_REALTIME for synchronization
phc2sys[1235.567]: CLOCK_REALTIME rms  100 max  150 freq -100 +/-  10
phc2sys[1236.567]: CLOCK_REALTIME rms   50 max   80 freq  -50 +/-   5
phc2sys[1237.567]: CLOCK_REALTIME rms   20 max   30 freq  -20 +/-   2
```

**Field descriptions**:

```text
CLOCK_REALTIME: target clock
rms  100: root mean square of the offset (nanoseconds)
max  150: maximum offset (nanoseconds)
freq -100: frequency adjustment (ppb)
+/-   10: frequency standard deviation
```

### Statistics implementation

```c
/* phc2sys.c:537-574 (excerpt) */

static void update_clock_stats(struct clock *clock, unsigned int max_count,
                               int64_t offset, double freq, int64_t delay)
{
    struct stats_result offset_stats, freq_stats, delay_stats;

    /* add the value */
    stats_add_value(clock->offset_stats, offset);
    stats_add_value(clock->freq_stats, freq);
    if (delay >= 0)
        stats_add_value(clock->delay_stats, delay);

    /* output when the maximum count is reached */
    if (stats_get_num_values(clock->offset_stats) < max_count)
        return;

    /* get the statistics results */
    stats_get_result(clock->offset_stats, &offset_stats);
    stats_get_result(clock->freq_stats, &freq_stats);

    /* print */
    pr_info("%s "
            "rms %4.0f max %4.0f "
            "freq %+6.0f +/- %3.0f",
            clock->device,
            offset_stats.rms, offset_stats.max_abs,
            freq_stats.mean, freq_stats.stddev);

    /* reset the statistics */
    stats_reset(clock->offset_stats);
    stats_reset(clock->freq_stats);
    stats_reset(clock->delay_stats);
}
```

## Hands-on examples

### Scenario 1: a complete PTP slave deployment

```bash
# Terminal 1: run ptp4l
sudo ptp4l -i eth0 -s -m -S

# Terminal 2: run phc2sys
sudo phc2sys -s eth0 -c CLOCK_REALTIME -w -m

# Terminal 3: monitor synchronization status
watch -n 1 'pmc -u "GET TIME_STATUS_NP"'

# Terminal 4: check the time
date          # system time (local timezone; UTC only if the timezone is UTC)
phc_ctl /dev/ptp0 -- get  # PHC time (TAI)
```

### Scenario 2: multi-domain synchronization

```bash
# the two ptp4l instances must each use their own interface, domain number and UDS address,
# otherwise they fight over the same /var/run/ptp4l
ptp4l -i eth0 -m --domainNumber 0 --uds_address /var/run/ptp4l0 &
ptp4l -i eth1 -m --domainNumber 1 --uds_address /var/run/ptp4l1 &

# on the phc2sys side, use -z to give each ptp4l its own UDS and -n the matching domain,
# up to 16 of each
phc2sys -a -r -z /var/run/ptp4l0 -n 0 -z /var/run/ptp4l1 -n 1 -m &

# pick the best source clock automatically
```

### Scenario 3: using a PPS signal

```bash
# Use a PPS signal to assist synchronization
phc2sys -s /dev/ptp0 -c CLOCK_REALTIME -w -m \
    -d /dev/pps0

# PPS provides an accurate one-pulse-per-second signal
# improves synchronization precision
```

## Summary: the key points of phc2sys

**Core role**:
- connects the PHC and the system clock
- gives applications accurate time

**How it works**:
- reads the two clocks
- computes the difference
- the servo controls the adjustment

**Typical deployment**:
- ptp4l: network → PHC
- phc2sys: PHC → system clock

**Automatic configuration**:
- watches port states
- picks the source clock automatically
- multi-domain support

**UTC/TAI handling**:
- handles leap-second offsets automatically
- can be configured manually
