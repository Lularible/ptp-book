# 3.11 phc2sys: The Bridge Between the PHC and the System Clock

## What problem does phc2sys solve?

`ptp4l` disciplines the PTP Hardware Clock (the NIC's on-board PHC). But applications read `CLOCK_REALTIME`, a completely different clock, ticking independently.

`phc2sys` bridges them: it reads the offset between a source clock (usually a PHC) and one or more destination clocks (usually the system clock), and disciplines the destinations.

```
ptp4l --disciplines--> /dev/ptp0 (PHC)
                           |
                           |  phc2sys: measure + adjust
                           v
                    CLOCK_REALTIME (system clock)
                           ^
                     applications read this
```

The standard recipe:

```bash
sudo ptp4l -i eth0 -m -S &      # discipline the PHC (or software mode)
sudo phc2sys -s eth0 -c CLOCK_REALTIME -w -m
```

(`-s eth0` means "the PHC bound to interface eth0", `-c CLOCK_REALTIME` is the target, `-w` waits for ptp4l to be ready, `-m` prints to stdout.)

## The options

```
-s <dev|name>   source clock: a PHC device or interface name
-c <dev|name>   sink clock(s)
-d <dev>        PPS source device
-a              auto mode: follow ptp4l's port states
-r              sync the real-time (system) clock; repeat -r to allow serving it as a source
-w              wait for ptp4l
-O <secs>       sink−source offset (timescale offset)
-E <pi|linreg>  servo to use (default pi)
-P <kp>         PI proportional constant (default 0.7)
-I <ki>         PI integration constant (default 0.3)
-S <step>       step threshold in seconds (default disabled)
-F <secs>       first-step threshold (default 0.00002)
-R <rate>       update rate of the sink clock in Hz (default 1.0)
-l <num>        log level (0-7, default 6)
-m              print to stdout
-t <tag>        message tag added to log messages
-z <path>       UDS server address
-n <num>        domain number
```

Two useful facts:
- `-S` is the *step threshold*, not "use linreg": the servo choice is `-E pi|linreg`.
- `-l` is the *log level*, not the update interval; the update rate is `-R`.

### Manual pairs

```bash
# PHC -> system clock
sudo phc2sys -s eth0 -c CLOCK_REALTIME -w -m

# two NICs: eth0 is synced by ptp4l, eth1 follows eth0
sudo phc2sys -s eth0 -c eth1 -w -m

# with a PPS source assisting
sudo phc2sys -s eth0 -c CLOCK_REALTIME -w -m -d /dev/pps0
```

(`-d` / PPS requires kernel user-space PPS support and a configured pps device.)

### Auto mode

```bash
sudo phc2sys -a -r -m
```

In `-a` mode, phc2sys watches ptp4l's port states and automatically picks the source (`SLAVE` port) and sinks (`MASTER`/passive ports), so you don't have to enumerate them. Add `-r` so the *system clock* may also be disciplined (and, with a second `-r`, offered as a source for other nodes).

### get_sync_offset (phc2sys.c:528-535)

```c
static int64_t get_sync_offset(struct domain *domain, struct clock *dst)
{
    int direction = domain->forced_sync_offset;

    if (!direction)
        direction = dst->is_utc - domain->src_clock->is_utc;
    return (int64_t)dst->sync_offset * NS_PER_SEC * direction;
}
```

This is not a clock read. It returns the configured timescale offset (the `-O` seconds, held in `sync_offset`) scaled by a direction that depends on whether the source and sink clocks are in UTC. The raw offset measurement comes from `clock_gettime` elsewhere; `get_sync_offset` adds the TAI/UTC correction on top of it.

### update_clock (phc2sys.c:576-647)

The heartbeat of the tool:

```c
static void update_clock(struct domain *domain, struct clock *clock,
                         int64_t offset, uint64_t ts, int64_t delay)
{
    enum servo_state state = SERVO_UNLOCKED;
    double ppb = 0.0;

    if (!clock->servo) {
        clock->servo = servo_add(domain, clock);
        if (!clock->servo)
            return;
    }

    if (clock_handle_leap(domain, clock, offset, ts))
        return;

    offset += get_sync_offset(domain, clock);

    if (domain->free_running)
        goto report;

    if (clock->sanity_check && clockcheck_sample(clock->sanity_check, ts))
        servo_reset(clock->servo);

    ppb = servo_sample(clock->servo, offset, ts, 1.0, &state);
    clock->servo_state = state;

    switch (state) {
    case SERVO_UNLOCKED:
        break;
    case SERVO_JUMP:
        if (clockadj_step(clock->clkid, -offset))
            goto servo_unlock;
        /* fall through */
    case SERVO_LOCKED:
    case SERVO_LOCKED_STABLE:
        if (clockadj_set_freq(clock->clkid, -ppb))
            goto servo_unlock;
        break;
    }

report:
    update_clock_stats(clock, domain->stats_max_count, offset, ppb, delay);
    return;

servo_unlock:
    servo_reset(clock->servo);
    clock->servo_state = SERVO_UNLOCKED;
}
```

(Simplified: the real body also drives `clockcheck`, calls `sysclk_set_sync()` when the sink is `CLOCK_REALTIME`, and prints a line when no stats object exists.)

The sign conventions come from section 2.9: the *sink* correction subtracts `offset` on a JUMP, and applies `−ppb` on the LOCKED states.

### reconfigure_domain (phc2sys.c, lines 382-466)

In auto mode this is what enacts ptp4l's state transitions: it walks the domain's clocks, and the clock whose `port_state == PS_SLAVE` becomes `src_clock`; the CLOCK_REALTIME (or others) become sinks. (Abridged here, the real function also handles `has_rt_clock`, `agent_subscribed`, and duplicate checks.)

## Statistics and reporting

`update_clock_stats` maintains rms/max for the offset and mean/stddev for the frequency, printed like:

```
phc2sys[1235.567]: CLOCK_REALTIME rms  100 max  150 freq  -100 +/-  10
```

(Format: `rms %4.0f max %4.0f freq %+6.0f +/- %3.0f`.)

## PPS-assisted mode

With `-d /dev/pps0`, phc2sys can also consume a 1PPS signal to refine the timing, a common setup when the PHC and the PPS come from the same board.

## Summary

- `ptp4l` disciplines the PHC; `phc2sys` pushes it to the system clock.
- Trivial in theory (`offset = CLOCK_REALTIME − PHC`), but the details live in servo selection, step vs. slew, PPS, leap-second handling (TAI), and stats.
- `-a -r` auto mode follows ptp4l's states to pick source and sinks automatically.
