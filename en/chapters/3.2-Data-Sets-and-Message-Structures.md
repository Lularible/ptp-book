# 3.2 Data Sets and Message Structures: The Art of Encoding PTP Data

## The version byte (again, in code)

`ver` is `minorVersionPTP << 4 | versionPTP`. LinuxPTP defines:

```
PTP_MAJOR_VERSION = 2
PTP_MINOR_VERSION = 1
PTP_VERSION      = (PTP_MINOR_VERSION << 4) | PTP_MAJOR_VERSION   /* = 0x12 */
```

So a 1588-2019 message carries ver = 0x12, always encode it that way.

## Time values (tmv.h)

Timestamps are carried as a tiny wrapper to keep the algorithms readable:

```c
typedef struct {
    int64_t ns;   /* value in nanoseconds */
} tmv_t;
```

In v4.4 `tmv_t` is a struct wrapping a nanosecond int64, that forces all code through helpers (`tmv_add`, `tmv_sub`, ...) and leaves room to upgrade to a sub-nanosecond representation later. Conceptually it is just a 64-bit nanosecond integer.

## The BMCA comparison (bmc.c)

The dataset comparison orders masters per IEEE 1588:

```c
/* bmc.c, dscmp : lines 83-127 */

int dscmp(struct dataset *a, struct dataset *b)
{
    int diff;
    unsigned int A = a->priority1, B = b->priority1;

    if (a == b) return 0;
    /* comparing with a non-existing clock */
    if (a && !b) return A_BETTER;
    if (b && !a) return B_BETTER;

    diff = memcmp(&a->identity, &b->identity, sizeof(a->identity));
    if (!diff) return dscmp2(a, b);       /* same grandmaster */

    if (A < B) return A_BETTER;
    if (A > B) return B_BETTER;

    diff = memcmp(&a->quality, &b->quality, sizeof(a->quality));
    if (diff < 0) return A_BETTER;
    if (diff > 0) return B_BETTER;

    if (a->priority2 < b->priority2) return A_BETTER;
    if (a->priority2 > b->priority2) return B_BETTER;

    return memcmp(&a->identity, &b->identity, sizeof(a->identity)) < 0
           ? A_BETTER : B_BETTER;
}
```

The return values:

```c
#define A_BETTER_TOPO   2
#define A_BETTER        1
#define B_BETTER       -1
#define B_BETTER_TOPO  -2
```

`dscmp2` compares two datasets from the *same* grandmaster (stepsRemoved, then the topology-aware receiver/sender order). The book's later analysis (section 3.13) explains the full ordering.

## Byte order

Every multi-byte field is network order. LinuxPTP converts on send and on receive inside `msg.c` / `tlv.c`. The `Timestamp` struct itself is split so its 48-bit seconds field converts cleanly:

```c
struct Timestamp {
    UInteger48  seconds;      /* 6 bytes */
    UInteger32  nanoseconds;  /* 4 bytes */
};
```

## Summary

- Data sets and messages become PACKED C structs laid out byte-for-byte as on the wire.
- `ptp_header` is 34 bytes; Sync/Delay_Req/Follow_Up are 44; Delay_Resp/Pdelay_* are 54; Announce is 64.
- `ver = 0x12` for 1588-2019.
- The BMCA comparison (dscmp/dscmp2) and the tmv_t helpers are the two most-read pieces of the core.
