## Data set definitions

### defaultDS: the default data set

```c
/* ds.h:33-43 */

struct defaultDS {
    UInteger8            flags;          /* flags */
    UInteger8            reserved1;      /* reserved */
    UInteger16           numberPorts;    /* number of ports */
    UInteger8            priority1;      /* priority1 */
    struct ClockQuality  clockQuality;   /* clock quality */
    UInteger8            priority2;      /* priority2 */
    struct ClockIdentity clockIdentity;  /* clock identity */
    UInteger8            domainNumber;   /* domain number */
    UInteger8            reserved2;      /* reserved */
} PACKED;
```

**Compared with IEEE 1588**:

```text
The full defaultDS field list defined by IEEE 1588-2019:

1. twoStepFlag           → packed into bit 0 of the flags field
2. slaveOnly             → packed into bit 1 of the flags field
3. numberPorts           → direct match
4. priority1             → direct match
5. clockQuality          → direct match
   - clockClass
   - clockAccuracy
   - offsetScaledLogVariance
6. priority2             → direct match
7. domainNumber          → direct match
8. sdoId                 → not represented in the struct (handled another way)
9. clockIdentity         → direct match

LinuxPTP's design choice:
- pack twoStepFlag and slaveOnly into flags
- save memory
- the embedded-system approach to optimization
```

**The bit definitions in the flags field**:

```c
/* ds.h:30-31 */

#define DDS_TWO_STEP_FLAG (1<<0)  /* bit 0: twoStepFlag */
#define DDS_SLAVE_ONLY    (1<<1)  /* bit 1: slaveOnly */
```

**Example usage**:

```c
/* set twoStepFlag */
dds->flags |= DDS_TWO_STEP_FLAG;

/* check slaveOnly */
if (dds->flags & DDS_SLAVE_ONLY) {
    /* this is a slave-only clock */
}
```

### currentDS: the current data set

```c
/* ds.h:64-68 */

struct currentDS {
    UInteger16   stepsRemoved;       /* hops to the master clock */
    TimeInterval offsetFromMaster;   /* time offset from the master clock */
    TimeInterval meanPathDelay;      /* mean path delay */
} PACKED;
```

**Field by field**:

```text
stepsRemoved:
- how many boundary clocks the path from the master clock to this clock crosses
- starts at 0
- add 1 for each boundary clock
- used in BMCA decisions

offsetFromMaster:
- current time offset from the master clock (nanoseconds)
- computed by the servo
- positive means the local clock is ahead of the master

meanPathDelay:
- mean path delay to the master clock (nanoseconds)
- measured by E2E or P2P
- used to compute the total delay
```

### parentDS: the parent data set

```c
/* ds.h:70-80 */

struct parentDS {
    struct PortIdentity  parentPortIdentity;   /* parent port identity */
    UInteger8            parentStats;          /* parent clock statistics flags */
    UInteger8            reserved;             /* reserved */
    UInteger16           observedParentOffsetScaledLogVariance; /* observed variance */
    Integer32            observedParentClockPhaseChangeRate;   /* phase change rate */
    UInteger8            grandmasterPriority1; /* grandmaster priority1 */
    struct ClockQuality  grandmasterClockQuality; /* grandmaster quality */
    UInteger8            grandmasterPriority2; /* grandmaster priority2 */
    struct ClockIdentity grandmasterIdentity;  /* grandmaster identity */
} PACKED;
```

**What it does**:

```text
what parentDS does:

records "who my upstream clock is" and "who the network master clock is".

For example, this topology:
master clock (A) → BC(B) → BC(C) → slave clock (D)

Slave clock D's parentDS:
- parentPortIdentity = port identity of BC(C)
- grandmasterIdentity = identity of master clock (A)
- grandmasterPriority1/2 = priorities of master clock (A)

So the slave clock knows:
- its direct upstream is BC(C)
- the ultimate master clock is A
```

### portDS: the port data set

```c
/* ds.h:98-109 */

struct portDS {
    struct PortIdentity portIdentity;          /* port identity */
    Enumeration8        portState;             /* port state */
    Integer8            logMinDelayReqInterval;/* minimum Delay_Req interval */
    TimeInterval        peerMeanPathDelay;     /* P2P link delay */
    Integer8            logAnnounceInterval;   /* Announce interval */
    UInteger8           announceReceiptTimeout;/* Announce timeout */
    Integer8            logSyncInterval;       /* Sync interval */
    Enumeration8        delayMechanism;        /* delay mechanism */
    Integer8            logMinPdelayReqInterval;/* Pdelay_Req interval */
    UInteger8           versionNumber;         /* PTP version */
} PACKED;
```

**Field by field**:

```text
portIdentity:
- unique port identifier
- clockIdentity (8 bytes) + portNumber (2 bytes)

portState:
- current port state
- one of the enum port_state values

logMinDelayReqInterval:
- minimum send interval for Delay_Req (log2 seconds)
- for example: logMinDelayReqInterval=0 means a 1 s interval
-              logMinDelayReqInterval=1 means a 2 s interval

peerMeanPathDelay:
- link delay in P2P mode
- measured by Pdelay

delayMechanism:
- delay measurement mechanism
- E2E or P2P
```

## Comparing data sets

### dscmp: the data set comparison function

```c
/* bmc.c:83-127 */

int dscmp(struct dataset *a, struct dataset *b)
{
    int diff;

    /* special case: the same data set */
    if (a == b)
        return 0;
    
    /* special case: one of them is null */
    if (a && !b)
        return A_BETTER;
    if (b && !a)
        return B_BETTER;

    /* step 1: compare clockIdentity */
    diff = memcmp(&a->identity, &b->identity, sizeof(a->identity));
    if (!diff)
        return dscmp2(a, b);  /* same, go to the second-stage comparison */

    /* step 2: compare priority1 */
    if (a->priority1 < b->priority1)
        return A_BETTER;
    if (a->priority1 > b->priority1)
        return B_BETTER;

    /* step 3: compare clockClass */
    if (a->quality.clockClass < b->quality.clockClass)
        return A_BETTER;
    if (a->quality.clockClass > b->quality.clockClass)
        return B_BETTER;

    /* step 4: compare clockAccuracy */
    if (a->quality.clockAccuracy < b->quality.clockAccuracy)
        return A_BETTER;
    if (a->quality.clockAccuracy > b->quality.clockAccuracy)
        return B_BETTER;

    /* step 5: compare offsetScaledLogVariance */
    if (a->quality.offsetScaledLogVariance < b->quality.offsetScaledLogVariance)
        return A_BETTER;
    if (a->quality.offsetScaledLogVariance > b->quality.offsetScaledLogVariance)
        return B_BETTER;

    /* step 6: compare priority2 */
    if (a->priority2 < b->priority2)
        return A_BETTER;
    if (a->priority2 > b->priority2)
        return B_BETTER;

    /* step 7: compare clockIdentity */
    return diff < 0 ? A_BETTER : B_BETTER;
}
```

**Return values**:

```c
/* bmc.h:27-30 (source order) */

#define A_BETTER_TOPO  2   /* A is better (topology reason) */
#define A_BETTER       1   /* A is better */
#define B_BETTER      -1   /* B is better */
#define B_BETTER_TOPO -2   /* B is better (topology reason) */

/* next comes the comparison-algorithm enum, bmc.h:32-35 */
enum {
	DS_CMP_IEEE1588,     /* 0, default */
	DS_CMP_G8275,        /* 1, enables telecom_dscmp(), see 3.4 */
};
```

**The comparison flow**:

```text
dscmp comparison flow:

┌─────────────────────────────────────────────────┐
│ 1. clockIdentity same?                          │
│    yes → call dscmp2 (stage two)                │
│    no → continue                                │
├─────────────────────────────────────────────────┤
│ 2. priority1                                    │
│    A smaller → A_BETTER                         │
│    B smaller → B_BETTER                         │
│    same → continue                              │
├─────────────────────────────────────────────────┤
│ 3. clockClass                                   │
│    A smaller → A_BETTER                         │
│    B smaller → B_BETTER                         │
│    same → continue                              │
├─────────────────────────────────────────────────┤
│ 4. clockAccuracy                                │
│    A smaller → A_BETTER                         │
│    B smaller → B_BETTER                         │
│    same → continue                              │
├─────────────────────────────────────────────────┤
│ 5. offsetScaledLogVariance                      │
│    A smaller → A_BETTER                         │
│    B smaller → B_BETTER                         │
│    same → continue                              │
├─────────────────────────────────────────────────┤
│ 6. priority2                                    │
│    A smaller → A_BETTER                         │
│    B smaller → B_BETTER                         │
│    same → continue                              │
├─────────────────────────────────────────────────┤
│ 7. clockIdentity                                │
│    A smaller → A_BETTER                         │
│    B larger → B_BETTER                          │
└─────────────────────────────────────────────────┘
```

### dscmp2: the second-stage comparison

```c
/* bmc.c:35-81 */

int dscmp2(struct dataset *a, struct dataset *b)
{
    int diff;
    unsigned int A = a->stepsRemoved, B = b->stepsRemoved;

    /* case 1: stepsRemoved differ by more than 1 */
    if (A + 1 < B)
        return A_BETTER;  /* A has clearly fewer hops */
    if (B + 1 < A)
        return B_BETTER;  /* B has clearly fewer hops */

    /* case 2: A has one hop fewer */
    if (A < B) {
        diff = portid_cmp(&b->receiver, &b->sender);
        if (diff < 0)
            return A_BETTER;
        if (diff > 0)
            return A_BETTER_TOPO;
        return 0;  /* error-1 */
    }

    /* case 3: B has one hop fewer */
    if (A > B) {
        diff = portid_cmp(&a->receiver, &a->sender);
        if (diff < 0)
            return B_BETTER;
        if (diff > 0)
            return B_BETTER_TOPO;
        return 0;  /* error-1 */
    }

    /* case 4: same hop count, compare sender */
    diff = portid_cmp(&a->sender, &b->sender);
    if (diff < 0)
        return A_BETTER_TOPO;
    if (diff > 0)
        return B_BETTER_TOPO;

    /* case 5: compare receiver port numbers */
    if (a->receiver.portNumber < b->receiver.portNumber)
        return A_BETTER_TOPO;
    if (a->receiver.portNumber > b->receiver.portNumber)
        return B_BETTER_TOPO;

    /* error-2 */
    return 0;
}
```

**Why topology comparison matters**:

```text
When two clocks have identical attributes but different stepsRemoved:

For example:
A's stepsRemoved = 3
B's stepsRemoved = 4

Clearly A is closer to the master clock, so pick A.

But if:
A's stepsRemoved = 4
B's stepsRemoved = 5

the gap is only 1, and now you have to check the topology:
- is there a loop?
- whose path is better?

A_BETTER_TOPO and B_BETTER_TOPO mean the choice was made "for topology reasons".
```

## Message structure definitions

### The PTP header structure

```c
/* msg.h:90-103 */

struct ptp_header {
    uint8_t             tsmt;   /* transportSpecific | messageType */
    uint8_t             ver;    /* minorVersionPTP | versionPTP */
    UInteger16          messageLength;
    UInteger8           domainNumber;
    Octet               reserved1;
    Octet               flagField[2];
    Integer64           correction;
    UInteger32          reserved2;
    struct PortIdentity sourcePortIdentity;
    UInteger16          sequenceId;
    UInteger8           control;
    Integer8            logMessageInterval;
} PACKED;
```

**How the fields are packed**:

```text
tsmt field (1 byte):
- high nibble: transportSpecific
- low nibble: messageType

Example:
tsmt = 0x10
- high nibble = 0x1 → transportSpecific = 1 (e.g. 802.1AS)
- low nibble = 0x0 → messageType = SYNC

ver field (1 byte):
- high nibble: minorVersionPTP
- low nibble: versionPTP

Example:
ver = 0x12
- high nibble = 0x1 → minorVersionPTP = 1
- low nibble = 0x2 → versionPTP = 2
- full version: PTP 2.1 (IEEE 1588-2019)
```

**Message type definitions**:

```c
/* msg.h:45-54 */

#define SYNC                  0x0   /* Sync message */
#define DELAY_REQ             0x1   /* delay request */
#define PDELAY_REQ            0x2   /* peer delay request */
#define PDELAY_RESP           0x3   /* peer delay response */
#define FOLLOW_UP             0x8   /* Follow_Up message */
#define DELAY_RESP            0x9   /* delay response */
#define PDELAY_RESP_FOLLOW_UP 0xA   /* peer delay follow-up */
#define ANNOUNCE              0xB   /* Announce message */
#define SIGNALING             0xC   /* Signaling message */
#define MANAGEMENT            0xD   /* Management message */
```

### The Announce message structure

```c
/* msg.h:105-117 */
```

**The clever part**:

```text
the suffix[0] design:

This is a flexible array member:
- length 0, so it adds nothing to the struct size
- used to reach data at the end of the struct
- the Announce TLVs are appended after the struct

Key point: suffix is uint8_t (msg.h:116), and it holds
a raw TLV byte stream, not an array of any struct.
Reach it through the four legitimate paths below; don't cast it yourself.
```

The four access paths in the real source:

### The Sync message structure

```c
/* msg.h:119-123 */

struct sync_msg {
    struct ptp_header   hdr;              /* common header */
    struct Timestamp    originTimestamp;  /* send timestamp */
    uint8_t             suffix[0];        /* TLV suffix */
} PACKED;
```

**What originTimestamp means**:

```text
originTimestamp is the "send time" carried by a Sync message.

Two-step mode:
- the Sync's originTimestamp is usually 0
- the real timestamp comes in the Follow_Up
- why: the hardware timestamp is only available after transmission

One-step mode:
- the Sync carries the precise timestamp
- the hardware has to predict and insert the timestamp
- complex to implement, but efficient
```

### The Delay_Req/Delay_Resp message structures

```c
/* msg.h:125-142 */

struct delay_req_msg {
    struct ptp_header   hdr;              /* common header */
    struct Timestamp    originTimestamp;  /* wire field; linuxptp never fills it and never reads it, see the note below */
    uint8_t             suffix[0];        /* TLV suffix */
} PACKED;

/* —— struct follow_up_msg sits in between at msg.h:131-135 (deliberately
      not expanded here; it belongs to Sync's two-step flow, covered under
      Sync; the original book's 125-142 block makes the two look adjacent) */

/* msg.h:137-142 */

struct delay_resp_msg {
    struct ptp_header   hdr;                    /* common header */
    struct Timestamp    receiveTimestamp;       /* receive timestamp */
    struct PortIdentity requestingPortIdentity; /* requester identity */
    uint8_t             suffix[0];              /* TLV suffix */
} PACKED;
```

**How the four timestamps relate**:

```text
E2E delay measurement involves four timestamps:

t1 (master sends Sync): carried in the Sync or the Follow_Up
t2 (slave receives Sync): recorded locally by the slave clock
t3 (slave sends Delay_Req): the send timestamp the slave clock records locally when it transmits that Delay_Req (Internal `req->hwts.ts`); linuxptp never sets and never uses the Delay_Req originTimestamp
t4 (master receives Delay_Req): carried in delay_resp_msg.receiveTimestamp

Offset calculation:
offset = [(t2 - t1) - (t4 - t3)] / 2

Path delay:
delay = [(t2 - t1) + (t4 - t3)] / 2
```

## Message handling functions

### Message reception flow

```c
/* the real entry point on the receive side is process_sync() — this is a
   rewritten version (excerpt); for the real source see port.c:2714-2767 */

void process_sync(struct port *p, struct ptp_message *m)   /* returns void, not static int */
{
    enum syfu_event event;

    /* step 1: filter by port state first — only UNCALIBRATED / SLAVE go on */
    switch (p->state) {                                    /* port.c:2717-2730 */
    case PS_INITIALIZING: case PS_FAULTY:   case PS_DISABLED:
    case PS_LISTENING:    case PS_PRE_MASTER: case PS_MASTER:
    case PS_GRAND_MASTER: case PS_PASSIVE:
        return;
    case PS_UNCALIBRATED: case PS_SLAVE:
        break;
    }

    /* step 2: check whether it comes from the current parent clock.
       struct port has no parentDS; the parent identity has to come from clock */
    if (check_source_identity(p, m)) {                     /* port.c:2732-2734 */
        return;
    }
    /* check_source_identity() itself is at port.c:105-114:
       master = clock_parent_identity(p->clock);          (clock.c:1787)
       return pid_eq(&master, &m->header.sourcePortIdentity) ? 0 : -1;
       if ignore_source_id is configured it lets everything through (port.c:109-111) */

    /* step 3: if the master changed logSyncInterval, follow it (port.c:2736-2746) */

    /* step 4: fold the local asymmetry into correction first */
    m->header.correction += p->asymmetry;                  /* port.c:2748 */

    /* step 5: one-step synchronizes directly; t2 is m->hwts.ts,
       t1 comes from m->ts.pdu parsed out of the PDU */
    if (one_step(m)) {                                     /* port.c:2750 */
        port_synchronize(p, m->header.sequenceId,
                         m->hwts.ts, m->ts.pdu,            /* ← t2, t1 */
                         m->header.correction, 0,
                         m->header.logMessageInterval);
        flush_last_sync(p);
        return;
    }

    /* step 6: two-step — instead of storing t2 in p->t2,
       keep the whole Sync message alive by refcount and wait for the Follow_Up to pair with it */
    if (p->syfu == SF_HAVE_FUP &&
        fup_sync_ok(p->last_syncfup, m) &&                 /* port.c:587 */
        p->last_syncfup->header.sequenceId == m->header.sequenceId) {
        event = SYNC_MATCH;                                /* port.c:2759-2762 */
    } else {
        event = SYNC_MISMATCH;
    }
    port_syfufsm(p, event, m);                             /* port.c:2766 */
}

/* the two-step pairing state machine: port.c:1474-1563, only three states
   (enum syfu_state: SF_EMPTY / SF_HAVE_SYNC / SF_HAVE_FUP, port_private.h:34-38) */

/* SF_HAVE_SYNC + FUP_MATCH, i.e. a Follow_Up arrives on top of a Sync (port.c:1518-1527): */
syn = p->last_syncfup;
port_synchronize(p, syn->header.sequenceId,
                 syn->hwts.ts, m->ts.pdu,          /* t2 comes from the retained Sync */
                 syn->header.correction,           /* c1: the Sync's correction */
                 m->header.correction,             /* c2: the Follow_Up's correction */
                 m->header.logMessageInterval);
msg_put(p->last_syncfup);
p->syfu = SF_EMPTY;

/* the real t1/t2 computation happens in port_synchronize(), port.c:1386-1420 (excerpt): */
t1  = timestamp_to_tmv(origin_ts);                          /* port.c:1400 */
t2  = ingress_ts;                                           /* :1401 */
c1  = correction_to_tmv(correction1);                       /* :1402 */
c2  = correction_to_tmv(correction2);                       /* :1403 */
t1c = tmv_add(t1, tmv_add(c1, c2));                         /* :1404 */
/* ... */
state = clock_synchronize(p->clock, t2, t1c);               /* port.c:1420 */
```

### Message transmission flow

```c
/* the real entry point on the transmit side — rewritten excerpt; for the real source see port.c:1781-1886 */

/* the signature has three parameters; the sequence number is passed in by the caller */
int port_tx_sync(struct port *p, struct address *dst, uint16_t sequence_id)
{
    struct ptp_message *msg, *fup;      /* prepare both messages at once: Sync and Follow_Up */
    int err, event;

    /* step 0: pick the transport channel from the timestamping mode */      /* port.c:1786-1800 */
    switch (p->timestamping) {
    case TS_SOFTWARE: case TS_LEGACY_HW: case TS_HARDWARE:
        event = TRANS_EVENT;   break;
    case TS_ONESTEP:           event = TRANS_ONESTEP;   break;
    case TS_P2P1STEP:          event = TRANS_P2P1STEP;  break;
    default: return -1;
    }

    /* step 1: allocate both messages */                          /* port.c:1811-1819 */
    msg = msg_allocate();
    if (!msg) {
        return -1;                                    /* not -ENOMEM */
    }
    fup = msg_allocate();
    if (!fup) {                                      /* note that fup is allocated unconditionally */
        msg_put(msg);
        return -1;
    }
    msg->hwts.type = p->timestamping;                 /* port.c:1821 */
    fup->hwts.type = p->timestamping;                 /* port.c:1856 */

    /* step 2: fill the Sync header. The member is header (union member, msg.h:187), not hdr */
    msg->header.tsmt               = SYNC | p->transportSpecific;   /* port.c:1823 */
    msg->header.ver                = ptp_hdr_ver;                   /* :1824 */
    msg->header.messageLength      = sizeof(struct sync_msg);       /* :1825 */
    msg->header.domainNumber       = clock_domain_number(p->clock); /* :1826 */
    msg->header.sourcePortIdentity = p->portIdentity;               /* :1827 */
    msg->header.sequenceId         = sequence_id;                   /* :1828 */
    msg->header.logMessageInterval = p->logSyncInterval;             /* :1829 */

    /* step 3: TWO_STEP is set conditionally, and with |= not = */
    if (p->timestamping != TS_ONESTEP &&
        p->timestamping != TS_P2P1STEP) {                           /* :1831-1833 */
        msg->header.flagField[0] |= TWO_STEP;
    }

    /* step 4: extra handling for unicast */                                    /* :1835-1839 */
    if (dst) {
        msg->address = *dst;
        msg->header.flagField[0] |= UNICAST;
        msg->header.logMessageInterval = 0x7f;
    }

    /* step 5: send the Sync */                                            /* :1840-1851 */
    err = port_prepare_and_send(p, msg, event);
    if (err) {
        pr_err("%s: send sync failed", p->log_name);
        goto out;
    }
    if (p->timestamping == TS_ONESTEP ||
        p->timestamping == TS_P2P1STEP) {
        goto out;              /* one-step: the NIC already inserted the timestamp, no Follow_Up */
    } else if (msg_sots_missing(msg)) {
        pr_err("missing timestamp on transmitted sync");              /* msg.c:615 */
        err = -1;
        goto out;
    }

    /* step 6: build the Follow_Up on the spot and send it too */                   /* :1853-1881 */
    fup->header.tsmt               = FOLLOW_UP | p->transportSpecific; /* :1858 */
    fup->header.ver                = ptp_hdr_ver;                       /* :1859 */
    fup->header.messageLength      = sizeof(struct follow_up_msg);      /* :1860 */
    fup->header.domainNumber       = clock_domain_number(p->clock);     /* :1861 */
    fup->header.sourcePortIdentity = p->portIdentity;                   /* :1862 */
    fup->header.sequenceId         = sequence_id;    /* same sequence number as the Sync! */ /* :1863 */
    fup->header.logMessageInterval = p->logSyncInterval;                /* :1864 */

    /* fill in the Sync send timestamp just obtained — this is where two-step's t1 comes from */
    fup->follow_up.preciseOriginTimestamp = tmv_to_Timestamp(msg->hwts.ts); /* :1866 */

    if (dst) {                                                          /* :1868-1871 */
        fup->address = *dst;
        fup->header.flagField[0] |= UNICAST;
    }
    if (p->follow_up_info && follow_up_info_append(fup)) {              /* :1872-1876 */
        pr_err("%s: append fup info failed", p->log_name);
        err = -1;
        goto out;
    }
    err = port_prepare_and_send(p, fup, TRANS_GENERAL);   /* goes out on the general channel */ /* :1878 */

out:
    msg_put(msg);                                         /* port.c:1882-1885 */
    msg_put(fup);
    return err;
}

/* the sequence number is not incremented inside port_tx_sync(); the caller passes it in: */
return port_tx_sync(p, NULL, p->seqnum.sync++) ? EV_FAULT_DETECTED : EV_NONE;  /* port.c:3130-3131 */
/* a transparent clock forwards with the original message's sequence number: */
err = port_tx_sync(p, &m->address, m->header.sequenceId);  /* port.c:2332 */
```

## Summary: the design behind data sets and messages

**Memory optimization**:
- use flags to pack boolean fields
- flexible arrays for variable-length data
- PACKED keeps the structs compact

**Protocol mapping**:
- struct definitions match the IEEE 1588 message format
- field order matches the standard
- ready for direct transmission on the wire

**Encoding tricks**:
- bit packing (tsmt, ver)
- flexible arrays (suffix[0])
- type aliases (tmv_t)

**Completeness**:
- supports every PTP message type
- supports hardware and software timestamping
- supports one-step and two-step mode
