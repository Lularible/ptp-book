# 3.3 The Port State Machine: 200 Lines of C Driving Nine States

## The art of the state machine

A PTP port has nine states, and the rules for moving between them are complicated.

Yet LinuxPTP implements the whole state machine in just **337 lines** of `fsm.c` (`ptp_fsm()` accounts for 200 of them).

How does it pull that off?

---

## State machine overview

### The states IEEE 1588 defines

Chapter 2 covered the nine states of a PTP port in detail:

```text
1. INITIALIZING   - initializing
2. FAULTY         - fault
3. DISABLED       - disabled
4. LISTENING      - listening
5. PRE_MASTER     - pre-master
6. MASTER         - master clock
7. PASSIVE        - passive
8. UNCALIBRATED   - uncalibrated
9. SLAVE          - slave clock
```

### How LinuxPTP defines states

```c
/* fsm.h, lines 24-35 */

enum port_state {
    PS_INITIALIZING = 1,
    PS_FAULTY,
    PS_DISABLED,
    PS_LISTENING,
    PS_PRE_MASTER,
    PS_MASTER,
    PS_PASSIVE,
    PS_UNCALIBRATED,
    PS_SLAVE,
    PS_GRAND_MASTER,  /* non-standard extension */
};
```

**Where PS_GRAND_MASTER comes from**:

```text
IEEE 1588 defines only PS_MASTER.

LinuxPTP adds PS_GRAND_MASTER (fsm.h:34, and the comment at the end of
that source line says non-standard extension outright). Of the 10 PS_*
values, it's the only one that's linuxptp's own invention.

Difference:
- PS_MASTER: the port is the master clock on some path (BMCA decision M3,
  bmc.c:173)
- PS_GRAND_MASTER: this clock is the root of the whole clock domain
  (BMCA decisions M1/M2, bmc.c:156, bmc.c:163)

It's a purely internal state, never exposed. Everywhere a state goes into
a message, linuxptp folds it back to PS_MASTER:
- PORT_DATA_SET management attribute response:
    if (target->state == PS_GRAND_MASTER) {       /* port.c:1019-1023 */
        pds->portState = PS_MASTER;
    } else {
        pds->portState = target->state;
    }
- NetSync Monitor response:
    head->port_state =                            /* port.c:543 */
        p->state == PS_GRAND_MASTER ? PS_MASTER : p->state;
```

**Event categories**:

```text
Category 1: basic events
- EV_POWERUP: device power-up
- EV_INITIALIZE: re-initialize
- EV_INIT_COMPLETE: initialization complete

Category 2: control events
- EV_DESIGNATED_ENABLED: administrator enables the port
- EV_DESIGNATED_DISABLED: administrator disables the port

Category 3: fault events
- EV_FAULT_DETECTED: fault detected
- EV_FAULT_CLEARED: fault cleared
- EV_SYNCHRONIZATION_FAULT: synchronization fault

Category 4: timer events
- EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES: Announce timeout
- EV_QUALIFICATION_TIMEOUT_EXPIRES: qualification timeout

Category 5: BMCA events
- EV_STATE_DECISION_EVENT: state decision
- EV_MASTER_CLOCK_SELECTED: master clock selected
- EV_RS_*: BMCA recommended state
```

## The main state machine

### The ptp_fsm function

```c
/* fsm.c:21-220 —— excerpt: skeleton only. The 10 case branches
   appear verbatim one by one under "The transitions in detail" below;
   the full 44 rules are in "The complete transition tables" */

enum port_state ptp_fsm(enum port_state state, enum fsm_event event, int mdiff)
{
	enum port_state next = state;              /* fsm.c:23 */

	if (EV_INITIALIZE == event || EV_POWERUP == event)   /* fsm.c:25-26 */
		return PS_INITIALIZING;

	switch (state) {                         /* fsm.c:28 */
	case PS_INITIALIZING:                    /* fsm.c:29-40, see below */
		break;
	case PS_FAULTY:                          /* fsm.c:42-53 */
		break;
	case PS_DISABLED:                        /* fsm.c:55-58 */
		break;
	case PS_LISTENING:                       /* fsm.c:60-86, see below */
		break;
	case PS_PRE_MASTER:                      /* fsm.c:88-108, see below */
		break;
	case PS_MASTER:                          /* fsm.c:110 */
	case PS_GRAND_MASTER:                    /* fsm.c:111 (shares the MASTER fall-through block) */
		break;
	case PS_PASSIVE:                         /* fsm.c:130-153 */
		break;
	case PS_UNCALIBRATED:                    /* fsm.c:155-184 */
		break;
	case PS_SLAVE:                           /* fsm.c:186-216, see below */
		break;
	}

	return next;                                 /* fsm.c:219 */
}
```

**Design highlights**:

```text
Highlight 1: functional design

The state machine is a pure function:
- input: current state + event + mdiff
- output: next state
- no side effects

Benefits:
- easy to test
- easy to understand
- easy to debug

Highlight 2: stay in the current state by default

enum port_state next = state;

If an event isn't handled, the state doesn't change.
That avoids complex error handling.

Highlight 3: fast path

if (EV_INITIALIZE == event || EV_POWERUP == event)
    return PS_INITIALIZING;

Whatever the current state, an initialize event returns to INITIALIZING.
No need to handle it again in every case.
```

### The transitions in detail

#### INITIALIZING

```c
/* fsm.c, lines 29-40 */

case PS_INITIALIZING:
    switch (event) {
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_INIT_COMPLETE:

        break;
    default:

    }
    break;
```

**State transition diagram**:

```text

    │
    ├─ EV_FAULT_DETECTED ──→ PS_FAULTY
    │
    └─ EV_INIT_COMPLETE ───→ PS_LISTENING

Notes:
- a fault during initialization → FAULTY
- initialization complete → LISTENING, ready to receive Announce
```

**State transition diagram**:

```text
LISTENING
    │
    ├─ EV_DESIGNATED_DISABLED ────────────────→ PS_DISABLED
    │
    ├─ EV_FAULT_DETECTED ─────────────────────→ PS_FAULTY
    │
    ├─ EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES ───→ PS_MASTER
    │   (no Announce for a long time, so it becomes master itself)
    │
    ├─ EV_RS_MASTER ──────────────────────────→ PS_PRE_MASTER
    │   (the BMCA suggests it should be master)
    │
    ├─ EV_RS_GRAND_MASTER ────────────────────→ PS_GRAND_MASTER
    │   (the BMCA suggests it should be Grandmaster)
    │
    ├─ EV_RS_SLAVE ───────────────────────────→ PS_UNCALIBRATED
    │   (the BMCA suggests it should be slave)
    │
    └─ EV_RS_PASSIVE ─────────────────────────→ PS_PASSIVE
        (the BMCA suggests it should stay passive)
```

#### PRE_MASTER

```c
/* fsm.c, lines 88-108 */

case PS_PRE_MASTER:
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_QUALIFICATION_TIMEOUT_EXPIRES:
        next = PS_MASTER;
        break;
    case EV_RS_SLAVE:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**Why PRE_MASTER exists**:

```text
Why does the PRE_MASTER state exist?

Prevent network oscillation:
- the port decides to become master
- it enters PRE_MASTER and waits
- it confirms no better master is out there
- only after the timeout does it enter MASTER

Wait time:
- set by qualificationTimeout
- usually a few announceIntervals
- long enough for Announce information to spread
```

#### MASTER and GRAND_MASTER

```c
/* fsm.c, lines 110-128 */

case PS_MASTER:
case PS_GRAND_MASTER:  /* both states are handled the same way */
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_RS_SLAVE:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**The code-merging trick**:

```text
case PS_MASTER:
case PS_GRAND_MASTER:
    /* both states share the same handling logic */

This is a C switch feature:
- several cases can share one code block
- less duplicated code
- easier to maintain
```

#### SLAVE

```c
/* fsm.c, lines 186-216 */

case PS_SLAVE:
    switch (event) {
    case EV_DESIGNATED_DISABLED:
        next = PS_DISABLED;
        break;
    case EV_FAULT_DETECTED:
        next = PS_FAULTY;
        break;
    case EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES:
        next = PS_MASTER;
        break;
    case EV_SYNCHRONIZATION_FAULT:
        next = PS_UNCALIBRATED;
        break;
    case EV_RS_MASTER:
        next = PS_PRE_MASTER;
        break;
    case EV_RS_GRAND_MASTER:
        next = PS_GRAND_MASTER;
        break;
    case EV_RS_SLAVE:
        if (mdiff)  /* the master changed */
            next = PS_UNCALIBRATED;
        break;
    case EV_RS_PASSIVE:
        next = PS_PASSIVE;
        break;
    default:
        break;
    }
    break;
```

**What the mdiff argument means**:

```c
/* fsm.c:206-209 (inside the PS_SLAVE branch of ptp_fsm) */
case EV_RS_SLAVE:
	if (mdiff)
		next = PS_UNCALIBRATED;
	break;
```

```text
mdiff = "master difference"

Meaning:
- mdiff = 0: the master didn't change
- mdiff ≠ 0: the master changed

Behavior:
- EV_RS_SLAVE arrives and the master didn't change (mdiff=0)
  → stay in SLAVE; no recalibration needed

- EV_RS_SLAVE arrives and the master changed (mdiff≠0)
  → enter UNCALIBRATED and resynchronize

This is an optimization:
- a master switch is a common case
- it avoids unnecessary state changes
```

## The slave-only state machine

### The ptp_slave_fsm function

```c
/* fsm.c:222-337 —— excerpt: the full function has 6 state branches */

enum port_state ptp_slave_fsm(enum port_state state, enum fsm_event event,
			      int mdiff)
{
	enum port_state next = state;

	if (EV_INITIALIZE == event || EV_POWERUP == event)   /* fsm.c:227-228 */
		return PS_INITIALIZING;

	switch (state) {
	case PS_INITIALIZING:   /* fsm.c:231-242 */
	case PS_FAULTY:         /* fsm.c:244-255 */
	case PS_DISABLED:       /* fsm.c:257-260 */
	case PS_LISTENING:      /* fsm.c:262-282 */
	case PS_UNCALIBRATED:   /* fsm.c:284-304 */
	case PS_SLAVE:          /* fsm.c:306-330 */
		/* …each branch is below… */
		break;
	default:                /* fsm.c:332-333 */
		break;          /* PRE_MASTER / MASTER / GRAND_MASTER / PASSIVE
		                   have no branch in ptp_slave_fsm; they land
		                   here and next keeps the current state */
	}

	return next;                /* fsm.c:336 */
}
```

**Differences from the main state machine**:

```text
ptp_fsm (full state machine, fsm.c:21-220):
- can become master
- can become slave
- all 10 PS_* states have branches; it can enter every state

ptp_slave_fsm (slave-only machine, fsm.c:222-337):
- can never take a master-side role: PS_PRE_MASTER / PS_MASTER /
  PS_GRAND_MASTER; PS_PASSIVE is merely unreachable. None of these
  four has a case here, so all fall to default: break; (fsm.c:332-333)
- EV_RS_MASTER / EV_RS_GRAND_MASTER / EV_RS_PASSIVE /
  EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES are not "ignored"; they are
  **listed as explicit case labels and normalized to PS_LISTENING**
  (LISTENING: fsm.c:270-275; UNCALIBRATED: fsm.c:292-297;
   SLAVE: fsm.c:314-319)
- reachable states: **6**, not 3:
  PS_INITIALIZING (fsm.c:231), PS_FAULTY (:244), PS_DISABLED (:257),
  PS_LISTENING (:262), PS_UNCALIBRATED (:284), PS_SLAVE (:306)

Where this applies:
- devices with defaultDS.slaveOnly = TRUE (the setting is now called
  clientOnly; slaveOnly is the deprecated old name, config.c:264, 787-788)
- end devices that don't want to take part in the BMCA
```


### There are four state machines, not two

Besides the two above, v4.4 has another two, in `designated_fsm.c` (107 lines): `designated_master_fsm()` (`designated_fsm.c:23`) and `designated_slave_fsm()` (`designated_fsm.c:64`). Which one a port uses is decided once in `port_open()`, stored in the `p->state_machine` function pointer (`port_private.h:102-103`):

```c
/* port.c:3583-3594 (verbatim, excerpt) */

if (p->bmca == BMCA_NOOP && !port_is_uds(p)) {
	if (p->master_only) {
		p->state_machine = designated_master_fsm;
	} else if (clock_slave_only(clock)) {
		p->state_machine = designated_slave_fsm;
	} else {
		pr_err("Please enable at least one of serverOnly or clientOnly when BMCA == noop.\n");
		goto err_transport;
	}
} else {
	p->state_machine = clock_slave_only(clock) ? ptp_slave_fsm : ptp_fsm;
}
```

The test is `clock_slave_only()`. It reads a flag in `defaultDS`; one line (`clock.c:1919-1922`):

```c
/* clock.c:1919-1922 (verbatim excerpt, annotation added by this book) */

int clock_slave_only(struct clock *c)
{
	return c->dds.flags & DDS_SLAVE_ONLY;
}
```

## Using the state machine

### Calling the state machine from a port

The real call chain has **three layers**, not one: `port_dispatch()` only forwards through a function pointer; which machine to use was fixed earlier, in `port_open()` (previous section); the transition work splits into E2E and P2P versions by delay mechanism.

```c
/* Layer 1: port_dispatch() — port.c:2922-2925, verbatim; that thin */

void port_dispatch(struct port *p, enum fsm_event event, int mdiff)
{
	p->dispatch(p, event, mdiff);
}

/* p->dispatch is assigned in port_open() by clock_type (port.c:3553-3569):
   OC/BC → bc_dispatch, P2P → p2p_dispatch, E2E → e2e_dispatch */

/* Layer 2: bc_dispatch() — rewritten (excerpt); real source at port.c:2927-2957 */

static void bc_dispatch(struct port *p, enum fsm_event event, int mdiff)
{
	if (clock_slave_only(p->clock)) {          /* port.c:2929-2933 */
		if (event == EV_RS_GRAND_MASTER) {
			port_slave_priority_warning(p);    /* warn only, don't change the flow */
		}
	}

	if (!port_state_update(p, event, mdiff)) { /* port.c:2935-2937 */
		return;                            /* state didn't change; no timer rearm needed either */
	}

	switch (p->delayMechanism) {               /* port.c:2939-2947 */
	case DM_COMMON_P2P:
	case DM_P2P:
		port_p2p_transition(p, p->state);
		break;
	default:
		port_e2e_transition(p, p->state);
		break;
	}

	/* …under jbod, a failed PHC switch re-sends EV_FAULT_DETECTED, port.c:2949-2956… */
}

/* Layer 3: port_state_update() — rewritten (excerpt); real source at port.c:3761-3803 */

int port_state_update(struct port *p, enum fsm_event event, int mdiff)
{
	enum port_state next = p->state_machine(p->state, event, mdiff);  /* :3763 */
	/* ↑ this one call runs the pure function in fsm.c; which function
	   it is comes from the p->state_machine pointer (port.c:3593), so
	   there's no if/else on slave_only here */

	if (PS_FAULTY == next) {                    /* port.c:3765-3772 */
		struct fault_interval i;
		fault_interval(p, last_fault_type(p), &i);
		if (port_link_status_get(p) && clear_fault_asap(&i)) {
			pr_notice("%s: clearing fault immediately", p->log_name);
			next = p->state_machine(next, EV_FAULT_CLEARED, 0);
		}
	}

	if (PS_INITIALIZING == next) {              /* port.c:3774-3789 */
		/* special case: initialization happens immediately, so we can
		   feed the result straight back into the state machine and land
		   directly in LISTENING (or FAULTY) in one step */
		if (port_is_enabled(p)) {
			port_disable(p);
		}
		if (port_initialize(p)) {           /* port.c:2006 */
			event = EV_FAULT_DETECTED;
		} else {
			event = EV_INIT_COMPLETE;
		}
		next = p->state_machine(next, event, 0);
	}

	if (mdiff) {
		p->unicast_state_dirty = true;      /* port.c:3791-3793 */
	}
	if (next != p->state) {                     /* port.c:3794-3800 */
		port_show_transition(p, next, event);   /* port.c:1342, prints the state transition log */
		p->state = next;
		port_notify_event(p, NOTIFY_PORT_STATE); /* port.c:3498, notify subscribers */
		p->unicast_state_dirty = true;
		return 1;
	}

	return 0;                                   /* port.c:3802 */
}
```

### Transition actions (there is no enter / exit split)

Here's a model correction: linuxptp does **not** have separate enter / exit hooks. What it does is "**clear all timers first, then arm whichever ones the new state needs**", all in one function, with `next` (the new state) as the argument. This is the E2E version, copied verbatim:

```c
/* port.c, lines 2828-2873 (verbatim, only the comments are added) */

static void port_e2e_transition(struct port *p, enum port_state next)
{
	port_clr_tmo(p->fda.fd[FD_ANNOUNCE_TIMER]);        /* clear all six timers first */
	port_clr_tmo(p->fda.fd[FD_SYNC_RX_TIMER]);
	port_clr_tmo(p->fda.fd[FD_DELAY_TIMER]);
	port_clr_tmo(p->fda.fd[FD_QUALIFICATION_TIMER]);
	port_clr_tmo(p->fda.fd[FD_MANNO_TIMER]);
	port_clr_tmo(p->fda.fd[FD_SYNC_TX_TIMER]);
	/* Leave FD_UNICAST_REQ_TIMER running. */

	switch (next) {
	case PS_INITIALIZING:
		break;                                   /* nothing to do */
	case PS_FAULTY:
	case PS_DISABLED:
		port_disable(p);                           /* :2843 */
		sad_set_last_seqid(clock_config(p->clock), p->spp, -1);
		break;
	case PS_LISTENING:
		port_set_announce_tmo(p);                  /* :2847 */
		break;
	case PS_PRE_MASTER:
		port_set_qualification_tmo(p);             /* :2850 */
		break;
	case PS_MASTER:
	case PS_GRAND_MASTER:
		if (!p->inhibit_announce) {
			set_tmo_log(p->fda.fd[FD_MANNO_TIMER], 1, -10); /*~1ms*/
		}                                          /* :2854-2856 */
		port_set_sync_tx_tmo(p);                   /* :2857 */
		sad_set_last_seqid(clock_config(p->clock), p->spp, -1);
		break;
	case PS_PASSIVE:
		port_set_announce_tmo(p);                  /* :2861 */
		break;
	case PS_UNCALIBRATED:
		flush_last_sync(p);                        /* :2864 */
		flush_delay_req(p);                        /* :2865 */
		sad_set_last_seqid(clock_config(p->clock), p->spp, -1);
		/* fall through */
	case PS_SLAVE:
		port_set_announce_tmo(p);                  /* :2869 */
		port_set_delay_tmo(p);                     /* :2870 */
		break;
	};
}
```

**What each state actually does**:

```text
port_e2e_transition() (port.c:2838-2872):

PS_INITIALIZING (:2839-2840)
- the transition function does nothing
- the real initialization doesn't happen here; when port_state_update()
  sees next == PS_INITIALIZING it first calls port_initialize() (port.c:2006,
  which reads the portDS entries from the config into the struct and creates
  the timerfds), then immediately feeds back EV_INIT_COMPLETE /
  EV_FAULT_DETECTED (port.c:3774-3789)

PS_FAULTY / PS_DISABLED (:2841-2845)
- port_disable(p) (port.c:1978): clear the TC, flush three queues,
  p->best = NULL, free_foreign_masters(p), close the transport, close every
  timer fd
- sad_set_last_seqid(..., -1): reset the security association's sequence
  number baseline

PS_LISTENING (:2846-2848)
- arm only the Announce receipt timeout: port_set_announce_tmo(p)
- note: clearing the foreign master list happens inside port_disable()
  (port.c:1988), not on entry to LISTENING

PS_PRE_MASTER (:2849-2851)
- arm the qualification timeout: port_set_qualification_tmo(p)

PS_MASTER / PS_GRAND_MASTER (:2852-2859)
- both states share one block of code (switch case fall-through)
- unless inhibit_announce is set, arm the Announce transmit timer at about
  1 ms (set_tmo_log(fd, 1, -10))
- arm the Sync transmit timer: port_set_sync_tx_tmo(p)
- "ready to answer Delay_Req" needs no extra action; receive dispatch has
  been running all along

PS_PASSIVE (:2860-2862)
- again only the Announce receipt timeout (which is why PASSIVE can time
  out into MASTER too, see fsm.c:138-140); an incoming Sync is discarded

PS_UNCALIBRATED (:2863-2867)
- flush_last_sync(p) + flush_delay_req(p): clear the Sync waiting to be
  paired and the Delay_Req waiting for a response
- reset the security sequence number, then fall through to PS_SLAVE

PS_SLAVE (:2868-2871)
- arm the Announce receipt timeout and the Delay_Req transmit timer
```

The P2P version, `port_p2p_transition()` (`port.c:2875-2920`), has exactly the same structure with three differences: **the DELAY timer is not cleared across a transition** (`port.c:2879`, comment "Leave FD_DELAY_TIMER running."); entering LISTENING **also** arms the Delay timer (`port.c:2893-2896`, because P2P has to keep measuring peer delay against the peer); entering UNCALIBRATED flushes peer delay instead of delay_req (`port.c:2911-2914`), and the PS_SLAVE branch **no longer** calls `port_set_delay_tmo()` (`port.c:2916-2918`).

## Design pattern analysis

### The state pattern

LinuxPTP's state machine implements the classic state pattern:

```text
Elements of the state pattern:
1. state enum (enum port_state)
2. event enum (enum fsm_event)
3. transition table (nested switch-case)
4. transition actions (clear all timers first, then rearm for the new state; one version for E2E, one for P2P)

Benefits:
- transition logic lives in one place
- easy to add a state
- easy to add an event
- transitions are visible
```

### Table-driven vs nested switch

LinuxPTP picks **nested switch** over a **transition table**:

```text
Transition-table style (pseudocode):
struct {
    enum port_state from;
    enum fsm_event event;
    enum port_state to;
} state_table[] = {
    {PS_INITIALIZING, EV_INIT_COMPLETE, PS_LISTENING},
    {PS_LISTENING, EV_RS_SLAVE, PS_UNCALIBRATED},
    // ...
};

Nested-switch style:
switch (state) {
    case PS_INITIALIZING:
        switch (event) {
            case EV_INIT_COMPLETE:
                next = PS_LISTENING;
        }
}

Why nested switch?

Pros:
- compact code
- compilers optimize it well
- no extra data structure
- easy to debug (you can add logging in a case)

Cons:
- adding a state means touching several places
- less obvious than table-driven

LinuxPTP's reasoning:
- the number of states is fixed (the standard's 9 + linuxptp's private PS_GRAND_MASTER = 10)
- the number of events is fixed (17)
- the transition rules are stable
- nested switch is the more efficient choice
```

## Summary: the wisdom of the design

**Functional design**:
- pure function, no side effects
- easy to test and debug

**Stay in the current state by default**:
- unhandled events don't change the state
- no accidental transitions

**Fast path**:
- special events return early
- less nesting

**Merged states**:
- similar states share code
- less duplication

**The state machine is a replaceable function pointer**:
- full machine (`ptp_fsm`, fsm.c:21-220)
- slave-only machine (`ptp_slave_fsm`, fsm.c:222-337)
- also `designated_master_fsm` / `designated_slave_fsm` (designated_fsm.c:23, 64), for G.8275.1 setups with `bmca == BMCA_NOOP`
- all four share the signature, live in `p->state_machine`, and are chosen once by `port_open()` (port.c:3583-3594)
