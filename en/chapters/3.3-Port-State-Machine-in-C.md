# 3.3 The Port State Machine: 200 Lines of C Driving Nine States

## Where the states live

The state machine we studied in section 2.5 becomes, in LinuxPTP, two functions in `fsm.c`:

- `ptp_fsm`, the full machine for ordinary and boundary clocks (fsm.c, lines 21-220).
- `ptp_slave_fsm`, the simplified machine for slave-only ports (fsm.c, lines 222-337).

## ptp_fsm: the shape of the code

```c
enum port_state ptp_fsm(enum port_state state, enum fsm_event event, int mdiff)
{
    enum port_state next = state;

    /* any state: initialize/power-up resets */
    if (EV_INITIALIZE == event || EV_POWERUP == event)
        return PS_INITIALIZING;

    switch (state) {
    case PS_INITIALIZING:
        switch (event) {
        case EV_FAULT_DETECTED:      next = PS_FAULTY;      break;
        case EV_INIT_COMPLETE:       next = PS_LISTENING;   break;
        default: break;
        }
        break;

    case PS_LISTENING:
        switch (event) {
        case EV_DESIGNATED_DISABLED: next = PS_DISABLED;    break;
        case EV_FAULT_DETECTED:      next = PS_FAULTY;      break;
        case EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES:
                                     next = PS_MASTER;      break;
        case EV_RS_MASTER:           next = PS_PRE_MASTER;  break;
        case EV_RS_GRAND_MASTER:     next = PS_GRAND_MASTER; break;
        case EV_RS_SLAVE:            next = PS_UNCALIBRATED; break;
        case EV_RS_PASSIVE:          next = PS_PASSIVE;     break;
        default: break;
        }
        break;

    case PS_PRE_MASTER:
        switch (event) {
        /* ... EV_QUALIFICATION_TIMEOUT_EXPIRES → PS_MASTER ... */
        }
        break;

    case PS_MASTER:
    case PS_GRAND_MASTER:
        switch (event) {
        case EV_DESIGNATED_DISABLED: next = PS_DISABLED;    break;
        case EV_FAULT_DETECTED:      next = PS_FAULTY;      break;
        case EV_RS_SLAVE:            next = PS_UNCALIBRATED; break;
        case EV_RS_PASSIVE:          next = PS_PASSIVE;     break;
        default: break;
        }
        break;

    case PS_SLAVE:
        switch (event) {
        case EV_DESIGNATED_DISABLED: next = PS_DISABLED;    break;
        case EV_FAULT_DETECTED:      next = PS_FAULTY;      break;
        case EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES:
                                     next = PS_MASTER;      break;
        case EV_SYNCHRONIZATION_FAULT:
                                     next = PS_UNCALIBRATED; break;
        case EV_RS_MASTER:           next = PS_PRE_MASTER;  break;
        case EV_RS_GRAND_MASTER:     next = PS_GRAND_MASTER; break;
        case EV_RS_SLAVE:
            if (mdiff) next = PS_UNCALIBRATED;              break;
        case EV_RS_PASSIVE:          next = PS_PASSIVE;     break;
        default: break;
        }
        break;
    ...
    }
    return next;
}
```

Key facts already established in section 2.5, now in code:

- LISTENING + EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES → PS_MASTER (directly, no PRE_MASTER).
- SLAVE + EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES → PS_MASTER (an ordinary port takes over on master loss).
- EV_RS_SLAVE into SLAVE only leaves the state when mdiff is set (the master really changed).

## mdiff: the "master changed" flag

State transitions that depend on *which* grandmaster they'd follow use `mdiff`. When BMCA reports a brand-new best master (`fresh_best`), the SLAVE port re-enters through UNCALIBRATED to refresh the servo. When it's merely the same master reaffirmed, SLAVE stays put.

## ptp_slave_fsm: the slave-only machine

For `slaveOnly=TRUE` devices, the machine collapses:

```
INITIALIZING → LISTENING → UNCALIBRATED → SLAVE
```

In `ptp_slave_fsm`:

- LISTENING ignores EV_RS_MASTER / EV_RS_GRAND_MASTER (stays LISTENING).
- LISTENING + EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES → stays LISTENING.
- UNCALIBRATED + EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES → LISTENING.
- SLAVE + EV_ANNOUNCE_RECEIPT_TIMEOUT_EXPIRES → LISTENING (not MASTER).

That is the crucial difference from `ptp_fsm`: a slave-only port can never become master; on master loss it falls back to LISTENING and waits.

## How a port actually traverses states

In v4.4 the FSM is run by `port_state_update(p, event, mdiff)` (port.c:3761), and the per-state entry work (timers, sends, PHC config) is done afterward by the transition helpers `port_e2e_transition` / `port_p2p_transition`, dispatched from `bc_dispatch` (port.c:2927):

```c
static void bc_dispatch(struct port *p, enum fsm_event event, int mdiff)
{
    ...
    if (!port_state_update(p, event, mdiff))
        return;                              /* no state change */

    switch (p->delayMechanism) {
    case DM_COMMON_P2P:
    case DM_P2P:
        port_p2p_transition(p, p->state);    /* start timers, sends, ... */
        break;
    default:
        port_e2e_transition(p, p->state);
        break;
    }
    ...
}
```

`port_state_update` runs the machine and returns whether the state actually changed:

```c
int port_state_update(struct port *p, enum fsm_event event, int mdiff)
{
    enum port_state next = p->state_machine(p->state, event, mdiff);

    if (next == p->state)
        return 0;

    p->state = next;
    return 1;
}
```

The state machine is selected at port creation:

```c
p->state_machine = clock_slave_only(clock) ? ptp_slave_fsm : ptp_fsm;
```

Which port is *which* is decided separately by the BMCA orchestration (sections 3.4 and 3.10-3.13 cover the surrounding machinery, `port_compute_best`, `bmc_state_decision`, and `handle_state_decision_event`).

## Summary

- Nine states + one extension, seventeen events, all in `fsm.h`.
- `ptp_fsm` (lines 21-220) is the full machine; `ptp_slave_fsm` (lines 222-337) can't become master.
- The announce-timeout paths go directly to MASTER for ordinary ports; only the slave-only machine returns to LISTENING.
- `mdiff` guards the master-change transitions.
- state_machine is chosen once per clock; the port wrapper (`port_state_update`) owns timers and side effects.
