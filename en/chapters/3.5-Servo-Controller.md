# 3.5 The Servo Controller: The Art of Making a Clock Catch Its Master

## The servo's job

A PTP slave measures offsets. The clock servo turns that stream of offsets into clock corrections:

- phase: `clockadj_step()` or a slew,
- frequency: `clockadj_set_freq()`.

LinuxPTP implements the servo as a family behind a common interface.

## The servo framework (servo.h / servo_private.h / servo.c)

```c
/* servo_private.h */
struct servo {
    double max_frequency;
    double step_threshold;
    double first_step_threshold;
    int    first_update;
    int64_t offset_threshold;
    int    num_offset_values;
    int    curr_offset_values;

    int (*destroy)(struct servo *);
    double (*sample)(struct servo *, int64_t offset, uint64_t local_ts,
                    double weight, enum servo_state *state);
    void (*sync_interval)(struct servo *, double interval);
    void (*reset)(struct servo *);
    double (*rate_ratio)(struct servo *);
    void (*leap)(struct servo *, int leap);
};
```

Mount types via config:

| Type | Mount |
|:---|:---|
| PI | `pi_servo_create`: the default; a discretized PI controller |
| LINREG | `linreg_servo_create`: linear regression fit |
| NTPSHM | shares an NTP SHM segment (for ntpd) |
| NULLF | a null (no-op) servo |
| REFCLOCK_SOCK | sends PTP samples to an NTP refclock socket |

The common envelope (`servo.c`):

- `servo_create()` parses `step_threshold`, `first_step_threshold`, `max_frequency` and the offset thresholding.
- `servo_sample()` (servo.c:116-150) delegates to the concrete servo, then applies the framework's state bookkeeping:

```c
double servo_sample(struct servo *servo, int64_t offset, uint64_t local_ts,
                    double weight, enum servo_state *state)
{
    double r;

    r = servo->sample(servo, offset, local_ts, weight, state);

    switch (*state) {
    case SERVO_UNLOCKED:
        servo->curr_offset_values = servo->num_offset_values;
        break;
    case SERVO_JUMP:
        servo->curr_offset_values = servo->num_offset_values;
        servo->first_update = 0;
        break;
    case SERVO_LOCKED:
        if (check_offset_threshold(servo, offset))
            *state = SERVO_LOCKED_STABLE;
        servo->first_update = 0;
        break;
    case SERVO_LOCKED_STABLE:
        /* never reached: only this block sets LOCKED_STABLE */
        break;
    }

    return r;
}
```

`check_offset_threshold` (lines 100-114) passes through to `SERVO_LOCKED_STABLE` once the offset stays within `servo_offset_threshold` for `servo_num_offset_values` consecutive samples.

## The PI servo (pi.c)

### The model

A discretized PI controller (phase locked loop + frequency estimation):

```
ppb = kp × offset + ki × ∫offset + estimated drift
```

where `kp`, `ki` are the scaled gains, and the integral is accumulated every sample.

### pi_sample (pi.c, lines 64-155)

```
case 0 (no prior sample):
    remember offset[0], local[0]; return SERVO_UNLOCKED

case 1 (second sample — estimate frequency):
    if (local didn't advance) → SERVO_UNLOCKED, restart
    freq_est_interval = clamp(0.016 / ki, ..., 1000)
    drift += (1e9 − drift) × (offset[1] − offset[0]) / (local[1] − local[0])
    clamp drift to ±max_frequency
    if |offset| > step_threshold → SERVO_JUMP else SERVO_LOCKED
    ppb = drift; count → 2; done

case 2 and later (closed loop):
    weight per timer (default 1)
    if |offset| > step_threshold → SERVO_UNLOCKED, reset
    ki_term = ki × offset × weight
    ppb = kp × offset × weight + drift + ki_term
    clamp to ±max_frequency
    drift += ki_term
    SERVO_LOCKED
```

The accumulated `drift` doubles as the integral term, that's the I part.

### The adaptive gains

```c
double kp, ki;   /* scaled by sync length */
```

`pi_servo_create` reads the config:

```c
kp_scale   = config_get_float(cfg, "pi_proportional_scale");
ki_scale   = config_get_float(cfg, "pi_integral_scale");
kp_exp     = config_get_float(cfg, "pi_proportional_exponent");
ki_exp     = config_get_float(cfg, "pi_integral_exponent");
kp_norm    = config_get_float(cfg, "pi_proportional_norm_max");
ki_norm    = config_get_float(cfg, "pi_integral_norm_max");
```

and applies:

```
kp = kp_scale × interval^kp_exp
ki = ki_scale × interval^ki_exp
```

The actual defaults (config.c):

```
kp_scale   = 0.7 (HW) / 0.1 (SW)
kp_exponent = −0.3
ki_scale   = 0.3 (HW) / 0.001 (SW)
ki_exponent = 0.4
kp_norm_max = 0.7
ki_norm_max = 0.3
```

So by default the gains do adapt to the Sync interval, a longer interval shrinks kp and grows ki.

Fixed constants only if you set `pi_proportional_const`/`pi_integral_const` (then the exponents are forced to zero and kp/ki stop varying with the interval). `pi_*_norm_max` caps at 1.0 and 2.0 respectively.

### session interval

`pi_sync_interval(s, 0.5)` recomputes `kp` and `ki` from the Sync interval (`kp = kp_scale × interval^kp_exp`, capped by `kp_norm_max / interval`; likewise for `ki`). `max_frequency` from `servo_create` is respected via the clamped output.

## The linear-regression servo (linreg.c)

`linreg_servo` fits a line to the last `MAX_POINTS` (64) offset samples and returns the line's slope as the frequency correction, window sizes 4...64 (2²...2⁶). It has no phase output other than reset; it is a frequency estimator used by some deployments.

## What a servo reset does

On a *new* best master (fresh_best=1 → mdiff), `clock.c` calls `tsproc_reset(c->tsproc, 1)` and, on the slave, the servo is re-seeded (pi resets `count=0`, etc.). An old `drift` estimate must never be carried across grandmasters.

## Configuring a real deployment

```ini
[global]
step_threshold         0.00002    # 20 us ~ any bigger offset → step
first_step_threshold   0.00002    # step on first sample if big
max_frequency          900000000  # in ppb (default 900000000 = 0.9)
servo_offset_threshold 0          # 0 == never LOCKED_STABLE
servo_num_offset_values 10
```

For the PI specifically (example values; see the defaults above):

```ini
pi_proportional_scale 0.7
pi_proportional_exponent -0.3
pi_proportional_norm_max 0.7
pi_integral_scale 0.3
pi_integral_exponent 0.4
pi_integral_norm_max 0.3
```

## Summary

- The servo abstracts "offset → correction" behind a small interface; consumers only see `servo_sample()`.
- The PI controller (pi.c) is the default: proportional + integral, with drift serving as the integrator, and adaptive gains `kp_scale × interval^kp_exp`.
- Defaults: adaptive (exponent −0.3/0.4), clamped at ±max_frequency, jump for big offsets.
- Reset on master change, monotonic/none-backwards phase steering, and monitoring (`pj_`/`servo_offset_threshold`) complete the picture.
