# 3.6 PHC Operations and Clock Adjustment: Talking to the Hardware Clock

## From user space to kernel space

LinuxPTP runs in user space, but it has to operate the kernel's PTP hardware clock (PHC).

How does that work?

---

## The Linux PHC subsystem

### What a PHC is

```text
A PTP Hardware Clock (PHC) is a subsystem the Linux kernel provides:
- abstracts the various hardware clock devices
- provides one uniform user-space interface
- supports several operations: read, set, adjust

Device files:
/dev/ptp0   # first PHC device
/dev/ptp1   # second PHC device
...

List the PHCs on a system:
$ ls -l /dev/ptp*
crw-rw---- 1 root root 248, 0 Apr  1 10:00 /dev/ptp0
```

### The PHC kernel interface

```c
/* Linux kernel header <linux/ptp_clock.h> */

struct ptp_clock_caps {
    int max_adj;        /* maximum frequency adjustment (ppb) */
    int n_alarm;        /* number of alarms */
    int n_ext_ts;       /* number of external timestamp channels */
    int n_per_out;      /* number of periodic outputs */
    int pps;            /* whether PPS is supported */
    int n_pins;         /* number of pins */
    int cross_timestamping; /* whether cross timestamping is supported */
    int adjust_phase;   /* whether phase adjustment is supported */
    int max_phase_adj;  /* largest phase writable in phase adjustment mode (ns) */
    int rsv[11];        /* reserved for future expansion */
};
```

## PHC operation functions

### phc_open: opening a PHC device

```c
/* phc.c, lines 42-67 */

clockid_t phc_open(const char *phc)
{
    clockid_t clkid;
    struct timespec ts;
    struct timex tx;
    int fd;

    memset(&tx, 0, sizeof(tx));

    /* Step 1: open the device file */
    fd = open(phc, O_RDWR);
    if (fd < 0)
        return CLOCK_INVALID;

    /* Step 2: convert the file descriptor to a clockid_t */
    clkid = FD_TO_CLOCKID(fd);
    
    /* Step 3: check that the clockid is valid */
    if (clock_gettime(clkid, &ts)) {
        close(fd);
        return CLOCK_INVALID;
    }
    
    /* Step 4: check that the clock can be adjusted */
    if (clock_adjtime(clkid, &tx)) {
        close(fd);
        return CLOCK_INVALID;
    }

    return clkid;
}
```

**The FD_TO_CLOCKID macro**:

```c
/* missing.h, lines 49-51 */

#define CLOCKFD 3
#define FD_TO_CLOCKID(fd)	((clockid_t) ((((unsigned int) ~fd) << 3) | CLOCKFD))
#define CLOCKID_TO_FD(clk)	((unsigned int) ~((clk) >> 3))
```

**How it works**:

```text
The Linux clock API uses a clockid_t to identify a clock:
- CLOCK_REALTIME: the system real-time clock
- CLOCK_MONOTONIC: a monotonically increasing clock
- CLOCKFD: a dynamic clock (through a file descriptor)

Converting a PTP device file descriptor to a clockid_t:
1. open /dev/ptp0 → get fd (say fd=10)
2. FD_TO_CLOCKID(10) → clockid_t
3. call clock_gettime and friends with that clockid

That lets a user-space program treat a PHC like any ordinary clock!
```

### phc_max_adj: reading the maximum frequency adjustment

```c
/* phc.c, lines 87-101 and 77-85 (with phc_get_caps appended at the end) */

int phc_max_adj(clockid_t clkid)
{
    int max;
    struct ptp_clock_caps caps;

    /* fetch the capabilities with ioctl */
    if (phc_get_caps(clkid, &caps))
        return 0;

    max = caps.max_adj;

    /* special handling on 32-bit platforms */
    if (BITS_PER_LONG == 32 && max > MAX_PPB_32)
        max = MAX_PPB_32;

    return max;
}

static int phc_get_caps(clockid_t clkid, struct ptp_clock_caps *caps)
{
    int fd = CLOCKID_TO_FD(clkid), err;

    err = ioctl(fd, PTP_CLOCK_GETCAPS, caps);
    if (err)
        perror("PTP_CLOCK_GETCAPS");
    return err;
}
```

**The 32-bit platform limit**:

```c
/* phc.c, lines 37-38 */

#define BITS_PER_LONG   (sizeof(long)*8)
#define MAX_PPB_32      32767999  /* 2^31 - 1 / 65.536 */
```

```text
Why is this limit needed?

struct timex {
    long freq;    /* frequency offset: ppm scaled by 2^16, that is ppb × 65.536 */
    ...
};

(The 65.536 factor appears three times in clockadj.c: ×65.536 when setting (:64),
 ÷65.536 when reading (:81), and ÷65.536 when computing the maximum capability (:138))

On a 32-bit platform long is 32 bits, range ±2^31
Maximum: (2^31 - 1) / 65.536 ≈ 32,767,999 ppb

If the PHC hardware supports a wider adjustment range, it has to be clamped to this value.
```

### phc_has_pps: checking PPS support

```c
/* phc.c, lines 122-129 */

int phc_has_pps(clockid_t clkid)
{
    struct ptp_clock_caps caps;

    if (phc_get_caps(clkid, &caps))
        return 0;
    
    return caps.pps;
}
```

**PPS (Pulse Per Second)**:

```text
PPS is a hardware signal:
- generates one pulse per second
- accuracy down to nanoseconds
- used for precise time synchronization

Uses:
- input from an external time source (GPS)
- timestamp triggering
- frequency calibration

LinuxPTP can use PPS:
- if the PHC supports PPS
- it can take precise time from an external source
- improving synchronization accuracy
```

### phc_has_writephase: checking phase adjustment support

```c
/* phc.c, lines 131-139 */

int phc_has_writephase(clockid_t clkid)
{
    struct ptp_clock_caps caps;

    if (phc_get_caps(clkid, &caps)) {
        return 0;
    }
    
    return caps.adjust_phase;
}
```

**Phase adjustment capability**:

```text
Traditional frequency adjustment:
- works by adjusting the oscillator frequency
- phase changes accumulate
- good for long-term stability

Phase adjustment (writing phase in hardware):
- changes the clock phase directly
- does not change frequency
- takes effect immediately, no accumulated error

Hardware with adjust_phase:
- can adjust phase more precisely
- enables a "one-step" clock
- suits high-precision scenarios
```

## Clock adjustment functions

### clockadj_set_freq: setting the frequency

```c
/* clockadj.c, lines 51-70 */

int clockadj_set_freq(clockid_t clkid, double freq)
{
    struct timex tx;
    memset(&tx, 0, sizeof(tx));

    /* special handling for the system clock */
    if (clkid == CLOCK_REALTIME && realtime_nominal_tick) {
        tx.modes |= ADJ_TICK;
        tx.tick = round(freq / 1e3 / realtime_hz) + realtime_nominal_tick;
        freq -= 1e3 * realtime_hz * (tx.tick - realtime_nominal_tick);
    }

    /* set the frequency */
    tx.modes |= ADJ_FREQUENCY;
    tx.freq = (long) (freq * 65.536);
    
    if (clock_adjtime(clkid, &tx) < 0) {
        pr_err("failed to adjust the clock: %m");
        return -1;
    }
    return 0;
}
```

**The unit conversion for frequency adjustment**:

```text
Input: freq (ppb, parts per billion)
Kernel: tx.freq (unit: ppb × 65.536)

Conversion formula:
tx.freq = freq × 65.536

Why 65.536?

Historical reason: NTP uses "SHIFT_HZ = 16"
The freq field is ppm (parts per million) scaled by 2^16
1 ppm = 1000 ppb
So: tx.freq = freq_ppb × 2^16 / 1000
             = freq_ppb × 65.536

Example:
freq = 100 ppb
tx.freq = (long) (100 × 65.536) = 6553
```

**Special handling for the system clock**:

```c
if (clkid == CLOCK_REALTIME && realtime_nominal_tick) {
    tx.modes |= ADJ_TICK;
    tx.tick = round(freq / 1e3 / realtime_hz) + realtime_nominal_tick;
    freq -= 1e3 * realtime_hz * (tx.tick - realtime_nominal_tick);
}
```

```text
Why does the system clock need special handling?

The system clock (CLOCK_REALTIME):
- is based on the kernel tick
- the tick length can be adjusted
- allows a wider frequency adjustment range

Method:
1. adjust the tick length (coarse)
2. adjust the freq field (fine)
3. combine the two to widen the range

Example (the numbers below assume hz=1000; neither value is fixed, both depend on the kernel configuration):
realtime_hz = sysconf(_SC_CLK_TCK), that is USER_HZ in the kernel (clockadj.c:41; 100 in most Linux configurations, but also 250/1000)
realtime_nominal_tick = (1000000 + hz/2)/hz microseconds (clockadj.c:44-45; 1000 when hz=1000)

freq = 1e8 ppb (a large 10% deviation, the only case that needs the coarse tick)

Coarse:
tx.tick = round(1e8 / 1e3 / 1000) + 1000 = 1100 microseconds
(the tick goes from 1000 microseconds to 1100 microseconds, a 10% faster frequency)

Fine:
freq -= 1e3 × 1000 × (1100 - 1000) = 1e8
(all 10% is carried by the tick, the freq field is left at 0)

Result:
the tick performs the coarse 10% adjustment
the freq field only has to fine-tune the remainder
```

### clockadj_get_freq: reading the current frequency

```c
/* clockadj.c, lines 72-86 */

double clockadj_get_freq(clockid_t clkid)
{
    double f = 0.0;
    struct timex tx;
    memset(&tx, 0, sizeof(tx));
    
    if (clock_adjtime(clkid, &tx) < 0) {
        pr_err("failed to read out the clock frequency adjustment: %m");
        exit(1);
    } else {
        f = tx.freq / 65.536;
        if (clkid == CLOCK_REALTIME && realtime_nominal_tick && tx.tick)
            f += 1e3 * realtime_hz * (tx.tick - realtime_nominal_tick);
    }
    return f;
}
```

**The reverse conversion**:

```text
Unit conversion when reading:
freq_ppb = tx.freq / 65.536

For the system clock, add the tick adjustment back:
freq_ppb += 1e3 × hz × (tick - nominal_tick)
```

### clockadj_set_phase: setting the phase offset

```c
/* clockadj.c, lines 88-100 */

int clockadj_set_phase(clockid_t clkid, long offset)
{
    struct timex tx;
    memset(&tx, 0, sizeof(tx));

    tx.modes = ADJ_OFFSET | ADJ_NANO;
    tx.offset = offset;
    
    if (clock_adjtime(clkid, &tx) < 0) {
        pr_err("failed to set the clock offset: %m");
        return -1;
    }
    return 0;
}
```

**What ADJ_OFFSET does**:

```text
ADJ_OFFSET mode:
- sets the phase offset
- the clock adjusts gradually, it does not jump at once
- uses the kernel PLL

Parameters:
tx.offset = offset (nanoseconds here)
ADJ_NANO (missing.h:37-39, value 0x2000) says to interpret offset in nanoseconds;
without this flag tx.offset is in microseconds — see the struct timex comments below

How it works:
- the clock is offset nanoseconds
- the kernel gradually removes the offset
- the rate is controlled by time_constant

Where it applies:
- small offsets (microseconds)
- smooth adjustment, doesn't disturb applications
- in ptp4l it only happens on the write_phase_mode + SERVO_LOCKED_STABLE path (clock.c:2076-2081)
```

### clockadj_step: stepping the clock

```c
/* clockadj.c, lines 102-127 */

int clockadj_step(clockid_t clkid, int64_t step)
{
    struct timex tx;
    int sign = 1;
    if (step < 0) {
        sign = -1;
        step *= -1;
    }
    memset(&tx, 0, sizeof(tx));
    
    tx.modes = ADJ_SETOFFSET | ADJ_NANO;
    tx.time.tv_sec  = sign * (step / NS_PER_SEC);
    tx.time.tv_usec = sign * (step % NS_PER_SEC);
    
    /* make sure tv_usec is non-negative */
    if (tx.time.tv_usec < 0) {
        tx.time.tv_sec  -= 1;
        tx.time.tv_usec += 1000000000;
    }
    
    if (clock_adjtime(clkid, &tx) < 0) {
        pr_err("failed to step clock: %m");
        return -1;
    }
    return 0;
}
```

**What a clock step means**:

```text
ADJ_SETOFFSET mode:
- changes the clock value immediately
- time "jumps" to the new value
- can break applications

Parameters:
step = +1000000000: the clock jumps forward 1 second
step = -1000000000: the clock jumps back 1 second

Handling a negative step:
1. step = -1500000000 (-1.5 seconds)
2. sign = -1
3. step = 1500000000
4. tx.time.tv_sec = -1
5. tx.time.tv_usec = -500000000
6. adjust: tv_sec -= 1, tv_usec += 1000000000
   → tv_sec = -2, tv_usec = 500000000

Note:
tx.time is a timeval:
struct timeval {
    time_t tv_sec;    /* seconds */
    suseconds_t tv_usec; /* microseconds */
};

The field is named tv_usec, but under ADJ_NANO its meaning is nanoseconds:
the code writes the nanosecond remainder of step divided by NS_PER_SEC (clockadj.c:111-113),
so tv_usec ranges over [0, 999999999].
```

**set_phase vs step**:

```text
set_phase:
- gradual adjustment
- the PLL slowly removes the offset
- no time jump
- good for small offsets

step:
- jumps immediately
- changes the time directly
- can break applications
- good for large offsets

How to choose (clock_synchronize, clock.c:2007-2107; the switch branches are at :2052-2088):
- normal tracking with a small offset: the PI controller estimates the frequency and calls clockadj_set_freq, not set_phase
- |offset| above step_threshold (or first_step_threshold on the first pass) → the servo returns SERVO_JUMP and clockadj_step jumps the clock
- clockadj_set_phase is used only with write_phase_mode and state SERVO_LOCKED_STABLE (clock.c:2076-2079)
```

## The clock_adjtime system call

### Function prototype

```c
#include <sys/timex.h>

int clock_adjtime(clockid_t clkid, struct timex *tx);
```

**This is a Linux-specific system call**:

```text
Standard POSIX:
clock_gettime: read the time
clock_settime: set the time

Linux extension:
clock_adjtime: advanced clock adjustment
- set the frequency
- set the phase
- step the clock
- read the status

That lets a user-space program control the clock precisely!
```

### The struct timex structure

```c
/* <sys/timex.h> */

struct timex {
    int  modes;           /* mode selection */
    long offset;         /* phase offset: microseconds by default; nanoseconds only with ADJ_NANO */
    long freq;           /* frequency offset: ppm scaled by 2^16, that is ppb × 65.536 */
    long maxerror;        /* maximum error */
    long esterror;        /* estimated error */
    int  status;          /* clock status */
    long constant;        /* PLL time constant */
    long precision;       /* clock precision */
    long tolerance;       /* clock tolerance (maximum frequency deviation) */
    struct timeval time;  /* current time */
    long tick;            /* microseconds per clock tick */
    long ppsfreq;         /* PPS frequency */
    long jitter;          /* PPS jitter */
    int  shift;           /* PPS interval duration */
    long stabil;          /* PPS stability */
    long jitcnt;          /* PPS jitter limit exceeded count */
    long calcnt;          /* PPS calibration interval */
    long errcnt;          /* PPS calibration errors */
    long stbcnt;          /* PPS stability limit exceeded */
    int  tai;             /* TAI offset */
};
```

### The modes field in detail

```c
/* bit definitions for modes */

#define ADJ_OFFSET        0x0001  /* set the phase offset */
#define ADJ_FREQUENCY     0x0002  /* set the frequency */
#define ADJ_MAXERROR      0x0004  /* set the maximum error */
#define ADJ_ESTERROR      0x0008  /* set the estimated error */
#define ADJ_STATUS        0x0010  /* set the status */
#define ADJ_TIMECONST     0x0020  /* set the time constant */
#define ADJ_TAI           0x0080  /* set the TAI offset */
#define ADJ_SETOFFSET     0x0100  /* step the clock */
#define ADJ_MICRO         0x1000  /* microsecond resolution */
#define ADJ_NANO          0x2000  /* nanosecond resolution */
#define ADJ_TICK          0x4000  /* set the tick length */
```

**Common mode combinations**:

```c
/* set the frequency */
tx.modes = ADJ_FREQUENCY;

/* set the phase (nanoseconds) */
tx.modes = ADJ_OFFSET | ADJ_NANO;

/* step the clock (nanoseconds) */
tx.modes = ADJ_SETOFFSET | ADJ_NANO;

/* read the current state */
tx.modes = 0;  /* modify nothing, just read */
```

This chapter is about "how to adjust one clock". Moving the PHC's time onto the system clock is the job of another program, `phc2sys`, and **it has a section of its own (3.11)**. This section keeps just a minimal example and doesn't go into the details.


The three parameters:

```text

 -s [dev|name]  time source device                      time source
 -w             wait for ptp4l                          wait for ptp4l
```

## A practical example

### Using a PHC in LinuxPTP

```c
/* clock.c:1081-1445, rewritten: keep only the thread "which clock + where the maximum frequency range comes from + how the servo is built" */

struct clock *clock_create(enum clock_type type, struct config *config,
                           const char *phc_device)
{
    int max_adj = 0, phc_index, sw_ts;   /* clock.c:1084: max_adj is a local variable */
    char phc[32];
    struct clock *c = &the_clock;        /* clock.c:1088: a static singleton, not calloc'd */
    double fadj = 0.0;

    /* ... here the source first determines phc_index (clock.c:1206-1228):
       free_running or software/legacy timestamping → -1;
       phc_device of the form "/dev/ptpN" → sscanf out N;
       config option phc_index >= 0 → use it;
       otherwise probe the NIC tsinfo, and fail with NULL if that fails ... */

    /* four mutually exclusive branches: pick the clock, and take "how far it can adjust" from each (clock.c:1296-1328) */
    if (c->free_running) {                 /* (1) free_running config option */
        c->clkid = CLOCK_INVALID;          /* touch no clock, and no fallback either */
        if (timestamping == TS_SOFTWARE || timestamping == TS_LEGACY_HW)
            c->utc_timescale = 1;
    } else if (phc_index >= 0) {           /* (2) an explicit /dev/ptpN */
        snprintf(phc, sizeof(phc), "/dev/ptp%d", phc_index);
        c->clkid = phc_open(phc);
        if (c->clkid == CLOCK_INVALID) {
            pr_err("Failed to open %s: %m", phc);
            return NULL;                   /* fail if it can't be opened, never quietly swap clocks */
        }
        max_adj = phc_max_adj(c->clkid);   /* ← only this branch uses phc_max_adj() */
        if (!max_adj) {
            pr_err("clock is not adjustable");
            return NULL;
        }
        clockadj_init(c->clkid);
    } else if (phc_device) {               /* (3) a device name was given, but not in /dev/ptpN form */
        c->clkid = phc_open(phc_device);
        if (c->clkid == CLOCK_INVALID) {
            pr_err("Failed to open %s: %m", phc_device);
            return NULL;
        }
        max_adj = clockadj_max_freq(c->clkid);  /* ← this branch uses clockadj_max_freq() */
        clockadj_init(c->clkid);
    } else {                               /* (4) nothing at all: the system clock */
        c->clkid = CLOCK_REALTIME;
        c->utc_timescale = 1;
        clockadj_init(c->clkid);
        max_adj = sysclk_max_freq();            /* ← this branch uses sysclk_max_freq() */
        sysclk_set_leap(0);
    }

    /* read out "the adjustment already applied to this clock"; stays 0 when CLOCK_INVALID */
    if (c->clkid != CLOCK_INVALID)
        fadj = clockadj_get_freq(c->clkid);      /* clock.c:1333-1334 */

    /* note the third argument is -fadj (negated) */
    c->servo = servo_create(c->config, servo, -fadj, max_adj, sw_ts);  /* :1341 */

    /* ... only after this come tsproc, ports, UDS and so on (clock.c:1346-1444) ... */
}
```

### The clock adjustment flow

```c
/* clock.c:2007-2107, rewritten: keep the trunk, drop the free_running bypass, stats and event notifications */

enum servo_state clock_synchronize(struct clock *c, tmv_t ingress, tmv_t origin)
{
    enum servo_state state = SERVO_UNLOCKED;     /* clock.c:2009 */
    double adj, weight;
    int64_t offset;

    /* for a few ticks after a step, return the previous state and adjust nothing */
    if (c->step_window_counter) {                /* clock.c:2013-2019 */
        c->step_window_counter--;
        return c->servo_state;
    }

    c->ingress_ts = ingress;

    /* offset is not tmv_sub(ingress, origin); tsproc computes it from the delay model,
       and hands back this tick's weight as a side product */
    tsproc_down_ts(c->tsproc, origin, ingress);                     /* :2023 */
    if (tsproc_update_offset(c->tsproc, &c->master_offset, &weight)) {  /* :2025 */
        return state;            /* delay not measured yet, nothing to do this tick */
    }

    if (clock_utc_correct(c, ingress))    /* leave the clock alone on a UTC/leap tick */
        return c->servo_state;

    offset = tmv_to_nanoseconds(c->master_offset);                  /* :2045 */
    adj = servo_sample(c->servo, offset, tmv_to_nanoseconds(ingress),
                       weight, &state);                             /* :2046-2047 */
    c->servo_state = state;

    tsproc_set_clock_rate_ratio(c->tsproc, clock_rate_ratio(c));     /* :2050 */

    switch (state) {                                                /* :2052 */
    case SERVO_UNLOCKED:
        break;                               /* the servo isn't ready, do nothing */
    case SERVO_JUMP:
        if (clockadj_set_freq(c->clkid, -adj))    /* (1) set the frequency first :2056 */
            goto servo_unlock;
        if (clockadj_step(c->clkid, -offset))     /* (2) then step the phase :2059 */
            goto servo_unlock;
        c->ingress_ts = tmv_zero();
        tsproc_reset(c->tsproc, 0);               /* :2068 */
        clock_step_window(c);                     /* :2069 start the skip counter */
        break;
    case SERVO_LOCKED:
        if (clock_synchronize_locked(c, adj))     /* frequency only :2071-2074 */
            goto servo_unlock;
        break;
    case SERVO_LOCKED_STABLE:
        if (c->write_phase_mode) {                /* write phase mode :2076-2081 */
            if (clockadj_set_phase(c->clkid, -offset))
                goto servo_unlock;
            adj = 0;
        } else {                                  /* otherwise frequency only as well :2082-2086 */
            if (clock_synchronize_locked(c, adj))
                goto servo_unlock;
        }
        break;
    }

    /* ... the source also updates stats, prints pr_info("master offset …") and calls
       clock_notify_event(NOTIFY_TIME_SYNC) (clock.c:2090-2099) ... */

    return state;

servo_unlock:                                     /* clock.c:2103-2106 */
    servo_reset(c->servo);        /* every failed clockadj_* lands here */
    c->servo_state = SERVO_UNLOCKED;
    return SERVO_UNLOCKED;
}
```

Both the `SERVO_LOCKED` branch and the normal `SERVO_LOCKED_STABLE` branch call `clock_synchronize_locked()`, and the negation of the frequency adjustment is inside it (`clock.c:1995`). Worth pasting on its own:

```c
/* clock.c:1990-2005, complete source */

static int clock_synchronize_locked(struct clock *c, double adj)
{
    if (c->sanity_check) {
        clockcheck_freq(c->sanity_check, clockadj_get_freq(c->clkid));
    }
    if (clockadj_set_freq(c->clkid, -adj)) {     /* ← the negation is here */
        return -1;
    }
    if (c->clkid == CLOCK_REALTIME) {
        sysclk_set_sync();
    }
    if (c->sanity_check) {
        clockcheck_set_freq(c->sanity_check, -adj);
    }
    return 0;
}
```

```bash
$ phc_ctl /dev/ptp0 -- set 1640995200.000000000

# adjust the PHC frequency
$ phc_ctl /dev/ptp0 -- freq 100.0  # +100 ppb
```

## Summary: the key points of PHC operations

**The bridge from user space to kernel space**:
- file descriptor → clockid_t
- the standard clock API operates the PHC

**Key functions**:
- phc_open/close: open/close the device
- clockadj_set_freq: set the frequency (and tick the system clock along the way)
- clockadj_set_phase: set the phase (only in write phase mode)
- clockadj_step: step the clock
- clockadj_init / clockadj_max_freq: where the tick mechanism comes from, and the maximum frequency range
- sysclk_set_leap / sysclk_set_tai_offset / sysclk_set_sync: leap second, TAI and STA_UNSYNC handling for the system clock only

**System calls**:
- clock_adjtime: the core system call
- struct timex: a rich set of control parameters

**Three adjustment paths** (one-to-one with the branches at clock.c:2052-2088):
- frequency `clockadj_set_freq()`: `SERVO_LOCKED`, and the normal `SERVO_LOCKED_STABLE` path when not in write phase mode
- phase `clockadj_set_phase()`: only with `write_phase_mode` and `SERVO_LOCKED_STABLE` (`clock.c:2076-2079`)
- immediate step `clockadj_step()`: only on `SERVO_JUMP`, and **set_freq first, then step** (`clock.c:2056` → `:2059`)
