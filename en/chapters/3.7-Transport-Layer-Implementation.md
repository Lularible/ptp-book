# 3.7 Transport Layer Implementation: The Highway for PTP Messages

## The transport abstraction

LinuxPTP abstracts the network path behind `struct transport`: independent implementations for each medium share one interface.

```c
/* transport.h */
enum transport_type {
    TRANS_UDS = 0,
    TRANS_UDP_IPV4 = 1,
    TRANS_UDP_IPV6,
    TRANS_IEEE_802_3,
    TRANS_DEVICENET,
    TRANS_CONTROLNET,
    TRANS_PROFINET,
};

enum transport_event {
    TRANS_GENERAL,
    TRANS_EVENT,
    TRANS_ONESTEP,
    TRANS_P2P1STEP,
    TRANS_DEFER_EVENT,
};
```

```c
/* transport_private.h */
struct transport {
    enum transport_type type;
    struct config *cfg;
    int (*close)(struct transport *t, struct fdarray *fda);
    int (*open)(struct transport *t, struct interface *iface,
                struct fdarray *fda, enum timestamp_type tt);
    int (*recv)(struct transport *t, int fd, void *buf, int buflen,
                struct address *addr, struct hw_timestamp *hwts);
    int (*send)(struct transport *t, struct fdarray *fda,
                enum transport_event event, int peer, void *buf, int buflen,
                struct address *addr, struct hw_timestamp *hwts);
    void (*release)(struct transport *t);
    int (*physical_addr)(struct transport *t, uint8_t *addr);
    int (*protocol_addr)(struct transport *t, uint8_t *addr);
};
```

The generic functions in `transport.c` (`transport_open`, `transport_recv`, `transport_send`, `transport_peer`) simply call the vtable.

## UDP/IPv4 (udp.c)

### The well-known addresses

| Purpose | group address | port |
|:---|:---|:---|
| Event messages (Sync, Delay_Req, ...) | 224.0.1.129 | 319 |
| General messages (Announce, Follow_Up, ...) | 224.0.1.129 | 320 |
| PTP-over-UDP peer (P2P) | 224.0.0.107 | 319/320 |

(`ptp_dst_ipv4` / `p2p_dst_ipv4` in the config control the multicast groups.)

### mcast_join (udp.c, lines 63-82)

```c
static int mcast_join(int fd, int ifindex, const struct sockaddr_in *sa)
{
    int off = 0;
    struct ip_mreqn req;

    memset(&req, 0, sizeof(req));
    memcpy(&req.imr_multiaddr, &sa->sin_addr, sizeof(sa->sin_addr));
    req.imr_ifindex = ifindex;
    if (setsockopt(fd, IPPROTO_IP, IP_ADD_MEMBERSHIP, &req, sizeof(req)))
        return -1;
    /* disable loopback so our own multicast is not echoed back to us */
    return setsockopt(fd, IPPROTO_IP, IP_MULTICAST_LOOP, &off, sizeof(off));
}
```

### open_socket (udp.c, lines 91-145)

1. `socket(AF_INET, SOCK_DGRAM, 0)`.
2. `sk_interface_index()` to find the interface.
3. `SO_REUSEADDR` + `bind` to the port.
4. `SO_BINDTODEVICE` to pin the interface.
5. Set `IP_MULTICAST_TTL`.
6. Join the event and general multicast groups.
7. `mcast_bind(fd, ifindex)` to choose the multicast egress interface.

The two sockets (event → 319, general → 320) are returned in the `fdarray`.

## Raw Ethernet (raw.c)

For PTP over IEEE 802.3 (EtherType 0x88F7), the frame is wrapped with its own headers:

```
PTP over raw Ethernet:
[destination MAC 6][source MAC 6][EtherType 0x88F7][PTP message]
```

The PTP Layer-2 primary multicast MAC is `01:1B:19:00:00:00`; the P2P MAC is `01:80:C2:00:00:0E` (configured via `ptp_dst_mac` / `p2p_dst_mac`).

### The BPF filter (raw.c)

A classic BPF program limits what the event/general sockets pass to the kernel, so strange frames never wake userspace. The general filter matches messages with header bit 3 SET (`& 0x8 == 0x8`):

```
static struct sock_filter raw_filter_vlan_norm_general[] = {
    /* (000) ldh  [12]  -- EtherType */
    /* (001) jeq  #0x8100 (VLAN TPID) */
    /* ... */
    /* (004) ldb  [18]; and #0x8; jeq #0x8 jt 4 jf 9  -- bit3 SET => general */
    /* ... */
    /* (015) ret  #262144   (accept) */
    /* (016) ret  #0        (drop) */
};
```

The event filter (raw.c, lines 131-149) instead accepts only messages with header bit 3 CLEAR (`& 0x8 != 0x8`, event messages 0x0-0x3). Note the `jt`/`jf` (jump-if-true/if-false) fields are swapped between the two filters, that's the one subtle trap when transcribing them.

### raw_configure (raw.c, lines 154-228)

1. Install the BPF filter via `SO_ATTACH_FILTER`.
2. Patch the filter's source-MAC comparisons with the local address.
3. Add multicast memberships (`PACKET_ADD_MEMBERSHIP`).
4. Fall back to `PACKET_MR_ALLMULTI` then `PACKET_MR_PROMISC` if needed.

## Unix-domain sockets (uds.c)

`TRANS_UDS` moves management traffic over a Unix-domain socket, no IP at all. `pmc -u` uses this to talk to a locally running ptp4l without any networking. The addresses default to `/var/run/ptp4l` (read/write) and `/var/run/ptp4lro` (read-only).

## Socket helpers (sk.c)

### sk_timestamping_init (sk.c, lines 560-650)

Maps the desired `enum timestamp_type` onto `SO_TIMESTAMPING` flags and driver config:

```c
int sk_timestamping_init(int fd, const char *device, enum timestamp_type type,
                         enum transport_type transport, int vclock)
{
    int flags = 0, filter = 0, tx_type = 0;
    struct so_timestamping timestamping;
    int err = 0;

    switch (type) {
    case TS_SOFTWARE:
        flags |= SOF_TIMESTAMPING_RX_SOFTWARE | SOF_TIMESTAMPING_TX_SOFTWARE
              | SOF_TIMESTAMPING_SOFTWARE;
        break;
    case TS_HARDWARE:
    case TS_ONESTEP:
    case TS_P2P1STEP:
        flags |= SOF_TIMESTAMPING_RX_HARDWARE | SOF_TIMESTAMPING_TX_HARDWARE
              | SOF_TIMESTAMPING_RAW_HARDWARE;
        switch (type) {
        case TS_HARDWARE: tx_type = HWTSTAMP_TX_ON; break;
        ...
        case TS_P2P1STEP: tx_type = HWTSTAMP_TX_ONESTEP_P2P; break;
        }
        break;
    ...
    }
    ...
    if (type != TS_SOFTWARE)
        err = hwts_init(fd, device, filter, filter2, tx_type);
    ...
    timestamping.flags = flags;
    timestamping.bind_phc = vclock;
    if (setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING,
                   &timestamping, sizeof(timestamping))) ...
    if (setsockopt(fd, SOL_SOCKET, SO_SELECT_ERR_QUEUE, &flags, sizeof(int))) ...
    return err;
}
```

`hwts_init` (sk.c, lines 59-136) talks to the driver with `SIOCSHWTSTAMP`; if the most-general filter is rejected, it retries with a fallback filter, then verifies the accepted configuration.

## Reading timestamps back

On receive, `recvmsg()` returns ancillary data:

- `SO_TIMESTAMPING` → `struct timespec ts[3]`: ts[0] software, ts[1] "SYS_HARDWARE" (legacy, system-clock domain), ts[2] RAW_HARDWARE (PHC domain).
- `SO_TIMESTAMPNS` → the software receive timestamp (stored in `hwts->sw`).

The selection by type is straightforward (TS_HARDWARE → ts[2], etc.).

On transmit, the NIC's timestamp arrives through the error queue:

```
poll(fd, POLLERR/POLLIN, tx_timeout);
recvmsg(fd, &msg, MSG_ERRQUEUE);   /* the timestamp rides back on the sent frame */
```

`sk_tx_timeout` is set from the `tx_timestamp_timeout` config option, whose default is 10 ms (the static initializer of 1 is overwritten at startup).

## The multicast traffic split

PTP sends event messages (`SYNC`, `DELAY_REQ`, `PDELAY_REQ`, `PDELAY_RESP`) over the event socket (UDP 319); general messages (`ANNOUNCE`, `FOLLOW_UP`, `DELAY_RESP`, `SIGNALING`, `MANAGEMENT`) over the general socket (UDP 320). The transport's `send` with `event`/`general` selects the socket.

## One-step and the 2-byte checksum slack

For one-step operation (`TRANS_ONESTEP`), the hardware rewrites `originTimestamp` on the wire. Since UDP checksums cover the payload, the NIC needs room to fold in the correction:

```c
if (event == TRANS_ONESTEP)
    len += 2;   /* reserve two bytes for the on-the-fly checksum correction */
```

(udp.c), a detail that trips up anyone porting the code to a NIC that can't do it.

## Summary

- A small vtable (`transport.c`) unifies UDP/IPv4, UDP/IPv6, raw Ethernet, and UDS.
- Multicast groups and ports 319/320 are per-transport constants; the BPF filter keeps the kernel quiet.
- `sk.c` maps timestamp types to `SO_TIMESTAMPING` flags and drives `SIOCSHWTSTAMP`.
- Receive timestamps come in ancillary data; transmit timestamps come back through the error queue.
