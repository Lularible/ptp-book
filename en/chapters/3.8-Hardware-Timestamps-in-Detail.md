# 3.8 Hardware Timestamps in Detail: The Magic of Nanosecond Precision

## Why timestamps decide everything

For PTP, the offset computation assumes t1 and t2 are the exact instants the Sync crossed the wire. If they're off by a microsecond, so is the offset.

- Software timestamps, captured in the kernel stack (interrupts, scheduling), carry 100-1000 ns of jitter.
- Hardware timestamps, latched at the PHY, carry <10 ns of error.

That factor-of-a-100 difference is the difference between "good enough" and "PTP."

## The timestamp types (util.h / msg.h)

```c
enum timestamp_type {
    TS_SOFTWARE,     /* software timestamps */
    TS_HARDWARE,     /* PHY hardware timestamps */
    TS_LEGACY_HW,    /* legacy hardware timestamps ("sys" domain) */
    TS_ONESTEP,      /* one-step clock (Sync) */
    TS_P2P1STEP,     /* one-step clock (peer-to-peer) */
};
```

### ts_str (util.c, line 74)

```c
const char *ts_str(enum timestamp_type ts)
{
    switch (ts) {
    case TS_SOFTWARE:  return "SOFTWARE";
    case TS_HARDWARE:  return "HARDWARE";
    case TS_LEGACY_HW: return "LEGACY_HW";
    case TS_ONESTEP:   return "ONESTEP";
    case TS_P2P1STEP:  return "P2P1STEP";
    }
    return "???";
}
```

The strings are uppercase and appear verbatim in logs (e.g., `tx timestamp from PHY with TS_HARDWARE`).

## The kernel flags (net_tstamp.h)

The `SO_TIMESTAMPING` bit assignments (as of kernel 5.15):

```c
#define SOF_TIMESTAMPING_TX_HARDWARE   (1<<0)
#define SOF_TIMESTAMPING_TX_SOFTWARE   (1<<1)
#define SOF_TIMESTAMPING_RX_HARDWARE   (1<<2)
#define SOF_TIMESTAMPING_RX_SOFTWARE   (1<<3)
#define SOF_TIMESTAMPING_SOFTWARE      (1<<4)
#define SOF_TIMESTAMPING_SYS_HARDWARE  (1<<5)   /* legacy "sys" domain */
#define SOF_TIMESTAMPING_RAW_HARDWARE  (1<<6)
#define SOF_TIMESTAMPING_OPT_ID        (1<<7)
#define SOF_TIMESTAMPING_TX_SCHED      (1<<8)
#define SOF_TIMESTAMPING_TX_ACK        (1<<9)
#define SOF_TIMESTAMPING_OPT_CMSG      (1<<10)
#define SOF_TIMESTAMPING_OPT_TSONLY    (1<<11)
#define SOF_TIMESTAMPING_OPT_STATS     (1<<12)
#define SOF_TIMESTAMPING_OPT_PKTINFO   (1<<13)
#define SOF_TIMESTAMPING_OPT_TX_SWHW   (1<<14)
#define SOF_TIMESTAMPING_BIND_PHC      (1<<15)  /* virtual clock binding */
```

There is no `SOF_TIMESTAMPING_OPT_TSONESTEP`. One-step isn't configured with SO_TIMESTAMPING flags at all, it's set through the driver ioctls `HWTSTAMP_TX_ONESTEP_SYNC` / `HWTSTAMP_TX_ONESTEP_P2P` (see below).

Typical combinations:

```
software: TX_SOFTWARE | RX_SOFTWARE | SOFTWARE
hardware: TX_HARDWARE | RX_HARDWARE | RAW_HARDWARE
legacy:   TX_HARDWARE | RX_HARDWARE | SYS_HARDWARE
```

## Configuring the driver: hwts_init (sk.c, lines 59-136)

The driver ioctl takes a `struct hwtstamp_config`:

```c
struct hwtstamp_config {
    int flags;
    int tx_type;      /* enum hwtstamp_tx_types */
    int rx_filter;    /* enum hwtstamp_rx_filters */
};
```

`hwts_init`:

1. Query the current config (`SIOCGHWTSTAMP`), tolerating `EINVAL`/`EOPNOTSUPP`.
2. According to `sk_hwts_filter_mode`:
   - `HWTS_FILTER_CHECK`: only check, don't change.
   - `HWTS_FILTER_FULL`: set `rx_filter = HWTSTAMP_FILTER_ALL`.
   - `HWTS_FILTER_NORMAL`: try the requested filter, and on failure retry a fallback filter (`rx_filter2`).
3. Verify the accepted configuration matches what was asked for.

The tx type and the rx filter are chosen independently. The tx type follows the timestamp type:

```
TS_HARDWARE / TS_LEGACY_HW    → HWTSTAMP_TX_ON
TS_ONESTEP                    → HWTSTAMP_TX_ONESTEP_SYNC
TS_P2P1STEP                   → HWTSTAMP_TX_ONESTEP_P2P
```

For every non-software type the rx filter is:

```
filter1 = HWTSTAMP_FILTER_PTP_V2_EVENT
filter2 = HWTSTAMP_FILTER_PTP_V2_L4_EVENT   (UDP)
        / HWTSTAMP_FILTER_PTP_V2_L2_EVENT   (IEEE 802.3)
```

And `sk_timestamping_init` does the socket side: build `struct so_timestamping { flags; bind_phc; }`, call `setsockopt(SO_TIMESTAMPING, ...)`, then `SO_SELECT_ERR_QUEUE`.

## Reading receive timestamps

```c
for (cm = CMSG_FIRSTHDR(&msg); cm; cm = CMSG_NXTHDR(&msg, cm)) {
    level = cm->cmsg_level;
    type  = cm->cmsg_type;

    if (SOL_SOCKET == level && SO_TIMESTAMPING == type)
        ts = (struct timespec *) CMSG_DATA(cm);   /* ts[0..2] */

    if (SOL_SOCKET == level && SO_TIMESTAMPNS == type) {
        sw = (struct timespec *) CMSG_DATA(cm);
        hwts->sw = timespec_to_tmv(*sw);
    }
}

switch (hwts->type) {
case TS_SOFTWARE:      hwts->ts = ts0; break;
case TS_HARDWARE:
case TS_ONESTEP:
case TS_P2P1STEP:      hwts->ts = ts2; break;   /* raw PHC domain */
case TS_LEGACY_HW:     hwts->ts = ts1; break;   /* sys domain */
}
```

The `SO_TIMESTAMPING` ancillary data is `ts[3]`, software, sys-hardware, raw-hardware.

## Reading transmit timestamps (the error queue)

TX timestamps are delivered asynchronously on the socket error queue:

```
sendto(fd, ...)
...
poll(fd, POLLERR /*|others*/, sk_tx_timeout);   /* default 1 ms */
recvmsg(fd, &msg, MSG_ERRQUEUE);                /* the frame + timestamps */
```

The NIC posted the timestamp when the frame left; the round trip is a few microseconds to tens of microseconds depending on the NIC.

## One-step clocks

In two-step mode, the precise origin rides in a Follow_Up. In one-step mode, the NIC itself edits `originTimestamp` in the frame on the wire, hwdrivers that support it advertise `HWTSTAMP_TX_ONESTEP_SYNC` / `ONESTEP_P2P`.

`port.c` (lines 1831-1866) handles the two/one-step split:

```c
if (p->timestamping != TS_ONESTEP && p->timestamping != TS_P2P1STEP)
    msg->header.flagField[0] |= TWO_STEP;

err = port_prepare_and_send(p, msg, event);

if (p->timestamping == TS_ONESTEP || p->timestamping == TS_P2P1STEP) {
    /* one-step: hardware has written the timestamp; no Follow_Up needed */
} else {
    if (msg_sots_missing(msg)) { ... error ... }
    fup->follow_up.preciseOriginTimestamp = tmv_to_Timestamp(msg->hwts.ts);
    port_prepare_and_send(p, fup, TRANS_GENERAL);
}
```

There's also the two-byte UDP checksum slack for one-step (section 3.7).

## The timestamp correction (ingress/egress latency)

The PHY capture point may differ from the protocol's reference plane; LinuxPTP supports explicit corrections (as config `ingressLatency`/`egressLatency`):

- RX: `actual = captured − ingressLatency`
- TX: `actual = captured + egressLatency`

Per IEEE 1588-2019 9.6.2, the egress timestamp is the captured value plus `egressLatency`; the ingress timestamp is the captured value minus `ingressLatency`. For modern PHCs with on-chip timestamping these are usually zero.

## Virtual clocks (vclocks)

Since Linux 5.6, a single PHY can expose several independent PHC instances, letting multiple PTP domains share one NIC. The socket is bound to a virtual clock:

```c
enum { SOF_TIMESTAMPING_BIND_PHC = (1 << 15) };
struct so_timestamping {
    int flags;
    int bind_phc;      /* 0 = physical PHC; 1,2,... = vclocks */
};
```

ptp4l selects the clock with the `phc_index` config option; there is no `vclock_index` option. When `phc_index` is non-negative, `sk_timestamping_init` adds `SOF_TIMESTAMPING_BIND_PHC` and sets `bind_phc` to that index.

## NIC notes

- Intel igb (I210/I350): HW timestamps, one-step, ~ns accuracy, the reference for most labs.
- Intel i40e (X710): HW timestamps; one-step support varies by generation.
- Intel ice (E810) and newer: HW timestamps + virtual clocks.
- Broadcom bnxt_en, Marvell mv88e6xxx, NXP sja1105 (switches): HW timestamping for TCs/boundary clocks.

Always verify with `ethtool -T` and a quick `phc_ctl /dev/ptp0 -- get`.

## Debugging

- `pmc -u "GET PORT_PROPERTIES_NP"` shows `timestamping: HARD` etc.
- Kernel `SO_TIMESTAMPING` errors (misconfigured filter) surface as `ioctl SIOCSHWTSTAMP failed` in ptp4l logs.
- `/proc/net/ts` (some drivers), `dmesg | grep ptp`: practical first stops.

## Summary

- `TS_SOFTWARE | HARDWARE | LEGACY_HW | ONESTEP | P2P1STEP` map to `SO_TIMESTAMPING` flags + driver ioctls.
- The exact bit values are TX_HARDWARE=1<<0 ... SOFTWARE=1<<4 ..., and one-step uses driver ioctls, not a SOF flag.
- Receive timestamps come back in ancillary data; transmit timestamps via the error queue.
- vclocks (Linux ≥5.6) enable multiple independent domains per NIC.
