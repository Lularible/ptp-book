# 3.9 TLV Processing: The Swiss Army Knife of Extended Information

## TLV in one paragraph

TLV = Type-Length-Value. PTP's TLVs carry management payloads, vendor extensions, and other extended information. Their code lives mostly in `tlv.c`, with `msg.c` handling the message framing.

## The core TLVs

### struct management_tlv (tlv.h, lines 210-215)

```c
struct management_tlv {
    Enumeration16 type;   /* TLV_MANAGEMENT */
    UInteger16    length;
    Enumeration16 id;     /* managementId */
    Octet         data[0];/* variable */
};
```

A GET request is just the ID (length 2):

```
40 00 ...resp-sans... GET DEFAULT_DATA_SET
  type 0x0001, length 0x0002, id 0x2000
```

The response carries the data set:

```
  type 0x0001, length 0x0016 (22), id 0x2000, then defaultDS (20 bytes)
```

(`defaultDS` is 20 bytes on the wire: flags, numberPorts, priority1, clockQuality(4), priority2, clockIdentity(8), domainNumber, reserved.)

### struct management_error_status (tlv.h, lines 222-229)

```c
struct management_error_status {
    Enumeration16 type;
    UInteger16    length;
    Enumeration16 error;    /* MID_* error code */
    Enumeration16 id;       /* the managementId that failed */
    Octet         reserved[4];
    Octet         data[0];
};
```

For NO_SUCH_ID (a request for an unknown ID):

```
  type 0x0002, length 0x0008, error 0x0002, id 0x9999, reserved 0x00000000
```

### struct path_trace_tlv (tlv.h, lines 272-276)

```c
struct path_trace_tlv {
    Enumeration16 type;    /* TLV_PATH_TRACE */

```

`PATH_TRACE_MAX` is computed from the announce size minus the fixed header/TLV fields.

## Byte-order conversions (tlv.c)

```c
#define HTONS(x) (x) = htons(x)
#define HTONL(x) (x) = htonl(x)
#define NTOHS(x) (x) = ntohs(x)
#define NTOHL(x) (x) = ntohl(x)
```

64-bit fields need the unaligned helpers:

```c
static int64_t host2net64_unaligned(void *p)
{
    int64_t v;
    memcpy(&v, p, sizeof(v));
    v = host2net64(v);
    memcpy(p, &v, sizeof(v));
    return v;
}
```

(memcpy avoids unaligned-access traps on strict platforms.)

A Timestamp converts its seconds/nanoseconds:

```c
static void timestamp_host2net(struct Timestamp *t)
{
    HTONL(t->seconds_lsb);   /* the 48-bit seconds: low word first */
    HTONS(t->seconds_msb);
    HTONL(t->nanoseconds);
}
```

## tlv_post_recv: parsing incoming TLVs (tlv.c, line 1145-1224)

Dispatches by type, byte-swaps fields, and stores parsed content in `struct tlv_extra`:

```c
int tlv_post_recv(struct tlv_extra *extra)
{
    struct TLV *tlv = extra->tlv;
    int result = 0;

    switch (tlv->type) {
    case TLV_MANAGEMENT:
        mgt = (struct management_tlv *) tlv;
        mgt->id = ntohs(mgt->id);
        result = mgt_post_recv(mgt, tlv->length - sizeof(mgt->id), extra);
        break;
    case TLV_MANAGEMENT_ERROR_STATUS:
        mes = (struct management_error_status *) tlv;
        mes->error = ntohs(mes->error);
        mes->id = ntohs(mes->id);
        break;
    case TLV_REQUEST_UNICAST_TRANSMISSION:
    case TLV_GRANT_UNICAST_TRANSMISSION:
    case TLV_CANCEL_UNICAST_TRANSMISSION:
    case TLV_ACKNOWLEDGE_CANCEL_UNICAST_TRANSMISSION:
        result = unicast_negotiation_post_recv(extra);
        break;
    case TLV_PATH_TRACE:
        if (tlv_array_invalid(tlv, 0, sizeof(struct ClockIdentity)))
            return -EBADMSG;
        break;
    case TLV_ALTERNATE_TIME_OFFSET_INDICATOR:
        result = alttime_offset_post_recv(extra);
        break;
    case TLV_AUTHENTICATION:
        result = auth_post_recv(extra);
        break;
    ...
    }
    return result;
}
```

`mgt_post_recv` (tlv.c, lines 164-512) then decodes each management ID; the variable-length `CLOCK_DESCRIPTION` gets most of the attention. `mgt_pre_send` (lines 514-692) is the mirror for sending.

## tlv_extra and the memory pool

```c
/* tlv.h, lines 469-476 */
struct tlv_extra {
    TAILQ_ENTRY(tlv_extra) list;
    struct TLV *tlv;
    union {
        struct mgmt_clock_description cd;   /* pointers into CLOCK_DESCRIPTION */
        struct nsm_resp_tlv_foot *foot;
    };
};
```

The pool (`tlv.c`):

```c
static TAILQ_HEAD(tlv_pool, tlv_extra) tlv_pool =
    TAILQ_HEAD_INITIALIZER(tlv_pool);

struct tlv_extra *tlv_extra_alloc(void)   /* take from pool or calloc */
void tlv_extra_recycle(struct tlv_extra *extra)  /* zero + return to pool */
void tlv_extra_cleanup(void)              /* free everything */
```

Recycling avoids a malloc/free per message at PTP rates.

## A useful idiom: building a management GET

```c
struct ptp_message *msg = msg_allocate();
...
msg->header.messageType = MANAGEMENT;
...
mgt = (struct management_tlv *) msg->management.suffix;
mgt->type   = TLV_MANAGEMENT;
mgt->length = sizeof(mgt->id);      /* just the ID */
mgt->id     = MID_CURRENT_DATA_SET;

msg->header.messageLength += sizeof(struct TLV) + mgt->length;
tlv_pre_send((struct TLV *) mgt, NULL);
msg_pre_send(msg);
```

After a GET response arrives, `tlv_post_recv(extra)` has already byte-swapped `currentDS` into host order, so the parser reads `stepsRemoved`, `offsetFromMaster`, `meanPathDelay` directly.

## Summary

- tlv.h holds every constant and struct; tlv.c holds the byte-order and dispatch machinery.
- Byte order: all multi-byte fields are big-endian; unaligned 64-bit fields use memcpy helpers.
- `tlv_extra` + pooling make parsing cheap at line rates.
- Management TLVs (GET/SET/RESPONSE/ERROR), unicast negotiation TLVs, path trace, and organization extensions are the usual residents.
