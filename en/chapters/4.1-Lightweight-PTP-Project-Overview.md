## Core data structures

### Timestamp structure

```c
/* ptp_common.h:24-44 */

/* Nanoseconds per second (same as linuxptp clockadj.c:30). */
#define NS_PER_SEC 1000000000LL

/* Largest value accepted for a decoded 48-bit seconds field. The field itself
 * spans 8.9 million years, but ptp_lite computes in nanoseconds: with both
 * operands under this bound every widened "(int64_t)a - (int64_t)b", and every
 * product of it with NS_PER_SEC, stays inside int64_t. Anything larger is
 * malformed or hostile and is dropped. On a 32-bit time_t the bound tightens to
 * INT32_MAX: past that "(time_t)sec" is implementation defined (gcc wraps, it
 * does not saturate), and a wrap can alias a huge offset down to a small one. */
#define PTP_MAX_VALID_SECONDS (sizeof(time_t) < 8 ? 2147483647ULL : 4294967295ULL)

/* PTP timestamp: 48-bit seconds + 32-bit nanoseconds */
typedef struct {
    uint16_t seconds_msb;    /* high 16 bits of seconds */
    uint32_t seconds_lsb;    /* low 32 bits of seconds */
    uint32_t nanoseconds;    /* nanoseconds part */
} __attribute__((packed)) ptp_timestamp_t;

/* Clock identity: 8 bytes */
typedef uint8_t ptp_clock_identity_t[8];
```

### Message header

The message header is defined in `ptp_message.h`.

```c
/* ptp_message.h:12-50 */

/* Flag bits (IEEE 1588-2019 Table 37). The field goes on the wire as two
 * octets but ptp_header_t stores it as one uint16_t that must pass through
 * htobe16(), so a bit n of octet 0 appears here as bit (8 + n). linuxptp
 * declares "Octet flagField[2]" (msg.h:96) and plain bit values (msg.h:57-66). */
#define PTP_FLAG_TWO_STEP       0x0200U  /* octet 0.bit1 - Sync is two-step */
#define PTP_FLAG_UNICAST        0x0400U  /* octet 0.bit2 - sent to a unicast address */
#define PTP_FLAG_PTP_TIMESCALE  0x0008U  /* octet 1.bit3 - PTP timescale, not ARB */
#define PTP_FLAG_UTC_OFF_VALID  0x0004U  /* octet 1.bit2 - currentUtcOffset valid */

/* logMessageInterval value meaning "unknown / not applicable": what Table 42
 * assigns to Delay_Req, Signaling and management messages without exception. */
#define PTP_LOG_INTERVAL_NA     0x7F

/* PTP message header - IEEE 1588-2019 Table 35 (34 bytes) */
typedef struct {
    uint8_t  message_type;              /* Octet 0: message type */
    uint8_t  version_ptp;               /* Octet 1: PTP version */
    uint16_t message_length;            /* Octets 2-3: message length */
    uint8_t  domain_number;             /* Octet 4: domain number */
    /* Octet 5 is minorSdoId, not a spare field: a profile may put a value here.
     * ptp_lite implements no profile, so the all-zero value memset() leaves is
     * the correct one and a receiver must ignore it. */
    uint8_t  minor_sdoid;
    uint16_t flag_field;                /* Octets 6-7: flag field, big endian */
    uint64_t correction_field;          /* Octets 8-15: correction field, big endian */
    /* Octets 16-19 are messageTypeSpecific (Table 39): reserved for general
     * messages, available to the sender for event messages. Either way it goes
     * out as zero and the receiver ignores it. */
    uint32_t message_type_specific;
    ptp_port_identity_t source_port_identity;  /* Octets 20-29: source port ID */
    uint16_t sequence_id;               /* Octets 30-31: sequence number */
    /* Octet 32 is the legacy control field of IEEE 1588-2002, filled from
     * Table 41 (Sync 0, Delay_Req 1, Follow_Up 2, Delay_Resp 3, Management 4,
     * all others 5) and ignored by receivers. 13.3.2.13 also asks an
     * implementation without the Annex C.4.2 hardware-compatibility option to
     * transmit it as all zeros; ptp_lite keeps the Table 41 values. */
    uint8_t  control_field;
    int8_t   log_message_interval;      /* Octet 33: message interval */
} __attribute__((packed)) ptp_header_t;
```

## Configuration parameters

```c
/* ptp_common.h:62-80 */

/* Multicast address and ports */
#define PTP_PRIMARY_MCAST      "224.0.1.129"
#define PTP_EVENT_PORT         319
#define PTP_GENERAL_PORT       320

/* Default parameters. The two *_INT values are log2(seconds), which is also
 * what goes on the wire in logMessageInterval (Table 42), so one constant
 * drives both the timer and the message field. */
#define PTP_DEFAULT_DOMAIN     0
#define PTP_DEFAULT_PRIORITY1  128
#define PTP_DEFAULT_PRIORITY2  128
#define PTP_DEFAULT_ANNOUNCE_INT  1   /* 2^1 = 2 s */
#define PTP_DEFAULT_SYNC_INT      0   /* 2^0 = 1 s */

/* currentUtcOffset carried by Announce. Published by IERS Bulletin C: it has
 * been 37 s since the leap second of 2017-01-01 and moves by +-1 s whenever a
 * leap second is inserted or deleted. No leap-second table here (that would
 * need the machinery of linuxptp lstab.c) - bump this constant by hand. */
#define PTP_CURRENT_UTC_OFFSET 37
```

```c
/* ptp_servo.h:11-48 */

/* PI gains: the software-timestamp pair of linuxptp, SWTS_KP_SCALE = 0.1 and
 * SWTS_KI_SCALE = 0.001 (pi.c:30-31). The 0.7 / 0.3 that used to be here are
 * its *hardware* timestamp gains (pi.c:28-29) - seven and three hundred times
 * too hot for timestamps carrying tens of microseconds of jitter.
 *
 * linuxptp also rescales both gains with the sync interval and caps them by
 * norm_max (pi_sync_interval(), pi.c:157-171). ptp_lite always runs a 1 s sync
 * interval and pow(1, x) == 1, so that normalisation would be a no-op and is
 * deliberately not implemented. */
#define SERVO_KP 0.1
#define SERVO_KI 0.001

/* Step threshold (nanoseconds) - 10 ms */
#define SERVO_STEP_THRESHOLD 10000000LL

/* Contract on the caller, not a bound the servo enforces: pi_servo_sample()
 * works in double and 2^53 ns (~104 days) is where an int64_t stops converting
 * to double exactly, so a larger |offset| is not "a very large offset" but an
 * invalid measurement (a stale or hostile timestamp pair) that whoever calls
 * us must reject instead of handing it here - see ptp_slave.c. Two clocks
 * further apart than this have to be brought together with `date -s` first. */
#define SERVO_MAX_OFFSET_NS (9007199254740992LL)   /* 2^53 nanoseconds */

/* Clamp on the loop output, in ppb: +-500 ppm, the fallback limit linuxptp
 * uses when the kernel reports no adjustable range (clockadj.c:139-140).
 * Uncapped, one sample at the step threshold asks Kp * 1e7 = 1e6 ppb = 1000 ppm,
 * twice the clamp: the kernel answers EINVAL while the integral keeps charging. */
#define SERVO_MAX_FREQ_PPB 500000.0

/* Clamp on the integral accumulator, in nanoseconds of summed offset, derived
 * so that the integral term alone never exceeds the full frequency range:
 * ki * SERVO_MAX_INTEGRAL_NS == SERVO_MAX_FREQ_PPB. */
#define SERVO_MAX_INTEGRAL_NS (SERVO_MAX_FREQ_PPB / SERVO_KI)

/* Consecutive in-range samples needed to count as locked, and as stably locked
 * (the old code tested count > 1 and count > 10). */
#define SERVO_LOCKED_SAMPLES 2
#define SERVO_STABLE_SAMPLES 11
```

## Build environment

```makefile
# Makefile excerpt: default x86 build + all link rules (full list in 4.5)

# Per-architecture compilers, overridable: make arm64 CC_ARM64=my-aarch64-gcc
CC_X86   ?= gcc
CC_ARM64 ?= aarch64-linux-gnu-gcc
CC_ARM32 ?= arm-linux-gnueabihf-gcc

CFLAGS  = -Wall -Wextra -O2 -std=gnu11
LDFLAGS = -lrt -lm

# arm32 is the only target whose ABI has to be spelled out; both knobs follow
# the hard-float gnueabihf triple by default and can be overridden per board:
#   make arm32 ARM32_MCPU=cortex-a7 ARM32_MFLOAT=softfp
ARM32_MCPU   ?= cortex-a9
ARM32_MFLOAT ?= hard
CFLAGS_ARM32 = $(CFLAGS) -mcpu=$(ARM32_MCPU) -mfloat-abi=$(ARM32_MFLOAT)

HEADERS    = $(wildcard *.h)
COMMON_SRC = ptp_message.c

# The master never touches the servo, so ptp_servo.c is NOT linked into it. It
# used to be, which left pi_servo_init()/pi_servo_sample() as dead symbols in
# ptp_master (`nm ptp_master | grep servo` must stay empty).
MASTER_SRC = ptp_master.c $(COMMON_SRC)
SLAVE_SRC  = ptp_slave.c $(COMMON_SRC) ptp_servo.c

BIN_X86   = ptp_master ptp_slave

# Toolchain selection: the two rules below build all six binaries, and these
# target-specific variables say which compiler and flags each of them gets.
CC_FOR     = $(CC_X86)
CFLAGS_FOR = $(CFLAGS)
ptp_master         ptp_slave:         CC_FOR = $(CC_X86)
ptp_master_arm64   ptp_slave_arm64:   CC_FOR = $(CC_ARM64)
ptp_master_arm32   ptp_slave_arm32:   CC_FOR = $(CC_ARM32)
ptp_master_arm32   ptp_slave_arm32:   CFLAGS_FOR = $(CFLAGS_ARM32)

all: $(BIN_X86)

# Every target names its sources in the recipe instead of using $^, because
# the prerequisite list also carries $(HEADERS): editing a header must trigger
# a rebuild, but the header itself must not end up on the command line.
ptp_master ptp_master_arm64 ptp_master_arm32: $(MASTER_SRC) $(HEADERS)
	$(CC_FOR) $(CFLAGS_FOR) -o $@ $(MASTER_SRC) $(LDFLAGS)

ptp_slave ptp_slave_arm64 ptp_slave_arm32: $(SLAVE_SRC) $(HEADERS)
	$(CC_FOR) $(CFLAGS_FOR) -o $@ $(SLAVE_SRC) $(LDFLAGS)

.PHONY: all arm64 arm32 clean clean-arm64 clean-arm32 clean-all all-arch help
```

## Running requirements

```bash
# System requirements
# - Linux
# - GCC
# - root privileges

# Build
make

# Run the master clock
sudo ./ptp_master eth0

# Run the slave clock
sudo ./ptp_slave eth0

# Test
# Run master and slave on two hosts (or two ip netns on one machine)
# Watch them synchronize
```

Use two hosts, or two network namespaces on one machine. The `clockIdentity` comes from the NIC's MAC as an EUI-64, with FF-FE inserted in the middle. Master and slave on the same NIC therefore get the same identity, and the slave discards the master's packets. The master never adjusts the clock, so `sudo` is only for `SO_BINDTODEVICE`.
