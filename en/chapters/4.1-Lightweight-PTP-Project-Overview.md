# Part 4: Building PTP with Your Own Hands

## 4.1 A Lightweight PTP Project: A Synchronization Journey from Zero

### Why build it?

ptp-lite is a tiny, ~1,000-line C PTP implementation with a working master, a working slave, and synchronization over UDP multicast.

### The project layout

```
ptp_lite/
├── Makefile
├── ptp_common.h      types & constants
├── ptp_message.h     message structures
├── ptp_message.c     header/body constructors
├── ptp_servo.h       servo interface
├── ptp_servo.c       a small PI servo
├── ptp_master.c      the master clock program
├── ptp_slave.c       the slave clock program
└── README.md
```

Roughly 1,000 lines of C all in.

### Scope

| Feature | In ptp-lite? |
|:---|:---|
| Announce / Sync / Follow_Up / Delay_Req / Delay_Resp | yes |
| BMCA | minimal (fixed roles) |
| E2E delay measurement | yes |
| Four/two-step Sync | two-step (Follow_Up) |
| Part v2 message formats | yes (UDP/IPv4) |
| Software timestamping | yes (CLOCK_REALTIME reads) |
| PI servo | yes |
| Port state machine | simplified |
| Hardware timestamps | no (extension) |

This is deliberately narrower than LinuxPTP's full scope: a learning scaffold whose master and slave really synchronize.

### The build

```bash
make                 # x86
make arm64           # cross-compile for aarch64
make arm32           # cross-compile for arm-linux-gnueabihf
```

Requires a C11 compiler and `libm`/`librt`.

### Running it

```bash
# Terminal A: the master, on interface eth0
sudo ./ptp_master eth0

# Terminal B: the slave, on interface eth0
sudo ./ptp_slave eth0
```

You'll see Announce/Sync exchanges on the master, and offset/delay/frequency lines on the slave.

### How the pieces fit PTP

| Concept from Part 2 | Where it lives in ptp-lite |
|:---|:---|
| common header | `ptp_header_t` in ptp_message.h |
| Sync/Follow_Up | `ptp_sync_msg_t` / `ptp_follow_up_msg_t` |
| E2E four timestamps | the slave's `handle_delay_resp` |
| offsetFromMaster | `offset` in ptp_slave.c |
| meanPathDelay | `delay` in ptp_slave.c |
| phase/frequency adjustment | `adjust_clock()` + PI servo |
| transport | UDP 319/320 multicast |

## Summary

ptp-lite is the hands-on half of this book: the same ideas you traced in Parts 2 and 3, reduced to code you can read entirely and run today.

Our simplified header, the 44-byte Sync, the 54-byte Delay_Resp, and the static assertions that keep them honest.
