# 4.2 Message Structures and Encoding: The DNA of a PTP Message

## The header (ptp_message.h)

```c
/* PTP message header — IEEE 1588-2019 Figure 35 (34 bytes) */
typedef struct {
    uint8_t  message_type;         /* Octet 0: message type */
    uint8_t  version_ptp;          /* Octet 1: PTP version */
    uint16_t message_length;       /* Octets 2-3 */
    uint8_t  domain_number;        /* Octet 4 */
    uint8_t  reserved1;            /* Octet 5 */
    uint16_t flag_field;           /* Octets 6-7 */
    uint64_t correction_field;     /* Octets 8-15 */
    uint32_t reserved2;            /* Octets 16-19 */
    ptp_port_identity_t source_port_identity; /* Octets 20-29 */
    uint16_t sequence_id;          /* Octets 30-31 */
    uint8_t  control_field;        /* Octet 32 (legacy) */
    int8_t   log_message_interval; /* Octet 33 */
} __attribute__((packed)) ptp_header_t;
```

This is a deliberately simplified header: we keep the fields PTP actually needs for a two-step E2E exchange, and skip `majorSdoId`/`minorSdoId` encoding details (they're 0 in our domain).

### ptp_port_identity_t and ptp_timestamp_t

```c
typedef struct {
    uint8_t clock_identity[8];
    uint16_t port_number;          /* network byte order */
} ptp_port_identity_t;

typedef struct {
    uint16_t seconds_msb;          /* UInteger48 seconds, high 16 bits */
    uint32_t seconds_lsb;          /* UInteger48 seconds, low 32 bits */
    uint32_t nanoseconds;
} ptp_timestamp_t;
```

## Timestamp encoding

PTP timestamps are 6-byte seconds + 4-byte nanoseconds. To keep struct packing simple and correct:

```c
void timespec_to_ptp(const struct timespec *ts, ptp_timestamp_t *ptp)
{
    uint64_t secs = (uint64_t) ts->tv_sec;
    ptp->seconds_msb = htons((uint16_t) (secs >> 32));
    ptp->seconds_lsb = htonl((uint32_t) (secs & 0xFFFFFFFF));
    ptp->nanoseconds = htonl((uint32_t) ts->tv_nsec);
}
```

## The message bodies

```
Sync message (44 bytes):
┌──────────┬──────────────────────┐
│ Header   │ Origin Timestamp(10B)│
└──────────┴──────────────────────┘

Follow_Up (44 bytes):
┌──────────┬───────────────────────────┐
│ Header   │ Precise Origin Timestamp  │
└──────────┴───────────────────────────┘

Delay_Req (44 bytes in ptp-lite):
┌──────────┬──────────────────────┐
│ Header   │ Origin Timestamp(10B)│
└──────────┴──────────────────────┘

Delay_Resp (54 bytes):
┌──────────┬─────────────────┬───────────────┐
│ Header   │ Receive Timestamp│ Requesting ID │
└──────────┴─────────────────┴───────────────┘

Announce (64 bytes):
┌──────────┬────────────────┬──────────┬────────... ─┐
│ Header   │ Origin Ts(10B) │ QoS(4B)  │ rem(14B)... │
└──────────┴────────────────┴──────────┴────────... ─┘
```

Note: the standard IEEE 1588-2019 Delay_Req is 44 bytes (header 34 + originTimestamp 10), with no reserved field (Table 44). The 10-byte reserved field belongs to Pdelay_Req (Table 47), which pads it to match Pdelay_Resp. ptp-lite's 44-byte Delay_Req therefore matches the standard wire length.

```c
/* Sync message (44 bytes) - IEEE 1588-2019 Figure 39 */
typedef struct {
    ptp_header_t header;               /* 34 bytes */
    ptp_timestamp_t origin_timestamp;  /* 10 bytes */
} __attribute__((packed)) ptp_sync_msg_t;

/* Follow_Up (44 bytes) - Figure 40 */
typedef struct {
    ptp_header_t header;
    ptp_timestamp_t precise_origin_timestamp;
} __attribute__((packed)) ptp_follow_up_msg_t;

/* Delay_Req (44 bytes) - Figure 41 */
typedef struct {
    ptp_header_t header;
    ptp_timestamp_t origin_timestamp;
} __attribute__((packed)) ptp_delay_req_msg_t;

/* Delay_Resp (54 bytes) - Figure 42 */
typedef struct {
    ptp_header_t header;
    ptp_timestamp_t receive_timestamp;
    ptp_port_identity_t requesting_port_identity; /* 10 bytes */
} __attribute__((packed)) ptp_delay_resp_msg_t;
```

## Announce (64 bytes)

```c
typedef struct {
    ptp_header_t header;
    ptp_timestamp_t origin_timestamp;         /* 10 */
    uint16_t current_utc_offset;              /* 2 */
    uint8_t  reserved;                        /* 1 */
    uint8_t  grandmaster_priority1;           /* 1 */
    ptp_clock_quality_t grandmaster_clock_quality; /* 4 */
    uint8_t  grandmaster_priority2;           /* 1 */
    ptp_clock_identity_t grandmaster_identity;/* 8 */
    uint16_t steps_removed;                   /* 2 */
    uint8_t  time_source;                     /* 1 */
} __attribute__((packed)) ptp_announce_msg_t;
```

## Static assertions: catch layout bugs at compile time

```c
_Static_assert(sizeof(ptp_header_t) == 34, "Header size incorrect");
_Static_assert(sizeof(ptp_sync_msg_t) == 44, "Sync size incorrect");
_Static_assert(sizeof(ptp_follow_up_msg_t) == 44, "Follow_Up size incorrect");
_Static_assert(sizeof(ptp_delay_req_msg_t) == 44, "Delay_Req size incorrect");
_Static_assert(sizeof(ptp_delay_resp_msg_t) == 54, "Delay_Resp size incorrect");
_Static_assert(sizeof(ptp_announce_msg_t) == 64, "Announce size incorrect");
```

(`__attribute__((packed))` + static assertions mean any accidental padding is a compile error, not a silent wire bug.)

## The constructors (ptp_message.c)

```c
void ptp_init_header(ptp_header_t *hdr, uint8_t msg_type, uint16_t seq_id,
                     const ptp_port_identity_t *port_id)
{
    memset(hdr, 0, sizeof(*hdr));
    hdr->message_type     = msg_type;
    hdr->version_ptp      = PTP_VERSION;
    hdr->domain_number    = PTP_DEFAULT_DOMAIN;
    hdr->flag_field       = 0;
    hdr->correction_field = 0;
    memcpy(&hdr->source_port_identity, port_id, sizeof(ptp_port_identity_t));
    hdr->sequence_id      = htobe16(seq_id);
    hdr->log_message_interval = 0x7F;
}
```

Followed by `ptp_init_sync`, `ptp_init_follow_up`, `ptp_init_delay_req`, `ptp_init_delay_resp`, `ptp_init_announce`, each filling the body and setting `message_length` correctly.

## Summary

- One packed header; one body per message type; constructors keep the wire format right.
- `timespec_to_ptp` / `ptp_to_timespec` handle the 48-bit-seconds encoding.
- Static assertions pin the lengths (44/44/44/54/64).
