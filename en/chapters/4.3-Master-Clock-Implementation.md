# 4.3 The Master Clock Implementation: The Publisher of Time

## The master's jobs

A master clock does four things:

1. Send Announce (quality + identity for (our simplified) BMCA).
2. Send Sync + Follow_Up (the time itself, in two step).
3. Answer Delay_Req with Delay_Resp.
4. Maintain a stable rate.

ptp-lite's `ptp_master.c` is a ~220-line C program that loops on a single UDP socket.

## The socket (create_socket)

```c
fd = socket(AF_INET, SOCK_DGRAM, 0);
setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

addr.sin_family = AF_INET;
addr.sin_addr.s_addr = htonl(INADDR_ANY);
addr.sin_port = htons(PTP_EVENT_PORT);   /* 319 */

bind(fd, (struct sockaddr *)&addr, sizeof(addr));

setsockopt(fd, SOL_SOCKET, SO_BINDTODEVICE, iface, strlen(iface));

inet_pton(AF_INET, PTP_PRIMARY_MCAST, &mreq.imr_multiaddr);  /* 224.0.1.129 */
mreq.imr_ifindex = if_nametoindex(iface);
setsockopt(fd, IPPROTO_IP, IP_ADD_MEMBERSHIP, &mreq, sizeof(mreq));
setsockopt(fd, IPPROTO_IP, IP_MULTICAST_IF, &mreq, sizeof(mreq));
```

One socket, bound to port 319, joined to the primary multicast group, pinned to one interface. Both event (319) and general (320) sends go out on this socket by passing the destination port to `send_multicast`.

## Sending multicast

```c
static int send_multicast(int fd, const void *data, size_t len, int port)
{
    struct sockaddr_in addr;

    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    inet_pton(AF_INET, PTP_PRIMARY_MCAST, &addr.sin_addr);
    addr.sin_port = htons(port);

    return sendto(fd, data, len, 0, (struct sockaddr *)&addr, sizeof(addr));
}
```

## The scheduler loop

```c
clock_gettime(CLOCK_MONOTONIC, &next_announce);
clock_gettime(CLOCK_MONOTONIC, &next_sync);
next_announce.tv_sec += 2;    /* announce every 2 s */
next_sync.tv_sec    += 1;     /* sync every 1 s */

while (1) {
    clock_gettime(CLOCK_MONOTONIC, &now);

    if (now.tv_sec >= next_announce.tv_sec) {
        send_announce(fd);
        next_announce.tv_sec = now.tv_sec + 2;
    }
    if (now.tv_sec >= next_sync.tv_sec) {
        send_sync(fd);
        next_sync.tv_sec = now.tv_sec + 1;
    }

    timeout.tv_usec = 100000;               /* poll every 100 ms */
    ...
    ret = select(fd + 1, &readfds, NULL, NULL, &timeout);
    if (ret > 0 && FD_ISSET(fd, &readfds)) {
        ret = recvfrom(fd, recv_buf, sizeof(recv_buf), 0,
                       (struct sockaddr *)&client_addr, &addr_len);
        if (ret > (ssize_t) sizeof(ptp_header_t)) {
            ptp_header_t *hdr = (ptp_header_t *) recv_buf;
            if (hdr->message_type == PTP_MSG_DELAY_REQ &&
                ret >= (ssize_t) sizeof(ptp_delay_req_msg_t)) {
                handle_delay_req(fd, recv_buf, &client_addr);
            }
        }
    }
}
```

`CLOCK_MONOTONIC` schedules the interval; `CLOCK_REALTIME` provides the published timestamp.

## Sync + Follow_Up (send_sync)

```c
ptp_init_sync(&sync_msg, sync_seq, &master_port_id);
ret = send_multicast(fd, &sync_msg, sizeof(sync_msg), PTP_EVENT_PORT);  /* 319 */

if (ret > 0) {
    clock_gettime(CLOCK_REALTIME, &ts);
    ptp_init_follow_up(&follow_up_msg, sync_seq, &master_port_id, &ts);
    send_multicast(fd, &follow_up_msg, sizeof(follow_up_msg),
                   PTP_GENERAL_PORT);                                  /* 320 */
}
sync_seq++;                          /* both messages carry the same seq */
```

The two-step pairing: same `sequenceId` in Sync and Follow_Up; the Follow_Up holds the precise send time.

## Answering Delay_Req (handle_delay_req)

```c
clock_gettime(CLOCK_REALTIME, &ts);
timespec_to_ptp(&ts, &recv_ts);

ptp_init_delay_resp(&resp, delay_resp_seq++, &master_port_id,
                    &recv_ts, &req->header.source_port_identity);
send_unicast(fd, &resp, sizeof(resp), client_addr);
```

The receive timestamp (CLOCK_REALTIME at receipt) is echoed back, along with the requester's port identity so the slave can pair the response.

## Summary

- A master is a timer loop plus a UDP socket: schedule, send Sync+Follow_Up, answer Delay_Req.
- Announce carries identity/quality for (simplified) discovery.
- Two-step: the precise origin lives in Follow_Up, not Sync.
