# 4.4 The Slave Clock Implementation: The Follower of Time

## The slave's jobs

The slave:

1. Receives Announce (knows who the master is).
2. Receives Sync + Follow_Up (obtains t1, records t2).
3. Sends Delay_Req, receives Delay_Resp (obtains t3, t4).
4. Computes `meanPathDelay` and `offsetFromMaster`.
5. Disciplines its own clock (phase and frequency) with the PI servo.

This is where the four-timestamp math of section 2.7 finally runs.

## The E2E measurement (handle_delay_resp)

```c
int64_t delay, offset;

delay  = ((t2.tv_sec - t1.tv_sec) * 1000000000LL + (t2.tv_nsec - t1.tv_nsec)) +
         ((t4.tv_sec - t3.tv_sec) * 1000000000LL + (t4.tv_nsec - t3.tv_nsec));
delay /= 2;

offset = ((t2.tv_sec - t1.tv_sec) * 1000000000LL + (t2.tv_nsec - t1.tv_nsec)) -
         ((t4.tv_sec - t3.tv_sec) * 1000000000LL + (t4.tv_nsec - t3.tv_nsec));
offset /= 2;
```

Exactly the formulas:

```
meanPathDelay = [(t2 − t1) + (t4 − t3)] / 2
offset       = [(t2 − t1) − (t4 − t3)] / 2
```

The timestamps come from the local clock at the four appropriate events:
- t1: from Follow_Up's preciseOriginTimestamp (master clock domain),
- t2: local time at Sync receipt,
- t3: local time when Delay_Req was sent,
- t4: from Delay_Resp's receiveTimestamp (master clock domain).

## The servo (ptp_servo.c)

A small PI controller: faster than a naive step, gentle enough to avoid disturbing applications.

```c
void pi_servo_init(pi_servo_t *s)
{
    s->kp = SERVO_KP;       /* 0.7 */
    s->ki = SERVO_KI;       /* 0.3 */
    s->integral = 0.0;
    s->last_freq = 0.0;
    s->state = SERVO_UNLOCKED;
    s->count = 0;
}
```

```c
double pi_servo_sample(pi_servo_t *s, int64_t offset, servo_state_t *state)
{
    double freq_adj;

    if (llabs(offset) > SERVO_STEP_THRESHOLD) {   /* e.g. 10 ms */
        s->state = SERVO_JUMP;
        s->integral = 0;
        s->count = 0;
    } else {
        s->count++;
        if (s->count > 1)  s->state = SERVO_LOCKED;
        if (s->count > 10) s->state = SERVO_LOCKED_STABLE;
    }

    /* PI control runs only in the LOCKED states; a jump returns 0 */
    if (s->state == SERVO_LOCKED || s->state == SERVO_LOCKED_STABLE) {
        s->integral += offset;
        freq_adj = -s->kp * offset - s->ki * s->integral;
    } else {
        freq_adj = 0.0;
    }

    *state = s->state;
    s->last_freq = freq_adj;
    return freq_adj;
}
```

## Applying the correction (adjust_clock)

```c
static void adjust_clock(int64_t offset_ns, double freq_ppb, servo_state_t state)
{
    struct timespec ts;
    struct timex tx;

    switch (state) {
    case SERVO_JUMP:
        /* a large error: set the clock directly (step) */
        if (clock_gettime(CLOCK_REALTIME, &ts) != 0) { ... }

        if (offset_ns < 0) {        /* slave is behind → add */
            ts.tv_sec += (-offset_ns) / 1000000000LL;
            ts.tv_nsec += (-offset_ns) % 1000000000LL;
            if (ts.tv_nsec >= 1000000000LL) { ts.tv_sec++; ts.tv_nsec -= 1000000000LL; }
        } else {                    /* slave is ahead → subtract */
            ts.tv_sec -= offset_ns / 1000000000LL;
            ts.tv_nsec -= offset_ns % 1000000000LL;
            if (ts.tv_nsec < 0) { ts.tv_sec--; ts.tv_nsec += 1000000000LL; }
        }
        clock_settime(CLOCK_REALTIME, &ts);
        break;

    case SERVO_LOCKED:
    case SERVO_LOCKED_STABLE:
        /* apply the frequency only, keeping time continuous */
        memset(&tx, 0, sizeof(tx));
        tx.modes = ADJ_FREQUENCY;
        tx.freq  = (long)(freq_ppb * 65.536);   /* ppb scaled by 65.536 */
        clock_adjtime(CLOCK_REALTIME, &tx);
        break;
    }
}
```

The sign convention matches section 2.9: `offset = slave − master`, so the slave's new value is `current − offset`, subtract when ahead, add when behind.

## The receive loop

```c
while (1) {
    recvfrom(event_fd or general_fd, ...);
    switch (hdr->message_type) {
    case PTP_MSG_ANNOUNCE:      (store master identity)
    case PTP_MSG_SYNC:          (record t2, remember seq)
    case PTP_MSG_FOLLOW_UP:     (combine with Sync → t1, call servo on offset)
    case PTP_MSG_DELAY_RESP:    (compute delay + offset, adjust)
    }
}
```

The slave listens on two sockets: the event port (319) for Sync and Delay_Resp, and the general port (320) for Follow_Up and Announce. Both are needed for interoperability.

Log lines to look for when it works:

```
Received Sync seq=0
Follow_Up seq=0: t1=... t2=...
Delay_Resp: delay=2000 ns offset=-5000 ns
CLOCK JUMP: -5000 ns (new time: ...)
...
```

## Summary

- The slave implements the E2E four-timestamp math verbatim.
- A small PI servo turns the offset stream into phase/frequency corrections.
- Jump for big offsets, slew (frequency-only) when locked, keeping time continuous.
- `offset = slave − master` sign convention throughout, matching Part 2.
