# 4.5 Compiling, Running, and Testing

## Makefile

`ptp_lite/Makefile` is **106 lines** — 15 targets, 9 `.PHONY` entries, 11 `@echo` lines, two link recipes, 16 tab-indented lines. It is reproduced **word for word** here, with no excerpt and no translation:

```makefile
# ==================== compiler configuration ====================

# Per-architecture compilers, overridable: make arm64 CC_ARM64=my-aarch64-gcc
CC_X86   ?= gcc
CC_ARM64 ?= aarch64-linux-gnu-gcc
CC_ARM32 ?= arm-linux-gnueabihf-gcc

# ==================== build options ====================

# One set of flags for all three architectures. The code is warning free on
# x86-64, arm64 and arm32 - int64_t is printed with PRId64, so the ILP32 arm32
# target reports no -Wformat diagnostics either.
#
# -D_GNU_SOURCE is not needed: -std=gnu11 already turns on _DEFAULT_SOURCE,
# which is what <net/if.h> (struct ifreq) and <netinet/in.h> (struct ip_mreqn)
# require. Adding -D_GNU_SOURCE would work too, but would not change a thing.
CFLAGS  = -Wall -Wextra -O2 -std=gnu11
LDFLAGS = -lrt -lm

# arm32 is the only target whose ABI has to be spelled out; both knobs follow
# the hard-float gnueabihf triple by default and can be overridden per board:
#   make arm32 ARM32_MCPU=cortex-a7 ARM32_MFLOAT=softfp
ARM32_MCPU   ?= cortex-a9
ARM32_MFLOAT ?= hard
CFLAGS_ARM32 = $(CFLAGS) -mcpu=$(ARM32_MCPU) -mfloat-abi=$(ARM32_MFLOAT)

# ==================== sources ====================

HEADERS    = $(wildcard *.h)
COMMON_SRC = ptp_message.c

# The master never touches the servo, so ptp_servo.c is NOT linked into it. It
# used to be, which left pi_servo_init()/pi_servo_sample() as dead symbols in
# ptp_master (`nm ptp_master | grep servo` must stay empty).
MASTER_SRC = ptp_master.c $(COMMON_SRC)
SLAVE_SRC  = ptp_slave.c $(COMMON_SRC) ptp_servo.c

BIN_X86   = ptp_master ptp_slave
BIN_ARM64 = ptp_master_arm64 ptp_slave_arm64
BIN_ARM32 = ptp_master_arm32 ptp_slave_arm32

# Toolchain selection: the two rules below build all six binaries, and these
# target-specific variables say which compiler and flags each of them gets.
CC_FOR     = $(CC_X86)
CFLAGS_FOR = $(CFLAGS)
ptp_master         ptp_slave:         CC_FOR = $(CC_X86)
ptp_master_arm64   ptp_slave_arm64:   CC_FOR = $(CC_ARM64)
ptp_master_arm32   ptp_slave_arm32:   CC_FOR = $(CC_ARM32)
ptp_master_arm32   ptp_slave_arm32:   CFLAGS_FOR = $(CFLAGS_ARM32)

# ==================== x86 targets (default) ====================

all: $(BIN_X86)

# ==================== ARM64 targets ====================

arm64: $(BIN_ARM64)

# ==================== ARM32 targets ====================

arm32: $(BIN_ARM32)

# ==================== link rules (all architectures) ====================

# Every target names its sources in the recipe instead of using $^, because
# the prerequisite list also carries $(HEADERS): editing a header must trigger
# a rebuild, but the header itself must not end up on the command line.
ptp_master ptp_master_arm64 ptp_master_arm32: $(MASTER_SRC) $(HEADERS)
	$(CC_FOR) $(CFLAGS_FOR) -o $@ $(MASTER_SRC) $(LDFLAGS)

ptp_slave ptp_slave_arm64 ptp_slave_arm32: $(SLAVE_SRC) $(HEADERS)
	$(CC_FOR) $(CFLAGS_FOR) -o $@ $(SLAVE_SRC) $(LDFLAGS)

# ==================== clean targets ====================
# *.o is never produced (the link rules go .c -> binary); kept as a defensive glob.
clean:
	rm -f $(BIN_X86) *.o

clean-arm64:
	rm -f $(BIN_ARM64) *.o

clean-arm32:
	rm -f $(BIN_ARM32) *.o

clean-all: clean clean-arm64 clean-arm32

# ==================== auxiliary targets ====================

# build all architectures
all-arch: all arm64 arm32

# show help
help:
	@echo "PTP-lite build options:"
	@echo "  make           - build the x86 version (default)"
	@echo "  make arm64     - build the ARM64 version"
	@echo "  make arm32     - build the ARM32 version"
	@echo "  make all-arch  - build all architecture versions"
	@echo ""
	@echo "Clean options:"
	@echo "  make clean         - clean the x86 version"
	@echo "  make clean-arm64   - clean the ARM64 version"
	@echo "  make clean-arm32   - clean the ARM32 version"
	@echo "  make clean-all     - clean all versions"

.PHONY: all arm64 arm32 clean clean-arm64 clean-arm32 clean-all all-arch help
```

### How this Makefile is organized

| Location | Contents |
|---|---|
| `:4-6` | Three compilers, `CC_X86` / `CC_ARM64` / `CC_ARM32`, **all `?=`** ⟹ overridable on the command line (`make arm64 CC_ARM64=my-aarch64-gcc`) |
| `:17-18` | One set of `CFLAGS` / `LDFLAGS`, shared by all three architectures |
| `:23-25` | The arm32-specific ABI spelling: `CFLAGS_ARM32 = $(CFLAGS) -mcpu=… -mfloat-abi=…` |
| `:29-30` | `HEADERS = $(wildcard *.h)`, `COMMON_SRC = ptp_message.c` |
| `:35-36` | `MASTER_SRC` (**no servo**) / `SLAVE_SRC` (**with servo**) |
| `:38-40` | Three sets of binary names, `BIN_X86` / `BIN_ARM64` / `BIN_ARM32` |
| `:44-49` | Target-specific variables `CC_FOR` / `CFLAGS_FOR`: these six lines decide which toolchain each target gets. Six per-architecture recipes collapse into two |
| `:68-72` | **Two** link rules that cover all six binaries in one go |

## Build steps

### x86 (default)

```bash
make
```

### ARM64

```bash
make arm64
```

Output files: `ptp_master_arm64`, `ptp_slave_arm64`

### ARM32

```bash
make arm32
```

Output files: `ptp_master_arm32`, `ptp_slave_arm32`

The default build is `cortex-a9` plus hard float (gnueabihf). If your board isn't in that class, override on the command line — no need to edit the Makefile:

```bash
make arm32 ARM32_MCPU=cortex-a7 ARM32_MFLOAT=softfp
```

The compiler itself is overridable too (all three `CC_*` use `?=`):

```bash
make arm32 CC_ARM32=/opt/toolchain/bin/arm-none-linux-gnueabihf-gcc
```

### Build all architectures

```bash
make all-arch
```

### Show help

```bash
make help
```

## Installing the cross-compile toolchains

**Ubuntu/Debian**:
```bash
# Install the ARM64 toolchain
sudo apt install gcc-aarch64-linux-gnu

# Install the ARM32 toolchain (hard float)
sudo apt install gcc-arm-linux-gnueabihf
```

**Fedora/CentOS**:
```bash
# Install the ARM64 toolchain
sudo yum install gcc-aarch64-linux-gnu

# Install the ARM32 toolchain
sudo yum install gcc-arm-linux-gnu
```

> The Fedora/CentOS package installs the `arm-linux-gnu-` prefix (usually soft float, `gnueabi`), which doesn't match the Makefile default `arm-linux-gnueabihf-gcc`. After installing, either override `CC_ARM32` or set `ARM32_MCPU` / `ARM32_MFLOAT` to the ABI that toolchain actually uses.

## Test steps

```bash
# Step 1: build
make

# Step 2: turn off NTP on both machines first, or systemd-timesyncd / chrony will fight ptp_lite over the clock
sudo timedatectl set-ntp false

# Step 3: run the master on machine A
sudo ./ptp_master eth0

# Step 4: run the slave on machine B
sudo ./ptp_slave eth0

# Step 5: check the time
date
# or to the nanosecond: date +%s.%N
```

⚠️ **Master and slave must be two different hosts, or two `ip netns` on one machine.**

`sudo` is there for `CAP_SYS_TIME` and `CAP_NET_RAW`; binding 319/320 doesn't need root, and the master never changes the clock.

Once both are running, the logs look like this (**illustrative**; timestamps come from `date +%s.%N`, and the two timers have different phases, so the interleaving of lines will change):
